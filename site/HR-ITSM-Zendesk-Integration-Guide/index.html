Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

This integration automates identity-driven IT service management workflows by connecting your HR system with Zendesk. The integration retrieves workforce data from the selected HR application, detects employee lifecycle events based on the configured lifecycle rules, and automatically creates Zendesk tickets for the configured lifecycle events.

The integration supports configurable ticket creation for employee lifecycle events, such as new hires and terminations. It also allows you to control when tickets are created, map employee information to Zendesk ticket fields, and customize how employees are matched between the HR system and Zendesk.

Key Functions

This integration automates Zendesk ticket creation for employee lifecycle events with the following primary capabilities:

  • Retrieves workforce data from the configured HR application.
  • Detects employee lifecycle events based on configured rules.
  • Creates Zendesk tickets for selected employee lifecycle events.
  • Allows custom employee matching between the HR application and Zendesk.
  • Maps HR attributes to Zendesk request fields.
  • Supports configurable rules to determine when employee lifecycle events are processed for ticket creation.
  • Sends event notifications through email.
  • Generates detailed logs, operational reports, and execution summaries.

Integration Setup

This section explains how to configure the integration to synchronize employee lifecycle events from an HR application with Zendesk and automatically create requests for the configured lifecycle events.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for HR / ITSM - Zendesk in the search box next to the Explore Templates section and click it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Source
  • Service Desk
  • Operations
  • Features
  • Schedule

Overview

The Overview tab displays general information about the integration, including its purpose and supported capabilities. It provides a high-level overview of how the integration automates ticket creation for employee lifecycle events.

Source

The Source tab allows you to select the HR application used by the integration and define which employees are considered for Zendesk ticket creation.

The following sections are available on this tab:

  • Application settings
  • Filter Employees
  • Filter Candidates

Application Settings

The Application Settings section allows you to identify the HR application instance used by the integration. The following field is available in this section for configuration:

  • HR application instance: Select the HR application connector from which employee data and lifecycle events will be retrieved for this integration. If the required connector is not available in the list, click the refresh icon next to the field to reload the available connectors.
    Notes:
    • Currently, this integration supports the ADP Workforce Now, UKG Ready, and Dayforce connectors.
    • When you select ADP Workforce Now in this field, the Filter Candidates section will be redisplayed for further configuration.
    • When you select UKG Ready in this field, the following field is displayed for further configuration.
      • Company name: Enter the company name configured in your UKG Ready instance. Refer to the UKG Ready Configuration Guide for details on obtaining the company name.

Filter Employees

This section allows you to define which employees from the HR application are considered for Zendesk ticket creation. The following field is available in this section for configuration:

  • Enable employee filter: Turn on this toggle button to filter employees considered for Zendesk ticket creation. Only employees who match the configured filter criteria are processed. When enabled, the Employee Filter Configuration section is displayed for further configuration.

Employee Filter Configuration

This section allows you to configure the criteria used to filter employees from the HR application for Zendesk ticket creation.

The following fields are displayed for configuration:

  • Use filter for account creation: Turn on this toggle button to filter users from the HR application. Only new hires who match the filter criteria are considered for Zendesk ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Hire Date.
  • Use filter for terminated employees: Turn on this toggle button to filter terminated employees from the HR application. Only terminated employees who match the filter criteria are considered for Zendesk ticket creation.
    When enabled, the following fields are available for configuration:
    • Employee filter criteria: Select the method used to filter terminated employees from the HR application. The following is the available option:
      • Based on date: Select this to filter terminated employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter terminated employees from the HR application. For example, Termination Date.
  • Use filter for temporary account disable: Turn on this toggle button to filter users from the HR application.  Only users who match the defined rules are considered for Zendesk ticket creation. When enabled, the following fields are displayed for further configuration:
    • Leave types that trigger account deactivation: Select the leave types that trigger account deactivation. The integration deactivates accounts only for users whose leave type matches the selected values.
  • Use filter for account rehire: Turn on this toggle button to filter rehires from the HR application. Only rehires who match the filter criteria are considered for Zendesk ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter to trigger rehire: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Hire Date. If you do not find your data attribute in the list, click the refresh icon available next to the field to reload the available attributes.

Filter Candidates

This section allows you to define which candidates from the HR application are considered for Zendesk ticket creation.

Note:

This section will appear only if you select ADP Workforce Now in the HR Application Instance.

The following field is available in this section for configuration:

  • Enable candidate filter: Turn on this toggle button to filter candidates considered for Zendesk ticket creation. Only candidates who match the configured filter criteria are processed. When enabled, the Candidate Filter Configuration section is displayed for further configuration.

Candidate Filter Configuration

This section allows you to configure the criteria used to filter candidates from the HR application for Zendesk ticket creation.

The following fields are displayed for configuration:

  • Use filters and controls for candidates: Turn on this toggle button to apply custom filter rules and controls for candidates that trigger account creation in the Zendesk ticket creation. When enabled, the following fields are displayed for further configuration.
    • Candidate filter criteria: Select the method used to filter employees from the source system. The following is the available option:
      • Based on status: Select this to filter candidates using a status from the source system. Only matching employees are considered for ticket creation.
    • Status to filter candidates: Select the candidate statuses that trigger account creation in the Zendesk ticket creation.

Service Desk

The Service Desk tab enables you to configure the Zendesk application, where employee lifecycle tickets are created and managed. It allows you to select the Zendesk instance, define which lifecycle events create tickets, configure ticket settings, and map HR attributes to Zendesk ticket fields.

The following sections are displayed in this tab:

  • Channel
  • JML Ticket Creation

Channel

This section enables you to identify the Zendesk application used by the integration to create tickets. The following field is available in this section for configuration:

  • Service desk application instance: Select the Zendesk application connector where the integration will create tickets. If the required connector is not available in the list, click the refresh icon next to the field to reload the configured application connectors.
  • Enable Messaging: Turn on this toggle button to send notifications to users or administrators via the configured messaging channel. When enabled, the following fields will be displayed for further configuration.
    • Enable Slack notification: Turn on this toggle to send notifications in the configured Slack channel. When enabled, the Messaging platform settings (Chat) field is displayed to configure the required channel.
    • Enable Teams notification: Turn on this toggle to send notifications in the configured Teams channel. When enabled, the Messaging platform settings (Teams) field is displayed to configure the required channel.

JML Ticket Creation

This section enables you to configure how Zendesk tickets are created for employee lifecycle events. The following field is displayed in this section:

  • Enable ticket creation: Turn on this toggle button to automatically create Zendesk tickets for employee lifecycle events. When enabled, the Ticket Creation Configuration section is displayed for configuration.

Ticket Creation Configuration

This section allows you to configure how Zendesk tickets are created for a selected employee lifecycle event.

If the List View toggle button is disabled, the following parameters are displayed:

  • Select event type: Select the employee lifecycle event for which Zendesk tickets should be created. The following lifecycle events are available for selection:
    • Hire: Select this option if you want to create Zendesk tickets when a new hire event is detected.
    • Terminate: Select this option if you want to create Zendesk tickets when a termination event is detected.
    • Rehire: Select this option if you want to create Zendesk tickets when a rehire event is detected.
  • Event timing: Define when the Zendesk ticket should be created for the selected lifecycle event. The following are the available options:
    • When detected: Select this if you want to create tickets immediately after the lifecycle event is detected.
    • Before start date: Select this if you want to create tickets before the actual start date of the employee.
    • On start date: Select this if you want to create tickets on the employee's start date.

    • After start date: Select this if you want to create tickets after the actual start date of the employee.

      When you select Before start date or After start date, the following field is displayed to define the number of days:

      • Days Before / After Joining Date: Enter the number of days before or after the selected lifecycle event date when the ticket should be created. For example, entering 7 with Before start date selected creates the ticket seven days before the employee's effective start date.
  • Enable conditional event detection: Turn on this toggle button to create Zendesk tickets only for employees who satisfy a defined condition. When enabled, the following field is displayed:
    • Ticket creation condition: Enter a condition to control which employees trigger Zendesk ticket creation. Only employees who satisfy this condition are considered for ticket creation. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.
  • Enable ticket creation: Turn on this toggle button to create Zendesk tickets for the selected lifecycle event. When enabled, the following fields are displayed for further configuration:
    • Ticket type: Select the ticket type that should be used when creating tickets. If the required ticket type is not available, click the Refresh icon next to the field to reload the available ticket types.
      The following are the available options:
      • Problem: Select this option to create Zendesk tickets of the problem type to investigate the root cause of recurring issues.
      • Incident: Select this option to create Zendesk tickets of the incident type to report and resolve service issues.
      • Question: Select this option to create Zendesk tickets of the question type to manage user inquiries and information requests.
      • Task: Select this option to create Zendesk tickets of the task type to track and complete assigned work.
  • Customize how users are matched across systems: Turn on this toggle button to configure custom employee matching. When enabled, the following fields are displayed.
    • Select how employees are matched between Source and Target: Select the method used to correlate employees between the HR application and Zendesk.
    • Select source attribute for matching the employee: Select the HR application attribute used to uniquely identify employees.
    • Select Target attribute for matching the employee: Select the Zendesk field used to uniquely identify employees.
  • Allow auto update the ticket: Turn on the toggle button to automatically update Zendesk JML tickets only when their current status matches one of the selected ticket statuses. When enabled, the following field is displayed:
    • Ticket statuses to evaluate for auto update: Select the Zendesk ticket statuses that should be evaluated to determine whether a ticket is eligible for automatic updates. If you do not find your ticket status in the list, click the refresh icon available next to the field to reload the available ticket statuses.
  • Auto close the ticket: Enable this option to automatically close the Zendesk JML ticket after all actions associated with the user lifecycle event have been completed successfully. When enabled, additional configuration options are displayed:
    • Ticket status to evaluate for auto close: Select the Zendesk ticket statuses that should be evaluated to determine whether a ticket is eligible for automatic closure. If you do not find your ticket status in the list, click the refresh icon available next to the field to reload the available ticket statuses.
    • Ticket close status: Select the Zendesk ticket status to apply when the integration automatically closes the ticket.
  • Onboarding Ticket Field Mapper: This section allows you to map HR attributes to Zendesk ticket fields. Source attributes are displayed on the left side, and Zendesk ticket fields are displayed on the right side of the page. You can modify only the source attributes as needed to align with your specific use case. JavaScript expressions can be used to transform source attribute values and construct the values that are updated in the target attributes. You can enter the expression directly in the source attribute field or click the expand icon to write a longer expression. The Search Attributes field allows you to search for source attributes.
    Attributes marked with a red asterisk (*) are mandatory for successful execution.
    After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the configuration.
  • Enable email notification: Turn on this toggle button to sent email notification when a hire event occurs. When enabled, the following fields are displayed:
    • Subject: Enter the content that must be used as the email subject.
    • Notification recipients: Select the recipients to send email notifications. For example, select Supervisor if you want to send email notifications to the user's supervisor. The following field is displayed when you select Custom in this field:
      • Custom email address: Enter the email IDs of the users to whom you want to send email notifications.
    • Email notification template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the email body.
  • Enable Slack notification: Turn on this toggle button to send a Slack notification when a hire event occurs. When enabled, the following fields are displayed:
    • Select Channel: Select the required channel where the hire notification should be posted. If you do not find the required channel in the list, click the refresh icon available next to the field to reload the available channel.
    • Teams notification template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the notification body.
  • Enable Teams notification: Turn on this toggle button to sent teams notification when a hire event occurs. When enabled, the following fields are displayed:
    • Select team: Select the required teams where the hire notification should be posted. If you do not find the required teams in the list, click the refresh icon available next to the field to reload the available teams.
    • Select Channel: Select the required channel where the hire notification should be posted. If you do not find the required channel in the list, click the refresh icon available next to the field to reload the available channel.
    • Teams notification template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the notification body.

To add another configuration, click the + icon adjacent to the List View toggle button.

To navigate to multiple configurations, use the arrow icons (< or >).

To delete a configuration, click the delete icon.

To view the notification configuration in list view, enable the List View toggle button.

In List View, only configured values are displayed. If you want to modify the configuration, click any value in the row and you will be redirected to the edit mode, where you can make changes.

    • GUID with Non-PII Data: Select this option to include GUIDs, operation details, field names, and selected non-PII values.
    • Employee Number with Non-PII Data: Select this option to include employee numbers, operation details, field names, and selected non-PII values.
    • Employee Number with All Data: Select this option to include employee numbers, operation details, field names, and all values, including both PII and non-PII data.
  • Log level: Select the log detail level. The following are the available options:
    • All: Select this to include all attribute details in logs.
    • Include List: Select this if you want to choose attributes to be included in logs. When selected, the following field is displayed:
      • Fields to include in logs: Select the attributes to be included. For example, Email.
    • Exclude List: Select this if you want to choose attributes to be excluded from the logs. When selected, the following field is displayed:
      • Fields to exclude from logs: Select the attributes to be excluded. For example, FirstName.

Features

The Features tab provides an overview of the functional capabilities supported by the integration. The following section is displayed on this tab:

Service Desk Bridge

The Service Desk Bridge section controls the functional capabilities supported by the integration.

The following features are available for this integration:

  • Enable HCM Bridge: This is enabled by default to process employee lifecycle events from the configured UKG Ready connector.
  • Enable Service Desk Bridge: This is enabled by default to create and manage Zendesk requests based on employee lifecycle events.
  • Enable Employee Lifecycle: This is enabled by default to process employee lifecycle events, including onboarding, employee changes, and termination events.
  • JML Lifecycle Events: This is enabled by default to create Zendesk requests for Joiner, Mover, and Leaver (JML) lifecycle events.

Additional features displayed on this page represent capabilities supported by the integration. To learn more or enable these features, contact the Aquera Support team.
