ADP Workforce Now / Homecare Homebase Integration Guide

← Back to index

Overview

The Aquera platform allows your organization to scale complex data management by automating data integration across resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It allows organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately improving efficiency in managing intricate IT infrastructures and applications.

In this integration, worker records that are created, updated, or terminated in ADP Workforce Now are automatically provisioned in Homecare Homebase based on the defined schedule. The integration evaluates each worker's employment status in ADP Workforce Now, determines whether the corresponding HCHB profile must be created, updated, or deactivated, and applies the change through the HCHB API.

To identify user records across both systems, the integration uses the attribute configured in the ADP Workforce Now Correlation Attribute parameter and matches it to the attribute configured in the HCHB Correlation Attribute parameter as a correlation attribute.

Key Functions

The ADP Workforce Now / Homecare Homebase Integration performs the following functions:

  • Synchronizes worker records from ADP Workforce Now to Homecare Homebase.
  • Creates new worker profiles in HCHB when a worker is added and becomes active in ADP Workforce Now.
  • Updates existing HCHB worker profiles when the corresponding worker's information changes in ADP Workforce Now.
  • Deactivates HCHB worker profiles when a worker becomes inactive or is terminated in ADP Workforce Now.
  • Supports both full synchronization and incremental synchronization so that only changed or newly eventing records are processed.
  • Defers a worker's deactivation to a configured time of day, optionally evaluated in the worker's own time zone, and automatically re-evaluates deferred deactivations on every subsequent run until they become due.
  • Sends a welcome email to newly provisioned HCHB users with their generated username and temporary password.
  • Sends success and failure notification emails to administrators, optionally with a CSV integration report attached.
  • Generates a downloadable CSV integration report and detailed, field-level change logs for troubleshooting.
  • Supports a report-only (simulation) mode that shows the changes that would be made without applying them.
  • Supports testing with hard-coded ADP Workforce Now and HCHB payloads, without calling the live application APIs.
  • Logs integration metrics to a Log Insights dashboard for monitoring.

Prerequisites

The following are the prerequisites:

  • Admin Access to ADP Workforce Now: You must have admin access to your ADP Workforce Now instance to configure API access for the integration.
  • Admin Access to Homecare Homebase: You must have admin access to your Homecare Homebase instance.
  • ADP Workforce Now API Subscription and Consent: The integration calls ADP Workforce Now Human Resources and Events APIs (for example Workers, Worker, Events, Federal/State/Local Tax Profiles, Certifications, Licenses, Time Off, Pay Distributions, Pay Statements, and Personal Contacts, depending on the attributes selected). Ensure that consent has been granted to the Aquera application in the ADP Marketplace and that its subscription status is active. If consent is missing or the subscription is suspended, the integration will fail with a corresponding error during execution.
  • Homecare Homebase API Access: The HCHB service account used by the integration must have permission to search for, read, and create or update worker profiles.
  • Aquera Tenant Account: You must have a tenant account in the Aquera Admin portal. Visit https://admin.aquera.io to register for a tenant account. Contact your Aquera account manager to get Aquera tenant access.

Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io

  • Configure Application Connectors in the Aquera Admin Portal: You need to configure the ADP Workforce Now and Homecare Homebase application connectors in the Aquera Admin Portal before creating the integration.

Note: Terminated and inactive workers in ADP Workforce Now are not created in HCHB. Only workers that satisfy the configured Create Condition are provisioned.

Integration Setup

This section outlines how the integration must be configured to provision worker data from ADP Workforce Now into Homecare Homebase.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left-side panel.
  3. Click Create Integration.
  4. Select ADP Workforce Now / HCHB.
  5. Enter a name and a description for the integration.
  6. Select your ADP Workforce Now and Homecare Homebase connector instances.
  7. Click Continue. The Configuration page is displayed to configure the integration.

Configuration

The following sections are displayed under the Configuration tab:

Applications

The Applications section displays the source and target application connectors for the integration. This section allows you to search and update these application connectors.

Parameters

The Parameters section enables you to customize the integration settings according to your specific use case. It has the following sub-sections:

Integration Features

  • Enable User Lifecycle Management: Enable this toggle button to synchronise worker data from ADP Workforce Now to HCHB. When enabled, the Manage Users tab is displayed for further configuration.

General Settings

  • Enable Full Sync: Select this checkbox to execute the integration in full sync mode. When cleared, the integration runs incrementally and only processes workers that have changed since the last successful run.
  • Enable Report-Only Mode: Select this checkbox to generate a report detailing the data changes that would happen, without actually applying them to HCHB.
  • Enable Logging: Select this checkbox to generate logs outlining data changes. When enabled, the Logging tab is displayed for further configuration.
  • Enable Notifications: Select this checkbox to enable integration-related email notifications. When enabled, the Notification tab is displayed for further configuration.
  • Enable Report Generation: Select this checkbox to generate a downloadable CSV integration report. When enabled, the Reporting tab is displayed for further configuration.
  • Enable Log Insights: Select this checkbox to analyze integration-related metrics on a dashboard. When enabled, the Log Insights tab is displayed for further configuration.
  • Enable Debug Mode: Select this checkbox to generate logs outlining data changes for debugging purposes, including a field-level diff between the existing HCHB worker and the payload about to be sent. When enabled, the Debug Mode tab is displayed for further configuration.
  • Full Sync Threshold In days: Enter the number of days after which a full synchronization is automatically triggered, measured from the last successful sync. For example, if you enter 4, a full sync automatically runs once four days have elapsed since the last successful run, even if incremental sync was configured.

Manage Users

The Manage Users tab is displayed only when the Enable User Lifecycle Management parameter is enabled under Parameters. It enables you to customize how workers are correlated, and when they should be created, updated, or deactivated in HCHB.

ADP Workforce Now Settings

  • ADP Workforce Now Correlation Attribute: Select the ADP Workforce Now attribute used to distinctly find the associated HCHB worker record. The available options are Associate OID, Worker ID, and Position ID.
  • User Provisioning Configuration: Select one or more operations from the dropdown menu — Create, Update, Delete — to determine which lifecycle actions the integration should perform.
  • ADP Workforce Now Active Statuses: Select one or more ADP Workforce Now worker status values that should be treated as active (for example Active, On Leave). Workers with these statuses are eligible for creation and update in HCHB.
  • ADP Workforce Now Inactive Statuses: Select one or more ADP Workforce Now worker status values that should be treated as inactive (for example Terminated, Inactive, Retired). Workers with these statuses are eligible for deactivation in HCHB.

Note: The same status value cannot be configured as both active and inactive. The integration validates this and stops with an error if a duplicate is found.

Create User Settings

This section is displayed only when Create is selected in the User Provisioning Configuration parameter.

  • Create User Limit: Specify the maximum number of employee records that must be created in HCHB during a single integration run. Leave this blank to create every record that satisfies the Create Condition.
  • Create Condition: Select a condition from the dropdown menu to specify which ADP Workforce Now user records should be created in HCHB. The available options are All Active Users and Custom.
  • Custom Create Condition: Enter a JavaScript expression that defines the create condition. This field is displayed only when Custom is selected in Create Condition.

Update User Settings

This section is displayed only when Update is selected in the User Provisioning Configuration parameter.

  • Update User Limit: Specify the maximum number of employee records that must be updated in HCHB during a single integration run.
  • Update Condition: Select a condition from the dropdown menu to specify which ADP Workforce Now user records should be updated in HCHB. The available options are All Active Users and Custom.
  • Custom Update Condition: Enter a JavaScript expression that defines the update condition. This field is displayed only when Custom is selected in Update Condition.

Delete User Settings

This section is displayed only when Delete is selected in the User Provisioning Configuration parameter.

  • Deactivation time for terminating a user: Enter the time of day, in HH:MM:SS format, at which a worker's HCHB profile becomes eligible for deactivation on or after their ADP Workforce Now termination date. If this field is left blank, the deactivation is not gated by a time of day and proceeds as soon as the worker is identified as inactive.
  • Deactivate based on users timezone: Turn on this toggle button to evaluate the deactivation time in the worker's own time zone instead of the runtime's local time zone. The worker's time zone is resolved from their primary work assignment's time profile, their home work location, or, failing that, from the U.S. state associated with their home work location.
  • Delete User Limit: Specify the maximum number of employee records that must be deleted (deactivated) in HCHB during a single integration run.
  • Delete Condition: Select a condition from the dropdown menu to specify which ADP Workforce Now user records should be deleted in HCHB. The available options are All Inactive Users and Custom.
  • Custom Delete Condition: Enter a JavaScript expression that defines the delete condition. This field is displayed only when Custom is selected in Delete Condition.

Note: If a worker's termination date and time have not yet been reached, the worker is held in an internal cache and the deactivation is skipped for that run with a reason of "Termination deferred". The integration automatically re-checks cached workers on every subsequent run and deactivates them once the configured time is reached. Refer to the Future Terminated Users Cache section in the Appendix for details.

HCHB Settings

  • HCHB Correlation Attribute: Select the HCHB attribute used to distinctly find the associated ADP Workforce Now user, for example, PayrollNumber.

Logging

This tab is displayed only when the Enable Logging parameter is enabled under Parameters. It enables you to customize the log generation settings.

  • Log Detail Level: Select the desired log detail level from the dropdown menu. The available options are Summary Only, Full Details, and Custom.
  • Show Attribute Values for Each Event: Select this checkbox to populate the attribute values for each event when choosing the Full Details or Custom option. This requires consent to store event data temporarily.

When Custom is selected as the Log Detail Level, the following parameters are displayed:

  • Attribute Filter: Select whether to include or exclude specific attributes in the log.
  • Included Attributes: Select the attributes to be included in the log. This is displayed only when Included Attributes is selected in the Attribute Filter parameter.
  • Excluded Attributes: Select the attributes to be excluded from the log. This is displayed only when Excluded Attributes is selected in the Attribute Filter parameter.

Notification

This tab is displayed only when the Enable Notifications parameter is enabled under Parameters. It allows you to configure the welcome email sent to new HCHB users, the notification report attached to admin emails, and the admin notification emails sent when the integration succeeds or fails.

Welcome Email Notification

  • Enable to send welcome Email notification to user: Turn on this toggle button to send a welcome email to a worker after their HCHB profile is provisioned.
  • Welcome Email Subject: Enter the content that must be used as the subject of the welcome email.
  • Welcome Email Body: Enter the content that must be used as the body of the welcome email. Use the placeholders ${name}, ${userName}, and ${password} to insert the worker's name, generated HCHB username, and temporary password respectively.

Note: The welcome email is sent after the worker's first successful update in HCHB following their creation, once their login credentials are available, and is sent only once per worker.

Notification Report Settings

  • Send Integration Report via Email: Select this checkbox to receive an email notification with a CSV report attached, for all integration runs.
  • Report Detail Level: Select the report detail level from the dropdown menu. The available options are Summary Only, Full Details, and Custom.
  • Show Attribute Values for Each Event: Select this checkbox to populate the attribute values for each event when choosing the Full Details or Custom option.

Execution Success Notification

  • Admin's Email Address: Enter the email addresses of the admins to whom the success notification email will be sent.
  • Email Subject: Enter the content that must be used as the email subject for sending success notifications to the admins.
  • Email Notification Body: Enter the content that must be used as the email body for sending success notifications to the admins.

Execution Failure Notification

  • Admin's Email Address: Enter the email addresses of the admins to whom the failure notification email will be sent.
  • Email Subject: Enter the content that must be used as the email subject for sending failure notifications to the admins.
  • Email Notification Body: Enter the content that must be used as the email body for sending failure notifications to the admins. Use the placeholder ${error} to insert the error details.

Reporting

This tab is displayed only when the Enable Report Generation parameter is enabled under Parameters. It enables you to customize the CSV integration report that Aquera writes for every run.

  • Report Detail Level: Select the desired report detail level from the dropdown menu. The available options are Summary Only, Full Details, and Custom.
  • Show Attribute Values for Each Event: Select this checkbox to populate the attribute values for each event when choosing the Full Details or Custom option.

Log Insights

This tab is displayed only when the Enable Log Insights parameter is enabled under Parameters. It enables you to customize the metrics that are pushed to the Log Insights dashboard.

  • Log Insights Detail Level: Select the desired log insights detail level from the dropdown menu. The available options are Summary Only, Full Details, and Custom.
  • Show Attribute Values for Each Event: Select this checkbox to populate the attribute values for each event when choosing the Full Details or Custom option.

Debug Mode

This tab is displayed only when the Enable Debug Mode parameter is enabled under Parameters. It enables you to limit and target the workers retrieved from ADP Workforce Now during troubleshooting.

  • ADP Workforce Now Filter Attribute: Select the ADP Workforce Now attribute to filter workers while retrieving from ADP Workforce Now, for example, AssociateOID. When a value is selected, the integration switches to full sync and retrieves only the matching worker.
  • Filter Attribute Value: Provide the value for the selected filter attribute, for example, a specific Associate OID.
  • Import Limit: Specify the maximum number of worker records that can be imported from ADP Workforce Now during a single integration run.

Hard Coded Values

This tab is displayed only when the Enable Test With Hard Coded Values parameter is enabled under Parameters. It allows you to supply fixed worker payloads so the integration can be tested without calling the live ADP Workforce Now or HCHB APIs.

  • ADP Hard Coded Values: Enter a JSON payload containing one or more ADP Workforce Now worker records. When configured, the integration uses these records instead of retrieving workers from ADP Workforce Now.
  • Homecare Homebase Hard Coded Values: Enter a JSON payload containing one or more HCHB worker records. When configured, the integration uses these records instead of searching for correlated workers in HCHB.

Note: This mode is intended for configuration testing only. Disable it before running the integration against production data.

Attribute Map

The Attribute Map tab defines how worker data is mapped from ADP Workforce Now to Homecare Homebase. The default mapping of attributes is displayed on the page. The source attributes are listed on the left side and the target attributes are listed on the right side of the page.

You can modify only the source attributes as needed to align with your specific use case. You can write JavaScript expressions to transform the value of a source attribute and construct the value that is written to the target attribute. Write the expression directly in the source attribute field, or click the Expand icon in the source attribute field to write a longer expression.

Several HCHB target fields expect coded values (for example job title, worker status, worker category, payment method, or team IDs) rather than the free-text values available in ADP Workforce Now. For these fields, the attribute mapping looks up the corresponding HCHB code from a lookup table configured under the Tables tab, based on the worker's ADP Workforce Now values such as department, work location, and status.

After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the integration.

Tables

Tables can be added to create custom source attributes and POST (sync) them to the target application. Tables are used when an application attribute is empty or a specific data is not sent from the Jira Service Management Cloud application, and you want to update a value for that attribute in Active Directory. Based on your requirement, you can add any number of tables in the integration.

The table setup and functionality are the same as that in the User Integration. Refer to the Adding Tables in Integration section in the Using Tables in Integrations guide for details.

Update the Integration to the Latest Version

You can upgrade an integration built from a template to the latest version to access new features and enhancements. 

Perform the following steps to upgrade an integration:

  1. Navigate to the Integrations module on the Aquera Admin portal.
  2. Click the vertical ellipsis icon next to an integration and click View Details. The Details panel is displayed with the following sections:
    • INTEGRATION DETAILS: Displays the integration name, description, creation date, last update date, and the user who created or last updated it.
    • TEMPLATE DETAILS: Displays the current version number and its features under CURRENT VERSION. If a newer version is available, the version number and the changes are shown under NEW VERSION AVAILABLE with an Upgrade button.
  3. Click Upgrade. The Upgrade Integration pop-up window is displayed.
  4. Provide the following details for the new integration to be created after the upgrade:
    • New Integration Name: Enter the name of the new integration.
    • Description: Provide a description for the new integration.
      The current version number and the upgraded version number are displayed.
  5. Click Upgrade. A new integration is created with the same configuration details as the existing one, but with features or enhancements from the upgraded version.
