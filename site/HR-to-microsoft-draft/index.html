Ignore Case When Checking Uniqueness: This toggle determines whether the integration must ignore the character case of the generated value while checking uniqueness against the existing value.

  • When enabled, the integration ignores differences in character case between the generated value and the existing value while checking for uniqueness.
  • When disabled, the integration considers the generated value and the existing value as separate records. The generated value is treated as a new record, and the attempt logic is applied to it.

Update Case To Match Naming Pattern: This toggle determines whether the integration must update the existing user naming attribute values to match the character case of the values generated based on the user naming attributes configured in the integration.

  • When enabled, the integration compares the generated value with the existing value. If the values differ only by character case, the existing value is updated to match the character case configured in the Advanced User Naming Configuration section.
  • When disabled, the character case of the existing value is not updated.

Note: This toggle is displayed only when the Ignore Case When Checking Uniqueness toggle is enabled.

 

Ignore Case When Checking Uniqueness: This toggle determines whether the integration must ignore the character case when comparing the generated user naming attribute values with the existing attribute values in the directory for uniqueness.

  • When enabled, the integration ignores differences in character case between the generated value and the existing value while checking for uniqueness. For example, jsmith and JSmith are considered the same value.
  • When disabled, the integration considers character case when checking for uniqueness. Values that differ only by character case are considered different. The generated value is treated as a new record, and the attempt logic is applied to generate the unique attribute values.

Update Case To Match Naming Pattern: This toggle determines whether the integration must update the character case of existing user naming attribute values to match the values generated using the Advanced user naming configuration.

  • When enabled, the integration compares the generated value with the existing value. If the values differ only by character case, the existing value is updated to match the character case of the value generated using the Advanced user naming configuration.
  • When disabled, the character case of the existing value remains unchanged.

Note: This toggle is displayed only when the Ignore Case When Checking Uniqueness toggle is enabled.

Attribute Map

The integration supports hard-coded values for the Active attribute in the target Attribute Mapper. The integration also evaluates the configured offboarding conditions to determine whether a user should be activated or deactivated.

  • Deactivation: When the Active attribute is set to false, the user is deactivated only if the configured offboarding conditions are satisfied.
  • Activation: When the Active attribute is set to true, the user can be activated only if the configured offboarding conditions are not satisfied.

Event

The Events tab allows Aquera integrations to process specific events that occur in an application or system and synchronize the resulting changes with another application or system. These events may include creating an employee, deleting an employee, updating person data, and more.

To send event notifications to Aquera, you must configure webhooks in the source application and specify the events for which notifications should be sent. You must also configure the Aquera event integration URL as the destination for these notifications.

Notes: 

  • Contact Aquera Support to enable the Events tab. When the Event tab is enabled, the Schedule tab is not displayed.
  • Currently, this tab is tested and certified only with Paycor v9. For details on how to set up event hooks in Paycor, refer to the Set Up Webhooks in Paycor section in the Set Up Webhooks in Paycor guide.

The following events must be enabled for the application to send notifications via webhooks:

  • Person Information Created
  • Person Information Updated
  • Employee Created
  • Employee Deleted
  • Employee Information Updated

Refer to the Event Triggers section to learn which properties trigger each of the events listed above.

Perform the following in the Event tab:

  1. Event Trigger Enabled: Turn on the Event Trigger Enabled toggle button to trigger the integration when events occur.
  2. Event Source: Select the connector application that you configured for the integration from the dropdown menu.
  3. URL: Copy the URL and save it.
  4. Create Token: Click Create Token. A token is generated. Click Save Changes twice to save the configuration, then copy and save the token.
    Use the copied URL and token when configuring webhooks in the Event Subscription tab of the connector application's portal.

     
  5. URL: Copy the URL and paste it into the Event Subscription tab when setting up the webhooks in the connector application's portal.
  6. Create Token: Click Create Token. A token is generated. Click Save Changes twice to save the configuration, then copy the token and paste it into the Event Subscription tab when setting up webhooks in the connector application's portal.
