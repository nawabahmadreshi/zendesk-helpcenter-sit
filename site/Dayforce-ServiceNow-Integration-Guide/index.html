Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

 

Key Functions

This integration automates service desk processes for lifecycle events with the following capabilities:

  • Identifies workforce lifecycle events from the HR application, including hire, change, leave, termination, and rehire events.
  • Creates service requests or tickets in the configured service desk application based on selected lifecycle events.
  • Supports configurable event timing to create tickets when an event is detected, before the event date, on the event date, or after the event date.
  • Allows custom eligibility rules to control which employee records are included in lifecycle event processing.
  • Automatically updates or closes existing service desk tickets based on configured ticket statuses.
  • Sends event notifications through email and Microsoft Teams.
  • Generates detailed logs, operational reports, and execution summaries.

Prerequisites

The following are the prerequisites:

  • Aquera Tenant Account: You must have a tenant account in the Aquera Admin portal. Visit https://admin.aquera.io to register for a tenant account. Contact your Aquera account manager to get Aquera tenant access.
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/

    • ServiceNow Connector: You must configure a ServiceNow connector in the Aquera Admin Portal. Refer to the ServiceNow Configuration Guide for details.

Integration Setup

This section outlines how the integration must be configured to synchronize workforce lifecycle events from Dayforce to ServiceNow and automate the creation and management of service requests and tickets.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin Portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for Dayforce / ServiceNow in the search box next to the Explore Templates section and click it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Features
  • Source
  • Service Desk
  • Operations
  • Tables
  • Schedule

Overview

On this tab, you can view general information about the integration, including its purpose, functionality, and supported capabilities. This section provides a high-level overview of how the integration operates between connected applications.

Features

The Features tab provides an overview of the functional components supported by the integration. These features define the capabilities available within the integration and determine the configuration tabs and settings that are available.

Note: The features displayed on this tab are mandatory for this integration and are enabled by default. These features cannot be modified or disabled because they are required for the integration to function correctly.

HCM Bridge

The HCM Bridge section controls workforce lifecycle processing within the integration. The following feature is enabled by default:

  • Enable HCM bridge: This feature processes workforce lifecycle events from the Dayforce application, including onboarding, organizational changes, termination, and rehire events. It also makes the Source tab available, where you configure the Source application.

Service Desk Bridge

The Service Desk Bridge section controls service requests and ticket automation within the integration. The following features are enabled by default:

  • Enable service desk bridge: This feature creates and manages service requests or tickets based on workforce lifecycle events. It also makes the Service Desk tab available, where you configure the Target application. The following option is available:
    • JML lifecycle event: Creates and manages service desk tickets for Joiner, Mover, and Leaver (JML) lifecycle events. This feature enables the Lifecycle Event section, where you configure JML event processing.

Operations

The Operations section controls the operational execution capabilities of the integration. The following feature is enabled by default:

  • Enable operations: This feature executes scheduled synchronization jobs, operational workflows, monitoring activities, and other integration processes required for the integration to function.

Source

The Source tab enables you to configure the HR application used by the integration and define how workforce data is retrieved and processed. It also provides advanced settings to control change detection and future-dated workforce event processing.

Application Settings

The Application Settings section enables you to configure the Dayforce application used by the integration. It allows you to select the application instance from which to retrieve workforce data.

  • Source application instance: Select the Dayforce application connector that this integration will connect to for retrieving data. 

Filter Employees

The Filter Employees section allows you to configure how workforce lifecycle events from Dayforce are processed and synchronized with ServiceNow. You can define the conditions that control account creation, termination, and rehire events.

  • Enable employee filter: Enable this option to filter the employees considered for ServiceNow ticket creation. Only employees who match the configured filter criteria are processed for ticket creation. When enabled, the Employee Filter Configuration section is displayed to configure further integration settings.  

Employee Filter Configuration

The Employee Filter Configuration section allows you to configure the criteria used to filter employees from the HR application for ServiceNow ticket creation.

The following fields are displayed for configuration:

  • Use filter for account creation: Enable this option to filter employees from the Dayforce application for account creation. Only new hires who match the configured filter criteria are considered for ServiceNow ticket creation. When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the Dayforce application. The following is the available option:
      • Based on date: Select this option to filter employees using a date attribute from the Dayforce application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the Dayforce application. For example, select Hire Date. If you do not find your date attribute in the list, click the refresh icon available next to the field to reload the available attributes.
    • Hire employees lookback (days): Enter the number of past days to consider when filtering hired employees.
  • Use filter for account termination: Enable this option to filter employees from the Dayforce application for account termination. Only employees who match the configured filter criteria are processed for account termination. When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter terminated employees from the Dayforce application. The following is the available option:
      • Based on date: Select this option to filter terminated employees using a date attribute from the Dayforce application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the Dayforce application. For example, select Termination Date. If you do not find your data attribute in the list, click the refresh icon available next to the field to reload the available attributes.
    • Terminated employees lookback (days): Enter the number of past days to consider when filtering terminated employees.
  • Use filter for account rehire: Enable this option to filter employees from the Dayforce application for account rehire. Only employees who match the configured filter criteria are processed for account rehire. When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter rehired employees from the Dayforce application. The following is the available option:
      • Based on date: Select this option to filter rehired employees using a date attribute from the Dayforce application. Only matching employees are considered for ticket creation.
    • Rehired employees lookback (days): Enter the number of past days to consider when filtering rehired employees.

JML Ticket Creation

The JML Ticket Creation section enables you to configure how ServiceNow tickets are created for employee lifecycle events. The following field is displayed in this section:

  • Enable ticket creation: Enable this option to automatically create ServiceNow tickets for employee lifecycle events. When enabled, the Ticket Creation Configuration section is displayed for configuration.

Ticket Creation Configuration

The Ticket Creation Configuration section allows you to configure how ServiceNow tickets are created for a selected employee lifecycle event.

Click Add Event Configuration to open the Event Configuration panel and configure the following parameters:

  • Select event type: Select the employee lifecycle event for which ServiceNow tickets should be created. The following lifecycle events are available for selection:
    • Hire: Select this option if you want to create ServiceNow tickets when a new hire event is detected.
    • Change: Select this option to create ServiceNow tickets when a change event is detected.
    • Leave: Select this option to create ServiceNow tickets when a leave event is detected.
    • Terminate: Select this option to create ServiceNow tickets when a termination event is detected.
    • Rehire: Select this option to create ServiceNow tickets when a rehire event is detected.
  • Event timing: Define when the ServiceNow ticket should be created for the selected lifecycle event. The following are the available options:
    • When detected: Select this option to create tickets immediately after the lifecycle event is detected.
    • On hire date: Select this option to create tickets on the employee's start date.
    • Before start date: Select this option to create tickets before the actual start date of the employee.
      • Days Before / After Joining Date: Enter the number of days before or after the selected lifecycle event date when the ticket should be created. For example, entering 7 with Before start date selected creates the ticket seven days before the employee's effective start date.
    • After start date: Select this option to create tickets after the actual start date of the employee.
      • Days Before / After Joining Date: Enter the number of days before or after the selected lifecycle event date when the ticket should be created. For example, entering 7 with Before start date selected creates the ticket seven days before the employee's effective start date.
  • Enable conditional event detection: Enable this option to apply a condition for ticket creation. When enabled, the following field is displayed:
    • Ticket creation condition: Enter the condition used to determine which employees trigger ServiceNow ticket creation. Only employees who satisfy this condition are considered for ticket creation. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.
  • Enable ticket creation: Enable this option to create ServiceNow tickets for the selected lifecycle event. When enabled, the following fields are displayed for further configuration:
    • Space: Select the Jira Service Management space where tickets will be created. For example, select My Team if you want the tickets to be created in the My Team space.
      If the required space is not available, click the Refresh icon next to the field to reload the available spaces.
    • Work type: Select the work type that should be used when creating tickets. For example, Task. If the required work type is not available, click the Refresh icon next to the field to reload the available work types.
    • Enable to extend schema with Jira request type: Turn on this toggle button to retrieve additional request fields associated with the selected Jira Request Type. When enabled, the additional available ticket fields are retrieved and available for mapping in the Onboarding Ticket Field Mapper.
    • Request Type: Select the Jira Service Management request type used when creating tickets for the selected lifecycle event. If the required request type is not available, click the Refresh icon next to the field to reload the available request types.
    • Resolved Status Category: Select the Jira status category that represents completed requests. The selected status category is used by the integration when evaluating existing tickets. If the required status category is not available, click the Refresh icon next to the field to reload the available status categories.
    • Customize how users are matched across systems: Turn on this toggle button to configure custom employee matching. When enabled, the following fields are displayed.
      • Select How Employees Are Matched Between Source and Target: Select the method used to correlate employees between the HR application and Jira Service Management.
      • Select Source Attribute for Matching the Employee: Select the HR application attribute used to uniquely identify employees.
      • Select Target Attribute for Matching the Employee: Select the Jira Service Management field used to uniquely identify employees.
    • Onboarding Ticket Field Mapper: This section allows you to map HR attributes to Jira Service Management ticket fields. Source attributes are displayed on the left side, and Jira ticket fields are displayed on the right side of the page. You can modify only the source attributes as needed, to align with your specific use case. JavaScript expressions can be used to transform source attribute values and construct the values that are updated in the target attributes. You can enter the expression directly in the source attribute field or click the expand icon to write a longer expression. The Search Attributes field allows you to search for source attributes.
      Attributes marked with a red asterisk (*) are mandatory for successful execution.
      After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the configuration.
  • Send ticket creation request by email: Enable this option to send an email request with employee lifecycle event details to the configured recipients. Recipients can use the email to create the required ticket in the service desk application. When enabled, additional configuration options are displayed:
    • Ticket creation email subject: Enter the content that must be used as the email subject in the notifications sent for ticket creation.
    • Ticket creation email recipients: Select one or more recipient groups to whom the email notifications will be sent for ticket creation.
    • Ticket creation email template: Enter the content that must be used as the email body in the notifications sent for ticket creation.
  • Send ticket creation request by Slack: Enable this option to send a Slack message with employee lifecycle event details to the configured channel. When enabled, additional Slack settings are displayed: 
    • Select channel: Select the Slack channel within the selected team where ticket creation notifications will be posted. If you do not find your channel in the list, click the refresh icon available next to the field to reload the available channels.
    • Slack notification template: Enter the content that must be used as the notification message sent for ticket creation.
  • Send ticket creation request by Microsoft Teams: Enable this option to send a Microsoft Teams message with employee lifecycle event details to the configured team. When enabled, additional Teams notification settings are displayed: 
    • Select team: Select the Microsoft Teams team where ticket creation notifications will be posted. If you do not find your team in the list, click the refresh icon available next to the field to reload the available teams.
    • Select channel: Select the Microsoft Teams channel within the selected team where ticket creation notifications will be posted. If you do not find your channel in the list, click the refresh icon available next to the field to reload the available channels.
    • Teams notification template: Enter the content that must be used as the notification message sent for ticket creation.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the Ticket field mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the ticket field mapper, if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.

Update the Integration to the Latest Version

You can upgrade an integration built from a template to the latest version to access new features and enhancements. 

Perform the following steps to upgrade an integration:

  1. Navigate to the Integrations module on the Aquera Admin portal.
  2. Click the vertical ellipsis icon next to an integration and click View Details. The Details panel is displayed with the following sections:
    • INTEGRATION DETAILS: Displays the integration name, description, creation date, last update date, and the user who created or last updated it.
    • TEMPLATE DETAILS: Displays the current version number and its features under CURRENT VERSION. If a newer version is available, the version number and the changes are shown under NEW VERSION AVAILABLE with an Upgrade button.
  3. Click Upgrade. The Upgrade Integration pop-up window is displayed.
  4. Provide the following details for the new integration to be created after the upgrade:
    • New Integration Name: Enter the name of the new integration.
    • Description: Provide a description for the new integration.
      The current version number and the upgraded version number are displayed.
  5. Click Upgrade. A new integration is created with the same configuration details as the existing one, but with features or enhancements from the upgraded version.
