This guide applies to integration version 1.1.0.

Prerequisite Component

  • Custom Identity Source: You must configure a custom identity source in your Okta application. For more information, refer to the Custom Identity Source Configuration section in the Okta Initial Setup Guide.

Integration Execution

The Integration Execution section allows you to manage attribute updates for the user directory and the Okta application.
  • Integration Sync Mode: Select the mode that determines which attributes are updated during integration execution. The following options are available:
    • Aquera Manage: Select this option to update the user directory attributes. The Attribute Map section displays the Okta user directory attributes.
    • Okta Manage: Select this option to update the attributes of the Custom Identity Source application configured in Okta. The Attribute Map section displays only the Okta application attributes.

Aquera Manage

Aquera Manage enables users to update the user directory attributes. When Aquera Manage is selected, the Attribute Map section displays the directory attributes.

Okta Manage

When Okta Manage is selected in the Integration Execution field, the following sections display a different set of options.

Onboarding

In the Onboarding section, in the Bulk Upsert section, you can configure the expression to create new records and update existing records in Okta. Enter a JavaScript expression in the Upsert Expression field to perform bulk update and insert operations. 
The following are a few sample expressions:
  • SOURCE.Active === false && SOURCE.JobAssignment === "Admin Assistant (USA)" && SOURCE.WorkAssignmentJobLedgerCode!== "100200" && SOURCE.WorkAssignmentJobLedgerCode!== "100201"
  • SOURCE.Active == true || SOURCE.Active == false
  • true: Considers all users whose active attribute is set to true or false in the source application. 
  • false: Ignores the upsert operation.

Offboarding

In the Offboarding section, in the Bulk Delete section, you can delete multiple records at a single time based on the JavaScript expression provided in the Delete Expression field. Enter a JavaScript expression in the Delete Expression field to determine whether the bulk delete operation should be performed.
The following are sample values:

  • SOURCE.Active === false && SOURCE.JobAssignment === "Admin Assistant (USA)" && SOURCE.WorkAssignmentJobLedgerCode!== "100200" && SOURCE.WorkAssignmentJobLedgerCode!== "100201"
  • SOURCE.Active == true || SOURCE.Active == false
  • true: Considers all users whose active attribute is set to true or false in the source application. 
  • false: Ignores the upsert operation.

For information on remaining configuration fields in the Configuration tab, refer to the Integration Configurations Reference Guide.

Attribute Map

Auto-Create and Map Attributes in Okta Application: Enable the toggle button to automatically create attributes that are missing in the Okta application. Enter a source attribute/expression for the required attribute in the Attribute Map section, click Save Changes, and click the Refresh icon. If the attribute does not exist in the Okta application, the integration automatically creates the attribute. 
Refresh the Okta page to view the newly created attribute with the attribute type Custom.

If the toggle button is disabled and a source attribute/expression is configured for an attribute that is missing in the Okta application, the integration may fail. In such cases, you must manually create the attribute in the Okta application before running the integration.

Note: This toggle button is visible only when Aquera Manage is selected in the Integration Sync Mode field in the Connection tab.

Known Limitations

  • Map On Manager, User Naming Formats, Match Expression and Group Management tabs are currently not supported when we select Okta Manage in the Integration Execution field. This issue will be fixed in a future release.

Offboarding

In the Offboarding section, configure the following fields to manage user deactivation:

The Active Guard checkbox determines whether users can be deactivated when they meet the Deactivate Condition, even if they are active in the source application. The checkbox is enabled by default.

  • When the checkbox is selected, users are deactivated only when they meet the Deactivate Condition and are inactive in the source application.
  • When the checkbox is not selected, users are deactivated when they meet the Deactivate Condition, even if the user is active in the source application.

The Deactivate Condition field allows you to enter a JavaScript expression to determine whether a user should be deactivated.
The following is a sample expression:

SOURCE.active==false && SOURCE.EmploymentStatuses=="Terminated"

Notes: 

  • Even if the user is Active in the HR system, the user will be deactivated if they meet the Deactivate Condition
  • When upgrading from an older version, you must configure the new Deactivate Condition field. Until this field is configured, no users will be deactivated.

The Okta User Deactivation Statuses field allows you to select the statuses that should be considered inactive. The following options are available:

  • Deactivated
  • Suspended

Configure the reactivation settings in the Okta application by performing the following steps:

  1. Log in to your Okta instance.
  2. Select the application you created.
  3. Navigate to Provisioning > To Okta > Profile & Lifecycle Sourcing.
  4. Select the following checkboxes under When a user is reactivated in the app:
    • Reactivate suspended Okta users
    • Reactivate deactivated Okta users

Note: The Okta User Deactivation Statuses field applies to both employees and candidates.

Notifications

This section allows you to define notification settings for provisioning events.

To navigate to multiple configurations, use the arrow icons (< or >) which are located at the bottom-right side of the table.

If you want to modify the configuration, click any value in the row, and you will be redirected to the edit mode, where you can make changes.

If you want to display a few rows in the table, select a value from the drop-down list to specify the number of rows displayed per page.

To delete a configuration, place the cursor over the row and click the delete icon displayed on the right side of the table.

To add a new configuration, click the + Add notification button. The following parameters are displayed:

  • Enabled: Select this option to send notifications when the configured conditions are met.
  • Disabled: Select this option to prevent notifications from being sent, even if the fields are configured.
  • Name: Enter a name for the notification template.
  • Event: Select the provisioning event that will trigger a notification. The available options are:
    • Created: Select this option to send a notification every time a user account is created. When selected, the following fields are displayed:
      • Every successful creation: Select this option to send a notification every time a user account is successfully created.
      • Custom condition: Select this option to configure a custom condition for sending notifications. When selected, the following field is displayed:
        • Custom condition:
    • Updated: Select this option to send a notification when a user account is updated. When selected, the following fields are displayed:
      • Any attribute changes: Select this option to send a notification whenever any user attribute changes.
      • Specific attributes change: Select this option to send a notification when specific user attributes change. When selected, the following field is displayed:
        • Selected attributes: Select the attributes for which changes should trigger a notification.
      • Custom condition: Select this option if you want to set a custom condition for notifications. When selected, the following field is displayed:
        • Custom condition:
    • Deactivated: Select this option to send a notification when a user account is deactivated. When selected, the following fields are displayed:
      • Every successful deactivation: Select this option to send a notification every time a user account is successfully deactivated.
      • Custom condition: Select this option to configure a custom condition for sending notifications. When selected, the following field is displayed:
        • Custom condition:
    • Rehire: Select this option to send a notification when a user is rehired. When selected, the following fields are displayed:
      • Every successful rehire: Select this option to send a notification every time a user is successfully rehired.
      • Custom condition: Select this option to configure a custom condition for sending notifications. When selected, the following field is displayed:
        • Custom condition:
  • Resource type:
  • Channel: Select the channel to be used for sending notifications. The available options are:
    • Email: Select this option if you want to send notification through email.
  • Custom rule for who receives the notification (application & event): Define the custom rule that decides whether this notification should be sent for the current application and event. Use filters or expressions to validate recipients or conditions.
    This field uses Aquera Intelligence (AI Assistant). For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.

  • Body: Enter the content to be used as the notification body.

    To add another configuration, click the + icon which is located at top right corner of the page .

Writeback

The Writeback tab allows you to synchronize data from the target application back to the source application. This ensures that changes made in the target application are reflected in the source application.
 
Note: Currently, this tab is tested and certified only with ADP Workforce Now v31 and Dayforce v30. 

Setup

The Setup section enables you to configure writeback for the integration.

  • Enable Writeback: Select this checkbox to enable writeback for this integration. When enabled, the Attribute Mapper section is displayed, allowing you to map the attributes that will be written back from the target application to the source application.
  • Use Expression for Writeback Update Condition: Select this checkbox to configure a JavaScript expression that determines which records are eligible for writeback.
    • Writeback Expression: Enter a JavaScript expression to specify the condition that determines whether a user's data can be written back to the source HR application.
      The following is the sample value:
      SOURCE.department == "Engineering" && SOURCE.userAccountControl != 514
  • Writeback Condition: Select the condition that determines which users are included in the writeback process. The following options are available:
    • All Users: When selected, writes back data for all users in the HR system.
    • All Active Users: When selected, writes back data only for active users in the HR system.

Attribute Map

The Attribute Map page displays the default mapping used to write data from Okta user attributes to employee attributes.

Perform the following steps to add a new mapping from an Okta attribute to an employee attribute:

  1. Click Add Row at the end of the attribute mapping list.

  2. Click on the empty field on the source side to include a user attribute. The list of directory user attributes appears, categorized into Suggested Attributes and Other Attributes. The Suggested Attributes category contains the user attributes that most closely match the selected employee attribute. Depending on the employee attribute, the list of Suggested Attributes changes. Select an attribute from the dropdown list to add it as the user attribute. 

    You can even write a JavaScript expression in the source field. Click the Enter Expression option available at the end of the user attributes list to write the expression. The expression is evaluated at runtime, and the resulting value is assigned to the corresponding employee attribute.
    Note: Click the icon to expand the Expression editor area to write longer expressions.
     

  3. In the Attribute field on the target side, select the employee attribute name from the drop-down list.
  4. Select the data type of the employee attribute from the dropdown list.
  5. Select one of the following mapping options:
    • Map on Create and Update: The employee attribute will be updated during the create and update operations.
    • Map on Update: The employee attribute will be updated only during the update operation.
    • Don't Map: The employee attribute will never be updated and the mapping will be ignored during the integration runs.
  6. Finally, click the check mark to add the new mapping to the attribute map.

Preview Employee Data

You can preview the attribute values of an employee that will be updated in ADP Workforce based on your mappings.

To preview the attribute values of an employee, perform the following steps:

  1. Click the Enter objects for preview field at the top of the Attribute Map page. A pop-up window is displayed.
  2. Select id or userName, and enter the corresponding user ID or username of the user.
  3. Click Preview. The employee data are displayed corresponding to each mapping provided on the Attribute Mapper.
