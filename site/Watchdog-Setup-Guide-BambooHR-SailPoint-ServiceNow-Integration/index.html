Watchdog Setup Guide: BambooHR / SailPoint / ServiceNow Integration

← Back to index

Overview

Aquera Watchdog is a monitoring and validation tool designed to identify data synchronization issues between integrated applications. It operates independently of the Aquera integration and analyzes application events to detect inconsistencies between source and target systems.

After an integration execution is completed, you can run the Watchdog to retrieve the event logs, analyze the activities, and report any anomalies or data discrepancies across the applications. For example, if a user is created in the source application, Watchdog checks for a corresponding user provisioning event in the target application and reports an anomaly if no matching event is found. Aquera Watchdog helps ensure guaranteed delivery of events across integrated systems by continuously monitoring and validating data synchronization between the source and target applications.

When you run the integration Watchdog, a dashboard is generated with a consolidated view of the activities across the systems, including any detected anomalies. The dashboard can be accessed through the Insights module. Refer to the Watchdog Insights section for the details captured in the dashboard.

Watchdog ensures data consistency across systems, provides visibility into sync failures, and helps proactively identify and resolve integration issues. 

This guide provides details on how to configure and run the Watchdog for the integration that synchronizes employee data from BambooHR to user accounts in SailPoint Identity Security Cloud. It also covers the Watchdog settings used to monitor ServiceNow tickets created for employee lifecycle events (new employee onboarding, employee changes and transfers, and employee terminations) in BambooHR.

Prerequisites

The following are the prerequisites:

  • Tenant Account in the Aquera Admin Portal: You must have a tenant account with admin access in the Aquera Admin Portal. Visit https://admin.aquera.io to register for a tenant account. Contact your Aquera account manager to get the Aquera tenant access. 
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/
  • Configure Application Connectors in the Aquera Admin Portal: You must configure the following application connectors in the Aquera Admin Portal to connect to those applications for retrieving the event logs:
    • BambooHR: Ensure you add and configure the BambooHR connector in the Aquera Admin portal. Refer to the BambooHR Configuration Guide for details.
    • SailPoint Identity Security Cloud: Ensure you add and configure the SailPoint Identity Security Cloud connector in the Aquera Admin portal. Refer to the  SailPoint Identity Security Cloud Configuration Guide for details.
    • ServiceNow: Ensure you add and configure the ServiceNow connector in the Aquera Admin portal. Refer to the ServiceNow Configuration Guide for details.

Watchdog Setup

This section describes how to configure the Watchdog that monitors the user sync from BambooHR to SailPoint and the corresponding JML ticket creations in ServiceNow.

Create Integration Watchdog

Follow these steps to create the integration watchdog:

  1. Log in to the Aquera Admin Portal.

  2. In the left panel, go to Integrations.

  3. Click Create Integration.

  4. Select BambooHR / SailPoint Identity Security Cloud / ServiceNow [Watchdog].

  5. Enter a name and description for the integration.

  6. Choose your BambooHR, SailPoint Identity Security Cloud, and ServiceNow connector instances.

  7. Click Continue to open the Configuration page.

Configuration

The following sections are displayed under the Configuration tab:

Applications

The Applications section displays the BambooHR, SailPoint Identity Security Cloud, and ServiceNow connectors that you have selected while creating the integration watchdog. This section enables you to search and select a different instance of the application connectors, if required.

Parameters

The Parameters section enables you to customize the Watchdog settings according to your use case. It has the following settings:

  • BambooHR employee match attribute: Select the BambooHR employee attribute that must be used to uniquely identify an employee record and match with a SailPoint Identity Security Cloud user record.
  • SailPoint Identity Security Cloud user match attribute: Select the corresponding SailPoint Identity Security Cloud user attribute that is used to match against the selected BambooHR attribute to identify the correct SailPoint Identity Security Cloud user record.
  • Initial log lookback period: Specify the time period from which the watchdog retrieves historical logs from BambooHR and SailPoint Identity Security Cloud during its initial execution. After the first run, the watchdog processes only the event logs that have been created since the last run. These logs are used by Watchdog to compare and analyze the events across both systems. The following options are available:
    • Last: Select this option to retrieve logs from a specific duration in the past. You can specify the number of days, hours, or minutes for which logs should be retrieved.
    • Since the date: Select this option to retrieve and process logs starting from a specific date. A calendar field is displayed to select the date.
    • From the beginning of available logs: Select this option to retrieve all logs currently available in BambooHR and SailPoint Identity Security Cloud.

Policy

The Policy tab enables you to define and manage the access policies that Watchdog uses to validate user access in SailPoint Identity Security Cloud. 

When the Watchdog runs, these policies are evaluated to identify deviations and potential access violations. These policies serve as the basis for auditing user access and detecting compliance issues. Based on the evaluation results, Watchdog generates Audit dashboards and reports that help administrators review and analyze access compliance across the connected systems. Refer to the Watchdog: Audit Dashboard Guide for details on Audit dashboard.

Access Policy

The Access Policy section enables you to define policies that specify the roles and access profiles users are expected to have or must not have in SailPoint Identity Security Cloud, as well as whether they should have access to the directory.

Role Policy

Turn on the Enable toggle to enable role policy evaluation.

When Watchdog evaluates the policy, SailPoint Identity Security Cloud users whose role assignments do not comply with the configured rules are reported as policy violations.

The following sections are displayed.

Required Roles

Use this section to define the roles that users are expected to be assigned in SailPoint Identity Security Cloud based on specified conditions. Users who meet these conditions are expected to have the configured roles assigned.

  1. Turn on the Enable toggle to configure the access policies for required roles.
  2. Click on Choose Attribute to select a user attribute from the BambooHR application that you want to use in the condition.
  3. After selecting the attribute, specify one or more attribute values. Users who match any of the selected attribute values (OR operation) are considered eligible for the role.
  4. If required, add more attributes and values. When multiple attributes are added within the same row, those attribute conditions are evaluated using an AND operation. This means users who satisfy all attribute conditions in that row must be assigned the corresponding role.
  5. In the Roles field, select the roles to which users matching the defined conditions should be assigned.
  6. If required, click Add Row to add another condition within the same rule. 

  7. If required, click the + icon at the top-right corner of the rule setting section to add another rule with a set of rows/conditions for required roles. 

    When multiple rules are set, the integration evaluates every rule for each user.

Forbidden Roles

Use this section to define the roles that users must not be assigned in SailPoint Identity Security Cloud based on specified conditions.

The policy setup is similar to the Required Roles procedure.

Access Profile Policy

The Access Profile Policy section enables you to define access policies that specify the access profiles users are expected to have or must not have in SailPoint Identity Security Cloud. During policy evaluation, Watchdog verifies whether users have the appropriate access profile assignments based on the configured policies and identifies users whose assigned access profiles do not comply with the defined requirements.

Turn on the Enable toggle to enable access profile policy evaluation.

The Access Profile Policy section consists of the following subsections:

  • Required Access Profiles
  • Forbidden Access Profiles
Required Access Profiles

Use this section to define the access profiles that users are expected to be assigned in SailPoint Identity Security Cloud based on specified conditions.

  1. Turn on the Enable toggle to configure the policies for required access profiles.
  2. Click on Choose Attribute to select a user attribute from the BambooHR application that you want to use in the condition.
  3. After selecting the attribute, specify one or more attribute values. Users who match any of the selected attribute values (OR operation) are considered eligible for the access profile.
  4. If required, add more attributes and values. When multiple attributes are added within the same row, those attribute conditions are evaluated using an AND operation. This means users who satisfy all attribute conditions in that row must have the corresponding access profile.
  5. In the Access Profiles field, select the SailPoint Identity Security Cloud access profiles that users matching the configured conditions are expected to have.
  6. If required, click Add Row to add another condition within the same rule. 

  7. If required, click the + icon at the top-right corner of the rule setting section to add another rule with a set of rows/conditions for the required access profiles. 

    When multiple rules are set, the integration evaluates every rule for each user.

Forbidden Access Profiles

Use this section to define the access profiles that users must not be assigned in SailPoint Identity Security Cloud based on specified conditions.

Turn on the Enable toggle to configure the forbidden access profile policies.

The policy configuration process is the same as that described in the Required Access Profiles section.

Directory Access Policy

Turn on the Enable toggle to configure the directory access policies. 

You can set the conditions that define which users should and should not have access to the directory.

When you configure the policy, you must select Yes or No in the Can Access? field that indicates whether the user satisfying the condition must get access to the directory or not. During policy evaluation, Watchdog compares the configured policy with the actual directory access of the users and reports any deviations as policy violations.

Attribute Policy

The Attribute Policy section enables you to select the attributes for which you want to see the values in the Insights dashboard. Only the user attributes that are selected will be displayed in Insights logs.

ITSM

The ITSM tab enables you to set the configurations for monitoring the ServiceNow ticket creations for the employee lifecycle events such as new employee onboarding, employee changes and transfers, and employee terminations. You can also specify the correlation attributes used to match BambooHR employee records with their corresponding ITSM tickets, enabling Watchdog to validate ticket creation and identify any discrepancies.

Application Configurations

This section contains the ServiceNow-related settings required for Watchdog monitoring.

  • Enable ITSM Monitoring: Turn on the toggle to retrieve the logs from ServiceNow to monitor the JML ticketing events. The configuration fields are displayed.
  • Common catalog used for user lifecycle events: Turn on this toggle if a single ServiceNow catalog is used for tracking Joiner, Mover (profile updates, department changes, and so on), and Leaver requests. If separate catalogs are used for each request, then turn off the toggle. The remaining fields in this section vary based on this selection.
    • When Toggle is disabled:
      • Joiner catalog type: Select the ServiceNow catalog used to create Joiner requests. Watchdog uses this catalog to identify and retrieve relevant Joiner tickets. 
      • Mover catalog type: Select the ServiceNow catalog used to create employee profile change requests. Watchdog uses this catalog to identify and retrieve relevant Mover tickets. 
      • Leaver catalog type: Select the ServiceNow catalog used to create employee termination requests. Watchdog uses this catalog to identify and retrieve relevant termination tickets. 
    • When Toggle is enabled:
      • Catalog type: Select the common ServiceNow catalog that is used to create Joiner, Mover, and Leaver requests. Watchdog uses this catalog to identify and retrieve relevant Joiner, Mover, and Leaver tickets. 
      • Lifecycle event classification attribute: Select the attribute in the ITSM ticket that indicates the type of the employee lifecycle event (Joiner, Mover, or Leaver). Watchdog reads this field to determine how each ticket should be classified.
      • Joiner value: Enter the value of the Lifecycle event classification attribute that represents a new employee onboarding event.
      • Mover value: Enter the value of the Lifecycle event classification attribute that represents an employee transfer or change event.
      • Leaver value: Enter the value of the Lifecycle event classification attribute that represents an employee termination event.
  • BambooHR employee match attribute: Select the attribute that can be used to uniquely identify an employee in BambooHR.
  • ServiceNow attribute to find the matching ticket: Select the corresponding field in the ServiceNow catalog that stores the unique employee identifier. Watchdog matches this field against the BambooHR employee match attribute to identify the tickets generated for the employee events.

Schedule

The integration Watchdog can be scheduled to run automatically based on your choice of timeframe. Refer to Integration Schedule Setup Guide for further details. 

Watchdog Insights

This section details the data covered in the dashboard created by the Watchdog for the BambooHR / SailPoint Identity Security Cloud / ServiceNow integration. 

  1. Log in to the Aquera Admin portal.
  2. Navigate to Insights.
  3. Click on the integration watchdog name, for example, BambooHR / SailPoint Identity Security Cloud / ServiceNow Watchdog. The dashboards are displayed.

The dashboard provides a comprehensive view of employee events and their synchronization across BambooHR and SailPoint. It includes the following insights:

  • Displays the count of Joiner, Mover, and Leaver events in BambooHR, along with corresponding user creations, updates, and deactivations in SailPoint Identity Security Cloud. This helps identify any discrepancies in user data between the two systems.
  • A checklist that verifies whether a corresponding SailPoint Identity Security Cloud user record has been created for each employee added in BambooHR.
  • A timeline view illustrating an employee's journey, from hiring in BambooHR to account creation in SailPoint Identity Security Cloud, and from termination to account deactivation.
  • A dashboard showing the upcoming hires and terminations, categorized by departments
  • A trend graph that provides visibility into synchronization patterns or gaps between HR and directory events.
  • A geographical map showing the number of SailPoint user logins across various locations.
  • A list of SailPoint applications with the highest number of user logins.
  • The list of users who have been inactive for a long time.
  • A trend graph showing the most frequently accessed applications over a period of time.
  • A pie chart showing the percentage distribution of employees across different departments.
  • A horizontal bar chart showing the distribution of employees across various managers.
  • Insights into workforce distribution by geographic location, and by department and country.
  • A line chart illustrating hiring trends compared to employee terminations over time.
  • Detailed logs of events in the BambooHR application and the SailPoint directory.

ITSM Dashboards Created by Watchdog

This ITSM Dashboard generated by Watchdog provides a consolidated view of ITSM ticket activity generated for employee lifecycle events. It enables administrators to monitor the creation, processing, and status of Joiner, Mover, and Leaver (JML) tickets and verify that ITSM operations are being executed successfully.

This section explains the details available in the dashboards and provides some sample dashboards.

The ITSM dashboard includes the following details:

  • The total number of ITSM events processed during the selected time period.
  • The total number and percentage of tickets created for employee onboarding events.
  • The total number and percentage of tickets created for employee role, department, or organizational changes.
  • The total number and percentage of tickets created for employee offboarding or account deactivation
  • The success rate of the ITSM operations, which is the percentage of ITSM operations that completed successfully
  • The distribution of ITSM operations based on the action (Create/Update/Deactivate) performed
  • The number of tickets grouped by their current state
  • The number of ticket lifecycle events grouped by department
  • The number of tickets created for each Service Catalog or request type configured in the ITSM application.
  • The most recent ITSM lifecycle events and the corresponding service desk tickets generated for user lifecycle and provisioning activities.
