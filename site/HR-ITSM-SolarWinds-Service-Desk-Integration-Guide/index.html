Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

This integration automates identity-driven IT service management workflows by connecting your HR system with SolarWinds Service Desk. The integration retrieves workforce data from the selected HR application, detects employee lifecycle events based on the configured lifecycle rules, and automatically creates SolarWinds Service Desk tickets for the configured lifecycle events.

The integration supports configurable ticket creation for employee lifecycle events, such as new hires and terminations. It also allows you to control when tickets are created, map employee information to SolarWinds Service Desk ticket fields, and customize how employees are matched between the HR system and SolarWinds Service Desk.

Key Fuctions

This integration automates SolarWinds Service Desk ticket creation for employee lifecycle events with the following primary capabilities:

  • Retrieves workforce data from the configured HR application.
  • Detects employee lifecycle events based on configured rules.
  • Creates SolarWinds Service Desk tickets for selected employee lifecycle events.
  • Allows custom employee matching between the HR application and SolarWinds Service Desk.
  • Maps HR attributes to SolarWinds Service Desk ticket fields.
  • Supports configurable rules to determine when SolarWinds Service Desk tickets are created for employee lifecycle events.
  • Sends event notifications through email.
  • Generates detailed logs, operational reports, and execution summaries.

Integration Setup

This section explains how to configure the integration to synchronize employee lifecycle events from an HR application with SolarWinds and automatically create tickets for the configured lifecycle events.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for HR / ITSM - SolarWinds in the search box next to the Explore Templates section and click it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Source
  • Service Desk

Overview

The Overview tab displays general information about the integration, including its purpose and supported capabilities. It provides a high-level overview of how the integration automates ticket creation for employee lifecycle events.

Source

The Source tab allows you to select the HR application used by the integration and define which employees are considered for SolarWinds ticket creation.

The following sections are available on this tab:

  • Application Settings
  • Filter Employees
  • Filter Candidates

Application Settings

The Application Settings section allows you to identify the HR application instance used by the integration. The following field is available in this section for configuration:

  • HR application instance: Select the HR application connector from which employee data and lifecycle events will be retrieved for this integration. If the required connector is not available in the list, click the refresh icon next to the field to reload the available connectors.
    Note: Currently, this integration supports ADP Workforce Now as the source HR application.

Filter Employees

This section allows you to define which employees from the HR application are considered for SolarWinds ticket creation. The following field is available in this section for configuration:

  • Enable employee filter: Turn on this toggle button to filter employees considered for SolarWinds ticket creation. Only employees who match the configured filter criteria are processed. When enabled, the Employee Filter Configuration section is displayed for further configuration.

Employee Filter Configuration

This section allows you to configure the criteria used to filter employees from the HR application for SolarWinds Service Desk ticket creation.

The following fields are displayed for configuration:

  • Use filter for new hires: Turn on this toggle button to filter new hires from the HR application. Only new hires who match the filter criteria are considered for SolarWinds Service Desk ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the HR application. The following is the available option:
      Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
      • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Hire Date.
  • Use filter for account changes: Turn on this toggle button to filter users from the HR application.  Only users who match the defined rules are considered for SolarWinds Service Desk ticket creation. When enabled, the following fields are displayed for further configuration:
    • Select Attributes to Synchronize: Select the user profile attributes to synchronize from the source system to the target system. If you do not find your attribute in the list, click the refresh icon available next to the field to reload the available attributes.
  • Use filter for terminated employees: Turn on this toggle button to filter terminated employees from the HR application. Only terminated employees who match the filter criteria are considered for SolarWinds Service Desk ticket creation.
    When enabled, the following fields are available for configuration:
    • Employee filter criteria: Select the method used to filter terminated employees from the HR application. The following is the available option:
      Based on date: Select this to filter terminated employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
      • Date attribute to filter employees: Select the date attribute used to filter terminated employees from the HR application. For example, Termination Date.
  • Use filter for employees on leave: Enable this option to create or update a ticket when an employee is on the selected leave types. When enabled, the following field is displayed for further configuration:
    • Leave types for ticket creation: Select the leave types that trigger ticket creation or updates. For example, select Medical. If you do not find your leave type in the list, click the refresh icon available next to the field to reload the leave types.
  • Use filter for rehires: Turn on this toggle button to filter rehires from the HR application. Only rehires who match the filter criteria are considered for SolarWinds Service Desk ticket creation. When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the HR application. The following is the available option:
      Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
      • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Rehire Date.

Filter Candidates

The Filter Candidates section allows you to configure how candidate lifecycle events are processed by the integration. The following field is available in this section for configuration:

  • Enable candidate filter: Turn on this toggle button to filter candidates from the source system. Only candidates who match the filter criteria are considered for SolarWinds Service Desk ticket creation. When enabled, the Candidate Filter Configuration section is displayed for further configuration.

Candidate Filter Configuration

This section allows you to configure the criteria used to filter candidates from the source system for SolarWinds Service Desk ticket creation.

The following fields are displayed for configuration:

  • Use filter for candidates: Turn on this toggle button to apply custom filter rules and controls for candidates that trigger account creation in the SolarWinds Service Desk ticket creation. When enabled, the following fields are displayed for further configuration.
    • Candidate filter criteria: Select the method used to filter employees from the source system. The following is the available option:
      • Based on status: Select this to filter candidates using a status from the source system. Only matching employees are considered for ticket creation.
    • Status to filter candidates: Select the candidate statuses that trigger account creation in the SolarWinds Service Desk ticket creation.

Service Desk

The Service Desk tab enables you to configure the SolarWinds Service Desk application, where employee lifecycle tickets are created and managed. It allows you to select the SolarWinds Service Desk instance, define which lifecycle events create tickets, configure ticket settings, and map HR attributes to SolarWinds Service Desk ticket fields.

The following sections are displayed in this tab:

  • Channel
  • JML Ticket Creation

Channel

This section enables you to identify the SolarWinds Service Desk application used by the integration to create tickets. The following field is available in this section for configuration:

  • Enable target application selection: Enable this option to select the service desk application. When enabled, the ITSM Configuration section is displayed for further configuration.
  • Enable messaging: Enable this option to allow the integration to send messages and notifications through the configured messaging channel. When enabled, the Messaging Applications section is displayed for further configuration.

ITSM Configuration

The ITSM Configuration section allows you to identify the service desk application instance used by the integration.

  • Service desk application instance: Select the SolarWinds Service Desk application connector where the integration will create tickets. If the required connector is not available in the list, click the refresh icon next to the field to reload the configured application connectors.

Messaging Applications

The Messaging Applications section allows you to configure the messaging application instances used by the integration to send notifications.

  • Enable Slack notifications: Enable this option to send Slack notifications when the configured lifecycle event is detected. When enabled, additional Slack notification settings are displayed: 
    • Slack application instance: Select the Slack application instance configured in Aquera to send lifecycle event notifications. If the required connector is not available in the list, click the refresh icon next to the field to reload the configured application connectors.
  • Enable Microsoft Teams notifications: Enable this option to send Microsoft Teams notifications when the configured lifecycle event is detected. When enabled, additional Teams notification settings are displayed: 
    • Microsoft Teams application instance: Select the Microsoft Teams application instance configured in Aquera to send lifecycle event notifications. If the required connector is not available in the list, click the refresh icon next to the field to reload the configured application connectors.

JML Ticket Creation

This section enables you to configure how SolarWinds Service Desk tickets are created for employee lifecycle events. The following field is displayed in this section:

  • Enable ticket creation: Turn on this toggle button to automatically create SolarWinds Service Desk tickets for employee lifecycle events. When enabled, the Ticket Creation Configuration section is displayed for configuration.

Ticket Creation Configuration

This section allows you to configure how SolarWinds Service Desk tickets are created for a selected employee lifecycle event.

  • Select event type: Select the employee lifecycle event for which SolarWinds Service Desk tickets should be created. The following lifecycle events are available for selection:
    • Hire: Select this option if you want to create SolarWinds Service Desk tickets when a new hire event is detected.
    • Change: Select this option if you want to create SolarWinds Service Desk tickets when a change event is detected.
    • Leave: Select this option if you want to create SolarWinds Service Desk tickets when a Leave event is detected.
    • Terminate: Select this option if you want to create SolarWinds Service Desk tickets when a Terminate event is detected.
    • Rehire: Select this option if you want to create SolarWinds Service Desk tickets when a rehire event is detected.
    • Prehire: Select this option if you want to create SolarWinds Service Desk tickets when a prehire event is detected.
      • Select change events: Select the employee changes that should create a SolarWinds Service Desk ticket, for example change in Department or Location. By default, it uses the attributes selected in Select attributes to synchronize in the filter employees section. If multiple selected changes have the same effective date, they are grouped into a single SolarWinds Service Desk ticket.
        Note: This option appears only when the event type is selected to Change.
  • Event timing: Define when the SolarWinds Service Desk ticket should be created for the selected lifecycle event. The following are the available options:
    • When detected: Select this if you want to create tickets immediately after the lifecycle event is detected.
    • Before start date: Select this if you want to create tickets before the actual start date of the employee.
    • On start date: Select this if you want to create tickets on the employee's start date.
    • After start date: Select this if you want to create tickets after the actual start date of the employee.
      When you select Before start date or After start date, the following field is displayed to define the number of days:
      • Days Before / After Joining Date: Enter the number of days before or after the selected lifecycle event date when the ticket should be created. For example, entering 7 with Before start date selected creates the ticket seven days before the employee's effective start date.
    • Enable conditional event detection: Turn on this toggle button to create SolarWinds Service Desk tickets only for employees who satisfy a defined condition. When enabled, the following field is displayed:
      • Ticket creation condition: Enter a condition to control which employees trigger SolarWinds Service Desk creation. Only employees who satisfy this condition are considered for ticket creation. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.
    • Enable ticket creation: Turn on this toggle button to create SolarWinds Service Desk tickets for the selected lifecycle event. When enabled, the following fields are displayed for further configuration:
      • Ticket type: Select the type of ticket to create in SolarWinds Service Desk. Select Ticket to create a standard support ticket, or Select Service Request to create a request based on a service catalog item.
      • Customize how users are matched across systems: Turn on this toggle button to configure custom employee matching. When enabled, the following fields are displayed.
        • Select How Employees Are Matched Between Source and Target: Select the method used to correlate employees between the HR application and SolarWinds Service Desk.
        • Select Source Attribute for Matching the Employee: Select the HR application attribute used to uniquely identify employees.
        • Select Target Attribute for Matching the Employee: Select the SolarWinds Service Desk field used to uniquely identify employees.
      • Allow auto update the ticket: Turn on the toggle button to automatically update SolarWinds Service Desk JML tickets only when their current status matches one of the selected ticket statuses. When enabled, the following field is displayed:
        • Ticket statuses to evaluate for auto update: Select the SolarWinds Service Desk ticket statuses that should be evaluated to determine whether a ticket is eligible for automatic updates. If you do not find your ticket status in the list, click the refresh icon available next to the field to reload the available ticket statuses.
      • Auto close the ticket: Enable this option to automatically close the SolarWinds Service Desk JML ticket after all actions associated with the user lifecycle event have been completed successfully. When enabled, additional configuration options are displayed:
        • Ticket status to evaluate for auto close: Select the SolarWinds Service Desk ticket statuses that should be evaluated to determine whether a ticket is eligible for automatic closure. If you do not find your ticket status in the list, click the refresh icon available next to the field to reload the available ticket statuses.
        • Ticket close status: Select the SolarWinds Service Desk ticket status to apply when the integration automatically closes the ticket.
    • Onboarding ticket field mapper: This section allows you to map HR attributes to SolarWinds Service Desk ticket fields. Source attributes are displayed on the left side, and SolarWinds Service Desk ticket fields are displayed on the right side of the page. You can modify only the source attributes as needed, to align with your specific use case. JavaScript expressions can be used to transform source attribute values and construct the values that are updated in the target attributes. You can enter the expression directly in the source attribute field or click the expand icon to write a longer expression. The Search Attributes field allows you to search for source attributes.
      Attributes marked with a red asterisk (*) are mandatory for successful execution.
      After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the configuration.
    • Send ticket creation request by email: Enable this option to send an email request with employee lifecycle event details to the configured recipients. Recipients can use the email to create the required ticket in the service desk application. When enabled, additional configuration options are displayed:
      • Ticket creation email subject: Enter the content that must be used as the email subject in the notifications sent for ticket creation.
      • Ticket creation email recipients: Select one or more recipient groups to whom the email notifications will be sent for ticket creation.
      • Ticket creation email template: Enter the content that must be used as the email body in the notifications sent for ticket creation.
    • Send ticket creation request by Slack: Enable this option to send a Slack message with employee lifecycle event details to the configured channel. When enabled, additional Slack settings are displayed: 
      • Select channel: Select the Slack channel within the selected team where ticket creation notifications will be posted. If you do not find your channel in the list, click the refresh icon available next to the field to reload the available channels.
      • Slack notification template: Enter the content that must be used as the notification message sent for ticket creation.
    • Send ticket creation request by Microsoft Teams: Enable this option to send a Microsoft Teams message with employee lifecycle event details to the configured team. When enabled, additional Teams notification settings are displayed: 
      • Select team: Select the Microsoft Teams team where ticket creation notifications will be posted. If you do not find your team in the list, click the refresh icon available next to the field to reload the available teams.
      • Select channel: Select the Microsoft Teams channel within the selected team where ticket creation notifications will be posted. If you do not find your channel in the list, click the refresh icon available next to the field to reload the available channels.
      • Teams notification template: Enter the content that must be used as the notification message sent for ticket creation.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the Ticket field mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the ticket field mapper, if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.
