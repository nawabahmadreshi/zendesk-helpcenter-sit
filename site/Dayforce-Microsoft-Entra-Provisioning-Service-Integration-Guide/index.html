Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.
This integration automates the synchronization of worker data from Dayforce to the target directory configured through the Microsoft Entra Provisioning Service connector. Depending on the enterprise application configuration in Microsoft Entra ID, the target directory can be Microsoft Entra ID (cloud) or on-premises Active Directory configured through the Microsoft Entra ID API-driven provisioning application. The integration automatically creates user accounts during onboarding, updates accounts when worker information changes, and deactivates accounts when workers leave the organization. 

Key Functions

This integration keeps accounts in the target directory synchronized with worker records in Dayforce throughout the employee lifecycle. The target directory can be Microsoft Entra ID or on-premises Active Directory, depending on how the enterprise application is configured in Microsoft Entra ID. The integration provides the following capabilities:

  • Synchronizes worker data from Dayforce to the configured target directory on a scheduled full and incremental basis.
  • Creates user accounts automatically in the target directory when new workers are onboarded in Dayforce.
  • Updates account attributes in the target directory when corresponding worker details change in Dayforce.
  • Deactivates accounts in the target directory when workers are terminated in Dayforce.
  • Maps Dayforce worker attributes to target directory account fields through a configurable Attribute Mapper.
  • Scopes integration runs to specific workers using source filters, supporting staged rollouts and testing.
  • Previews the impact of configuration changes using report-only mode before applying updates to the target directory.
  • Sends configurable email notifications for provisioning events, including account creation, updates, and integration success or failure.
  • Captures detailed, configurable logs and generates operational reports for troubleshooting and audit purposes.

Prerequisites

The following are the prerequisites:

  • Tenant Account in the Aquera Admin Portal: You must have a tenant account with admin access in the Aquera Admin Portal. Visit https://admin.aquera.io to register for a tenant account. Contact your Aquera account manager to get Aquera tenant access.
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/.
  • Configure Application Connectors in the Aquera Admin Portal: You need to configure the following application connectors in the Aquera Admin portal:
    • Dayforce: Ensure that you configure the Dayforce connector in the Aquera Admin portal. Refer to the Dayforce Configuration Guide for details.
    • Microsoft Entra Provisioning Service: Ensure that you add and configure the Microsoft Entra Provisioning Service connector in the Aquera Admin portal. Refer to the Microsoft Entra Provisioning Service Configuration Guide for details.

Integration Setup

This section details the configuration and mapping process for integrating Dayforce with the target directory via the Microsoft Entra Provisioning Service connector. It outlines the steps to create the integration, set up integration preferences, and define how worker data is mapped from Dayforce to the target directory (Microsoft Entra ID or on-premises Active Directory).

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left-side panel.
  3. Click Create Integration.
  4. Search for Dayforce / Microsoft Entra Provisioning Service in the search box next to the Explore Templates section, and select it. The Create New Integration pop-up window appears.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Dayforce
  • Entra ID
  • Operations
  • Notification
  • Tables
  • Schedule

Overview

The Overview tab displays general information about the integration, including its purpose and supported capabilities. It provides a high-level overview of how the integration synchronizes employee lifecycle events from Dayforce to the target directory—Microsoft Entra ID or on-premises Active Directory—to automate user account provisioning, updates, and offboarding.

Dayforce

The Dayforce tab enables you to set the application connector that must be used to retrieve worker data from Dayforce.

Source Application

Configure the following source application setting:

  • Select Dayforce application instance: Select the Dayforce connector instance that must be used by the integration to retrieve worker data.

Entra ID

The Entra ID tab enables you to configure the target Microsoft Entra Provisioning Service connector, the data synchronization schedule, and the attribute mapping between Dayforce and the target directory (Microsoft Entra ID or on-premises Active Directory).

The following sections are displayed in this tab:

  • Application Settings
  • Attribute Mapping

Application Settings

Configure the following target application and data synchronization settings:

Target Application

Configure the following target application settings:

  • Select Entra ID instance: Select the Microsoft Entra Provisioning Service connector instance that the integration will use as the target application.

Data Synchronization Settings

Configure the following data synchronization settings:

  • Enable recurring full sync: Enable this toggle to schedule full synchronization to run repeatedly. If this toggle is disabled, the integration still performs a full synchronization during the initial run. After that, only new or updated records are synchronized. Enable this option when you want full synchronization to run again on a recurring schedule. When this option is enabled, additional scheduling fields are displayed:
    • Full sync schedule: Select how often the integration should run in full synchronization mode. For example, if you select Every 6 hours, one integration run is performed every 6 hours as a full synchronization. If incremental synchronization is enabled, any runs that occur between the scheduled full synchronizations are performed in incremental mode. For example, if a full synchronization runs at 12:00 AM, the next full synchronization runs at 6:00 AM. Any integration runs between 12:00 AM and 6:00 AM use incremental synchronization.
    • Start schedule from: Specify when the recurring full synchronization schedule should begin. The following options are available:
      • Start now: Select this option to start the recurring full sync from the next scheduled run, based on the configured schedule.
      • From specific date: Select this option to start the recurring full sync from a specific date and time. Specify the required values in the Start date and Start time fields.
    • Sync days: Select which day(s) of the week the full synchronization should run. This field is displayed only when Full sync schedule is set to Weekly.
    • Disable incremental sync: Select this checkbox to run the integration only in full synchronization mode and skip incremental synchronization runs. When disabled, the integration runs in both full and incremental synchronization modes based on the configured schedule settings.
  • Reset last full sync timestamp: Enable this toggle to reset the timestamp of the last full synchronization. Use this option when you need the integration to process data again from a specific date and time, such as after a previous synchronization failed or did not complete as expected. When enabled, the following fields are displayed:
    • Reset effective date: Specify the date from which the full synchronization timestamp should be reset.
    • Reset time: Specify the time from which the full synchronization timestamp should be reset.

Attribute Mapping

The Attribute Mapper maps worker attributes from Dayforce (source) to the corresponding target directory attributes (Microsoft Entra ID or on-premises Active Directory) used to create and update accounts. You can modify the source attributes as needed to align with your business requirements.

You can use JavaScript expressions to transform or construct values before mapping them to target attributes. Write the expression directly in the source field or use the expand option to define complex logic.

Attributes marked with a red asterisk (*) are required for successful provisioning.

The Search Attributes field allows you to filter the list of available attributes for mapping.

After completing the source-to-target attribute mapping, click Save Changes at the top-right corner of the page to save the configuration.

Operations

The Operations tab allows you to configure execution, rollout, filtering, logging, and reporting settings for the integration.

The following sections are displayed in this tab:

  • Execution
  • Monitor

Execution

The Execution section allows you to configure how the integration processes data during each run.

RollOut Configurations

Configure the following rollout configurations:

  • Integration start date (UTC): Specify the date from which the integration should begin processing records.
  • Source import limit: Specify the maximum number of source records to process in each integration run.
  • Enable report-only mode: Enable this toggle to generate a report showing the actions the integration would perform without making any changes to the target directory.
  • Turn on detailed logs for troubleshooting: Enable this toggle to capture detailed execution logs for troubleshooting and issue resolution.
  • Enable source filter: Enable this toggle to process only records that match the specified filter criteria. When enabled, the following fields are displayed:
    • Select filter type: Select the source attribute to use for filtering.
    • Filter value: Enter the value for the selected filter attribute.

Monitor

The Monitor section allows you to configure logging and reporting options for the integration.

Logging Settings

The Logging Settings section enables you to configure the level of detail recorded in execution logs. It has the following settings:

  • Log type: Select the log type. This setting determines the level of detail included in the integration log. The following options are available:
    • Minimum: Select this option to include only operation details. No GUIDs or field-level information will be included.
    • Metadata: Select this option to include operation details and field names. GUIDs are excluded.
    • Non-PII Data: Select this option to include operation details, field names, and selected non-PII values. GUIDs are excluded.
    • GUID with Non-PII Data: Select this option to include GUIDs, operation details, field names, and selected non-PII values.
    • Employee Number with Non-PII Data: Select this option to include employee numbers, operation details, field names, and selected non-PII values.
    • Employee Number with All Data: Select this option to include employee numbers, operation details, field names, and all values, including both PII and non-PII data.
  • Log level: Select the level of detail to include in the integration logs. The following options are available:
    • All: Include all attribute details in logs.
    • Include List: Includes only the selected attributes in the integration logs. When selected, the following field appears for further configuration:
      • Log — Custom Inclusion List: Select the attributes to include in the logs.
    • Exclude List: Excludes only the selected attributes from the integration logs. When selected, the following field appears for further configuration:
      • Log — Custom Exclusion List: Select the attributes to exclude from the logs.

Report Settings

  • Report type: Select the report type. This setting determines the level of detail included in the integration report. The following options are available:
    • Minimum: Select this option to include only operation details. No GUIDs or field-level information will be included.
    • Metadata: Select this option to include operation details and field names. GUIDs are excluded.
    • Non-PII Data: Select this option to include operation details, field names, and selected non-PII values. GUIDs are excluded.
    • GUID with Non-PII Data: Select this option to include GUIDs, operation details, field names, and selected non-PII values.
    • Employee Number with Non-PII Data: Select this option to include employee numbers, operation details, field names, and selected non-PII values.
    • Employee Number with All Data: Select this option to include employee numbers, operation details, field names, and all values, including both PII and non-PII data.
  • Reporting level: Select the level of detail to include in the integration report. The following options are available:
    • All: Includes all attribute details in the report.
    • Include List: Includes only the selected attributes in the integration report. When selected, the following field appears for further configuration:
      • Report — Custom Inclusion List: Select the attributes to include in the report.
    • Exclude List: Excludes only the selected attributes from the integration report. When selected, the following field appears for further configuration:
      • Report — Custom Exclusion List: Select the attributes to exclude from the report.

Notification

The Notifications tab enables you to configure notification settings for the integration. The following sections are displayed on the page:

  • Channels
  • Template Library
  • Configuration

Channels

The Channels section allows you to configure how integration notifications are delivered.

  • Enable email notifications: Enable this toggle to receive integration-related notifications by email. When enabled, the Template Library and Configuration sections are displayed for further configuration.

Template Library

The Template Library section enables you to create and manage the notification templates used for integration events.

Perform the following steps to create a notification template:

  1. Click + Add Templates. The Templates screen opens.
  2. Configure the following fields:
    • Name: Enter a unique name to identify the template.
    • Type: Select the notification type from the drop-down menu. The available option is Email.
    • Template: Enter the notification message. To generate the template content using Aquera AI, click the Improve Description icon () and enter a prompt. Aquera AI generates the notification content based on the prompt, which you can review and modify as needed.
  3. To create another template, click the + icon. A new blank Templates screen opens.
  4. Use the Left and Right arrow icons to navigate between the templates you are creating or have already created.
  5. After you finish creating all required templates, return to the previous screen and click Save Changes. The saved templates are displayed in the table under the Templates section.
  6. You can manage existing templates as follows:
    1. Click a template row in the table to open it for editing.
    2. Click the Delete icon on the Templates screen to remove the template.

Configuration

The Configuration section allows you to define notification rules for integration events.

Perform the following steps to create a notification configuration:

  1. Click + Add Define Notification Configuration. The Define Notification Configuration screen opens.
  2. Configure the following fields:
    • Template name: Enter a unique name to identify the notification configuration.
    • Select application: Select the target application where the integration event occurs. If the required application connector is not listed, click the Refresh icon next to the field to reload the available target application connectors.
    • Select event for notification: Select the integration event that triggers the notification. The available options are Account Provisioned, Account Updated, Success, and Failure.
    • Notification delivery channel: Select the notification delivery channel. Currently, only Email is supported as a channel. When selected, the following field appears for further configuration:
      • Send to: Select the notification recipients. The available options are:
        Note: The Success and Failure events represent the overall integration run rather than a specific worker. Notifications for these events are sent only to Admins and the Custom email addresses configured in the Send To field. The User's Work Email option is not applicable for these events. The Account Provisioned and Account Updated events are associated with individual worker records and can be sent to the worker's work email address, custom email addresses, or both.
        • User's Work Email: Sends the notification to the user's work email address associated with the integration event.
        • Custom: Sends the notification to one or more email addresses specified in the Custom email Address field.
      • Subject: Enter the subject line for the email notification.
    • Use existing templates: Select this checkbox to use a previously created notification template. When selected, the Templates field is displayed, allowing you to choose an existing template from the drop-down menu.
    • Template: If you are not using an existing template, enter the notification message. To generate the template content using Aquera AI, click the Improve Description icon () and enter a prompt. Aquera AI generates the notification content based on the prompt, which you can review and modify as needed.
    • Attach Report: Select this checkbox to include the integration report as an attachment in the notification email.
  3. To create another notification configuration, click the + icon. A new blank Define Notification Configuration screen opens.
  4. Use the Left and Right arrow icons to navigate between the configurations you are creating or have already created.
  5. After you finish creating all required configurations, return to the previous screen and click Save Changes. The saved configurations are displayed in the table under the Define Notification Configuration section.
  6. You can manage existing configurations as follows:
    1. Click a configuration row in the table to open it for editing.
    2. Click the Delete icon on the Define Notification Configuration screen to remove the configuration.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the Ticket field mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the ticket field mapper if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.

Update the Integration to the Latest Version

You can upgrade an integration built from a template to the latest version to access new features and enhancements. 

Perform the following steps to upgrade an integration:

  1. Navigate to the Integrations module on the Aquera Admin portal.
  2. Click the vertical ellipsis icon next to an integration and click View Details. The Details panel is displayed with the following sections:
    • INTEGRATION DETAILS: Displays the integration name, description, creation date, last update date, and the user who created or last updated it.
    • TEMPLATE DETAILS: Displays the current version number and its features under CURRENT VERSION. If a newer version is available, the version number and the changes are shown under NEW VERSION AVAILABLE with an Upgrade button.
  3. Click Upgrade. The Upgrade Integration pop-up window is displayed.
  4. Provide the following details for the new integration to be created after the upgrade:
    • New Integration Name: Enter the name of the new integration.
    • Description: Provide a description for the new integration.
      The current version number and the upgraded version number are displayed.
  5. Click Upgrade. A new integration is created with the same configuration details as the existing one, but with features or enhancements from the upgraded version.
