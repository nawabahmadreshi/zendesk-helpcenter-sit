Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

The integration connects a directory application with a service desk application to automate user lifecycle management, access fulfilment, account-expiry processing, ticket updates, and notifications.

Only the records that satisfy the integration settings are retrieved from the configured source application. The integration identifies the required lifecycle event and performs the corresponding action in the target system. Based on the configured rules, it can create, update, reactivate, disable, or delete user accounts, assign organisational units and groups, process access requests, update service desk tickets, and send notifications.

The integration supports configurable matching, conditional processing, attribute mapping, writeback, operational safeguards, reporting, and scheduled execution.

 

NOTE: Currently, the supported source applications are Jira Service Management Cloud and ServiceNow, and the supported target applications are Entra ID and Active Directory.

Key Functions

The Directory / ITSM Integration performs the following functions:

  • Provision, update, reactivate, disable, or delete user accounts based on service desk requests and lifecycle events.
  • Match service desk records with directory users by using default identifiers, custom attributes, or AI-based expressions.
  • Assign users to organizational units based on attributes such as country, department, location, role, and lifecycle event.
  • Assign users to directory groups by using general assignment rules or Active Directory-specific group rules.
  • Process access fulfilment requests to grant or revoke directory groups and other supported entitlements.
  • Identify accounts approaching expiry and send notifications to supervisors or configured recipients.
  • Create and process account-extension tickets and update expiry dates after approval.
  • Create, read, update, transition, and close tickets in the configured service desk application.
  • Write directory-generated values, such as usernames and email addresses, back to service desk tickets.
  • Add comments or transition tickets when provisioning operations fail.
  • Filter records and tickets by using status values, source filters, group types, and custom conditions.
  • Map source attributes to target attributes for user provisioning, ticket creation, access fulfilment, and writeback.
  • Send email, chat, and Microsoft Teams notifications for configured events.
  • Apply operation limits and safeguards to prevent unintended bulk changes.
  • Generate execution logs, reports, and insights for monitoring and troubleshooting.

Prerequisites

The following are the prerequisites:

  • Aquera Tenant Account: You must have a tenant account in the Aquera Admin portal. Visit https://admin.aquera.io to register for a tenant account. Contact your Aquera account manager to get Aquera tenant access.
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/
  • Configure Application Connectors in the Aquera Admin Portal: You need to configure the following application connectors in the Aquera Admin Portal:
    • ITSM connector: You must configure a connector for your ITSM application in the Aquera Admin Portal. Refer to the configuration guide for the respective ITSM application for configuration details. For example, if Jira Service Management Cloud is your ITSM application, refer to the Jira Service Management Cloud Configuration Guide for details.
    • Directory connector: You must configure a connector for your directory application in the Aquera Admin Portal. Refer to the configuration guide for the respective directory application for configuration details. For example, if Active Directory is your directory application, refer to the Active Directory (AD) Configuration Guide for details.

Integration Setup

This section outlines how the integration must be configured to synchronize workforce lifecycle events from an HR application to a service desk application and automate the creation and management of service requests and tickets.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for Directory / ITSM in the search box next to the Explore Templates section and click it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Directory
  • Service Desk
  • Rules
  • Operations
  • Schedule

Overview

On this tab, you can view general information about the integration, including its purpose, functionality, and supported capabilities. This section provides a high-level overview of how the integration operates between connected applications.

Directory

The Directory tab provides an overview of the functional components supported by the integration. These features define the capabilities available within the integration and determine the configuration tabs and settings that are available.

Configuration

This section enables you to specify the directory application and define conditions and rules for it.

  • Enable Directory Configuration: Turn on this toggle button to specify the directory details to which the user must be synchronized. When this toggle button is turned on, the Directory Configuration section is displayed for further configuration.
  • Enable Operations: Turn on this toggle button to configure operational features, notification settings, safeguard limits, source filters, and source import limits. When this toggle button is turned on, the Operations section is displayed for further configuration.
    Turn on this toggle to configure operational features, notification settings, safeguard limits, source filters, and source import limits.
  • Enable Rules: Turn on this toggle button to configure the rules for generating unique email addresses, Common Names (CNs), User Principal Names (UPNs), and Security Account Manager (SAM) account names. You can also define the Organizational Unit (OU) assignment and password policy. When this toggle button is turned on, the Rules section is displayed for further configuration.

Directory Configuration

The Directory Configuration section allows you to configure how user accounts are created, updated, reactivated, disabled, and deleted in the target directory application. It provides settings for selecting the directory application, defining account eligibility, configuring attribute mappings, generating usernames and email addresses, managing passwords, assigning organizational units and groups, and controlling lifecycle actions.

The integration uses these settings when processing user lifecycle events from the configured source system. Based on the selected options, it can provision new accounts, update existing accounts, apply naming and assignment rules, manage account activation and termination, and perform post-provisioning actions in Active Directory or Microsoft Entra ID.

Click Add Directory Configuration to create a new configuration, or select an existing configuration to update it. You can add up to three directory configurations. The following parameters are displayed when you click Add Directory Configuration:

  • Directory Application: Select the directory application from the dropdown menu in which user accounts must be provisioned and managed.
  • Resource Type: Select the type of directory resource that must be managed. For user lifecycle management, select User.
  • Enable Directory Provisioning: Turn on this toggle button to allow the integration to create, update, reactivate, disable, and delete user accounts in the selected directory application.
  • Enable Account Creation: Turn on this toggle button to allow the integration to create a user account when a configured account-creation event is detected.
  • Enable Custom Uniqueness Check: Select this checkbox to check additional identity attributes for duplicate values before creating a user account. By default, the integration checks the username or UPN. When selected, the following parameters are displayed:
    • Attributes to Check for Duplicates: Select one or more directory attributes from the dropdown menu that must be checked for existing values before account creation. For example, you can check the email address, user principal name, and proxy addresses.
    • Action When Duplicate is Detected: Select the action that the integration must perform when an existing account contains a value that matches one of the selected attributes. Depending on the selected option, the integration can block account creation, continue with a warning, or regenerate the configured identity values.
  • Apply Entitlement Assignment Rules: Turn on this toggle button to apply the configured organizational unit and group-assignment rules when a user account is created. When turned off, the configured assignment rules are not applied during account creation.
  • Auto-Generate Username: Select this checkbox to automatically generate usernames for synchronized users based on the policy defined in the Naming section.
  • Automatically Generate Email: Select this checkbox to automatically generate user emails for synchronized users based on the policy defined in the Naming section.
  • Must Change Password on First Logon: Select this checkbox to require the user to change the initial password when signing in for the first time. This option applies to only to Active Directory accounts.
  • Enable Early Account Creation: Select this checkbox to create the directory account before the user’s hire date. When selected, the following parameters are displayed:
    • Hire Date Ticket Field: Select the source ticket field that contains the user’s hire date. The integration uses this date to calculate when the account must be created.
    • Days Before Hire Date: Enter the number of days before the hire date when the account must be created. For example, if the hire date is August 10 and you enter 5, the account is scheduled for creation on August 5.
  • Create Inactive Account: Select this checkbox to create the user account before the hire date but keep it inactive until the configured activation time. When selected, the following parameter is displayed for further configuration:
    • Account Activation Timing: Select when the newly created account must become active in the target directory. The following are the available options:
      • Never: Select this option if you do not want the user account to be activated in the directory.
      • On Joining Day: Select this option if you want the user account to be activated on the user’s joining date.
      • X days Before Joining Date: Select this option if you want to activate the user account a specific number of days before the user’s joining date. When selected, the following parameter is displayed for further configuration:
        • Days to Activate Account: Enter the number of days before the joining date when the user should be activated. For example, if you enter 10 and the user’s joining date is 20th August, the user will be activated on 10th August.
  • Default/Fallback Location: Turn on this toggle button to set the location as the default location for the directory. When turned on, a field is displayed. Select an OU from the dropdown menu in the field that must be used as the default OU.
  • Enable Account Updates: Turn on this toggle button to update existing directory accounts when changes are detected in the corresponding source records. When turned on, the following parameter is displayed for further configuration:
    • Enable Assignment Rules: Turn on this toggle button to apply organizational unit and group-assignment rules during update events. When turned off, the integration updates only the mapped user attributes and does not perform rule-based OU moves or group assignments.
  • Enable Account Termination: Turn on this toggle button to perform the configured deprovisioning actions when a user-termination event is detected. When turned on, the following parameter is displayed for further configuration:
    • Remove all groups for user on termination: Select this checkbox to remove the user from all directory groups as part of the termination process. Group removal is performed before any scheduled account disablement or deletion.
    • Disable Account: Select this checkbox to disable the user account during the termination process.
    • Disable Timing: Select when the account must be disabled. Depending on the available options, the integration can disable the account immediately, disable it after a specified number of days, move it to a disabled-users organizational unit, or perform both disablement and an OU move.
    • Delete Account: Select this checkbox to permanently delete the user account from the target directory.
    • Delete Timing: Select when the user account must be deleted. You can delete the account immediately or after a specified number of days from the termination date.
    • Delete After (Days): Enter the number of days after the termination date when the account must be permanently deleted. This parameter is displayed when a delayed deletion option is selected. For example, if the termination date is August 1 and you enter 30, the account is deleted on August 31. The configured disable and delete timing options take priority over any previously saved immediate-termination setting. 
  • Invalidate Password: Select this checkbox to remove the user's password when the user account is deactivated in the directory.
  • Manage Dormant Accounts: Select this checkbox to detect and process inactive or expiring directory accounts. When selected, the following parameters are displayed for further configuration:
    • Inactive Users: Turn on this toggle button to identify directory accounts that have not been used for the configured number of days. When turned on, the following parameters are displayed for further configuration:
      • Last Active Date Field: Select the directory attribute that contains the date or time when the user account was last active.
      • Inactive Account Action: Select one or more actions that the integration must perform when an account is identified as inactive. Depending on the available options, the integration can notify an administrator or create an extension ticket for review.
      • Inactivity (Days): Enter the number of days without account activity after which the account must be considered inactive. For example, if you enter 90, an account is considered inactive when it has not been used for more than 90 days.
    • Expiring Users: Turn on this toggle button to detect directory accounts whose expiry dates are approaching. When turned on, the following parameters are displayed:
      • Expiry End Date Field: Select the directory attribute that contains the account expiry date.
      • Expiring Account Action: Select one or more actions that the integration must perform for accounts approaching their expiry date. Depending on the available options, the integration can notify an administrator or create an extension ticket.
      • Days Before End Date: Enter the number of days before the account expiry date when the configured action must be triggered. For example, if you enter 60, the integration performs the selected action when the account is within 60 days of its expiry date.

Manage Writeback

The Manage Writeback section allows you to configure how identity information generated or updated in the target directory is written back to the corresponding service desk ticket. You can create separate writeback configurations for different features and lifecycle events.

Enable Writeback: Turn on this toggle button to enable the writeback process for the integration. When enabled, the integration can write selected directory attributes, such as the generated username or email address, back to the corresponding source-system record. When this toggle button is turned on, the Writeback Configuration section is displayed for further configuration.

Writeback Configuration

Click Add Writeback Configuration to create a new configuration, or select an existing configuration to update it. 

You can add up to three writeback configurations. Each configuration applies to a specific feature and event combination, so you can define different writeback behavior for different lifecycle events sourced from the directory. The following parameters are displayed when you click Add Writeback Configuration:

  • Enable Writeback for This Feature: Turn on this toggle to enable writeback synchronization for the selected feature in this configuration. If the toggle is turned off, writeback synchronization will not be applied.

  • Select Feature for Writeback: Select a feature from the drop-down list to specify the type of data to synchronize from the Directory to your ITSM system. The following are the available options:

    • External User Ticketing: Select this option if you want to write back the user data from Directory to ITSM.
    • External User Expiry: Select this option if you want to updated the user's last working date or extend the user's expiry. 
    • Access Fulfilment: Select this option if you want to write back the group permission from Directory to ITSM.

    Note: The following parameters vary based on the selected option:

  • For Event: Select an option from the dropdown menu to specify when writeback synchronization should be applied. The integration uses the selected feature and event to determine the appropriate writeback configuration. The following are the available options:
    • Any (all events): Select this option to apply the writeback configuration to all events for the selected feature, regardless of whether access is granted or revoked.
    • Assign (grant): Select this option to apply the writeback configuration only when access is granted to a user, such as when a role, group, or license is assigned as part of the selected feature.
    • Revoke (remove): Select this option to apply the writeback configuration only when access is revoked from a user, such as when a role, group, or license is removed as part of the selected feature.
  • Write Provisioned Identity Back to Ticket: Turn on this toggle button to write the provisioned user identity information back to the source ticket. The values written to the ticket are determined by the configured writeback attribute mappings. For example, the integration can write the generated username, user principal name, or email address to the corresponding ticket fields.
  • Allow Auto Update the Ticket: Turn on this toggle button to automatically update the ticket whenever the contractor's status changes in Active Directory. For example, if the contractor's status changes from Created to In Progress in Active Directory, the corresponding Jira ticket status is updated automatically. When enabled, the following parameter is displayed for further configuration:
    • Ticket Statuses to Evaluate for Auto Update: Select the ticket statuses from the dropdown menu for which automatic updates should be applied.
  • Select Status Field: Select the ticket field whose value represents the current ticket status. The integration reads this field to determine whether the ticket is eligible for an automatic writeback update. For example, select Status (status) when the ticket status is stored in the status field.
  • Ticket Statuses to Evaluate for Auto Update: Select one or more ticket statuses from the dropdown menu to update the ticket fields only when the ticket is currently in one of the selected statuses. The ticket status is determined using the field selected in the Select Status Field parameter. If this field is left blank, tickets will be updated regardless of their status.
  • Writeback Source Filter: Select a filter from the dropdown menu to determine which source records must be considered for writeback. The following are the available options:
    • All Active Employees: Select this option to include all active employee records in the writeback process.
    • Custom: Select this option to define a custom condition for filtering the source records. When selected, the following parameter is displayed:
      • Custom Writeback Source Filter Expression: Enter a JavaScript expression that defines which source records must be considered for writeback. Only records for which the expression returns true are included in the writeback process.
  • Enable Comment on Failure in the Ticket: Turn on this toggle button to add an error comment to the source ticket when a directory operation fails. When enabled, the following parameters are displayed for further configuration:
    • Comment On Error Type: Select one or more error types from the dropdown menu to determine the failures for which a comment must be added to the ticket. The following are the available options:
      • All Errors: Select this option to add a comment for all types of failures.
      • Group Not Found: Select this option to add a comment when the specified group or entitlement is not found.
      • User Not Found: Select this option to add a comment when the specified user is not found.
  • Success Comment Template: Enter the content that must be added as a comment to the source ticket when the directory operation is completed successfully. Leave this parameter empty if a success comment is not required.
  • Failure Comment Template: Enter the content that must be added as a comment to the source ticket when the directory operation fails. You can include the actual error details in the template.
  • Transition the Ticket on Failure: Turn on this toggle button to transition the source ticket to a specified status when a directory operation fails. When enabled, the following parameters are displayed for further configuration:
    • Transition On Error Type: Select one or more error types from the dropdown menu to determine the failures for which the ticket must be transitioned.
    • Failure Transition Status: Select the status to which the source ticket must be transitioned when a configured failure occurs.

External User Ticketing

The External User Ticketing section allows you to configure ticket-based contractor provisioning. Based on the configured event, the integration reads qualifying tickets from the service desk and creates, updates, reactivates, or terminates the corresponding user accounts in the selected directory.

You can add multiple ticketing configurations to process different contractor lifecycle events. Each configuration is evaluated independently based on its event type, ticket source, statuses, correlation settings, and attribute mappings. The feature processes tickets from the ITSM application and provisions or updates users in the configured directory application.

Ticketing Configuration

Configure the following settings:

  • Manage External User: Turn on this toggle button to process contractor lifecycle events from service desk tickets. When turned on, the following parameters are displayed for further configuration:
  • Event Type: Select the contractor lifecycle event that must be processed by this configuration. Add a separate configuration for each event, such as Create, Update, Terminate, or Rehire. The integration routes each ticket to the configuration whose event type matches the detected event. For example, if you select Create, the integration is triggered when a contractor is created in the ITSM application.
  • Source Ticket Table: Select the service desk ticket source from the dropdown menu. The integration reads contractor requests from the selected project, table, or service-management application.

  • Ticket Category: Select the ticket category or work item type from the dropdown menu. Only tickets that belong to the selected category are considered by this configuration.

  • Enable to Extend Schema with Jira Request Type: Turn on this toggle button to filter and process Jira Service Management tickets by request type. When turned on, the following parameter is displayed:

    • Request Type: Select the Jira Service Management request type from the dropdown menu. Only tickets associated with the selected request type are processed. The request-type filter is applied only when Enable to Extend Schema with Jira Request Type is turned on. 

  • Select Status Field: Select the ticket field from the dropdown menu whose value represents the current ticket status.

  • Source Ticket Status Filter: Select one or more ticket statuses from the dropdown menu. Only tickets that are currently in one of the selected statuses are considered for processing.

  • Close the Ticket on Successful Provisioning: Turn on this toggle button to transition the source ticket after the corresponding directory operation completes successfully. When turned on, the following parameter is displayed:

    • Close Status: Select the status to which the source ticket must be transitioned after successful user creation, update, rehire, or termination.

  • Customize How Contractors Are Matched Across Systems: Turn on this toggle button to define how contractor records in the service desk must be matched with existing user accounts in the directory. When turned on, the following parameters are displayed:

    • Select How Contractor Records Are Matched Between the Service Desk and the Directory: Select a correlation method from the dropdown menu. The following methods are supported:

      • Correlate Using Custom Attributes: Select this option to match a ticket field with a directory attribute.
      • User AI Expression Builder: Select this option to define a custom matching expression for complex correlation requirements.
        When custom matching is not enabled, the integration uses the directory application’s natural identity attribute, such as sAMAccountName for Active Directory or userPrincipalName for Microsoft Entra ID. 

        • AI Expression Builder: Enter or generate an expression that defines how a contractor ticket must be matched with an existing directory user. This parameter is displayed only when the AI expression matching method is selected.

  • Select Source Attribute for Matching the Contractor Record: Select the service desk ticket field whose value must be used to find the corresponding user in the directory.

  • Select Target Attribute for Matching in the Directory: Select the directory attribute that must be matched with the selected service desk ticket field.

  • Enable Conditional Event Detection: Turn on this toggle button to process only contractor records that satisfy a custom condition. When turned on, the following parameter is displayed:

  • Define Contractor Ticket Creation Condition: Enter a JavaScript expression that defines which contractor tickets must be processed. Only tickets for which the expression returns true are considered for provisioning. For example, you can configure a condition to process a ticket only when the contractor’s department is Engineering and the contractor type is Fixed-Term.

  • Enable Email Notification: Turn on this toggle button to send an email notification when the configured contractor event is processed. When turned on, the following parameters are displayed:

    • Subject: Enter the content that must be used in the contractor event notification email.

    • Send To: Select one or more recipients from the dropdown menu. The following recipient types can be configured:

      • Work Email: Select this option to sends the notification to the users work email address.
      • Supervisor: Select this option to sends the notification to the users Supervisor (Manager).
      • Custom Email Address: Select this option to sends the notification for specific email addresses. When selected, the following parameter is displayed:
        • Custom Email Address: Enter a comma-separated list of email addresses to which the notifications must be sent.

  • Email Notification Template: Enter the content that must be used as the body of the contractor event notification email. You can include contractor and event-related attributes in the template.

External User Expiry Extension

The External User Expiry Extension section allows you to notify recipients about contractor account expiry, create extension tickets, process approved extension requests, update the account expiry date, and perform post-approval actions.

The feature scans the configured directory for contractor accounts that are approaching expiry and can perform notification, ticket creation, extension, termination, and ticket-closure actions.

Expiry Notification

Configure the following expiry notification settings:

This section enables you to configure when contractor expiry notifications are sent and who receives them.

  • Preset Notification Durations: Select one or more predefined notification periods from the dropdown menu. The integration sends expiry notifications when the contractor account reaches the selected number of days before its expiry date. For example, if you select 30 Days Before Expiry, the notification is sent 30 days before the contractor’s account expires. Select Custom to define a custom schedule for triggering the expiry notification.
    • Custom Duration (Days Before Expiry): Enter the number of days before the account expires when the custom notification should be triggered. This parameter is displayed only if you have selected Custom in the above parameter.
  • Notify Supervisor: Turn on this toggle button to send expiry notifications to the contractor’s supervisor. The supervisor is determined from the configured manager attribute in the directory.
  • Notify Custom Recipients:Turn on this toggle button to send expiry notifications to additional recipients. When turned on, the following parameter is displayed:
    • Custom Recipient Email(s): Enter a comma-separated list of email addresses that should receive the contractor expiry notifications.

Enable Ticket Creation: Turn on this toggle button to create service desk tickets for contractor account expiry and extension events. When this toggle button is turned on, the Create Ticket section is displayed for further configuration:

Create Ticket

Configure the following Create Ticket settings:

  • Ticketing System Project for Extension Ticket: Select the service desk project or ticket source in which contractor extension tickets must be created.
  • Work Item Type for Extension Requests: Select the work item type or ticket category that must be used for extension requests.
  • Enable to Extend Schema with Jira Request Type: Select this checkbox to create the extension request using a Jira Service Management request type. When selected, the following parameter is displayed:
    • Request Type: Select the Jira Service Management request type that must be used for contractor extension tickets.
  • Customize How Contractors Are Matched Across Systems: Turn on this toggle button to define how an extension ticket must be matched with the corresponding contractor account in the directory. When turned on, the following parameters are displayed:
    • Select How Contractor Records Are Matched Across Systems: Select the method that must be used to correlate contractor records in the service desk and directory.
    • Select Directory Attribute for Matching the Contractor: Select the directory attribute whose value uniquely identifies the contractor account.
    • Select Ticket Field for Matching the Contractor: Select the ticket field whose value must be matched with the selected directory attribute.
  • Extension Period for Contractor: Select the period by which the contractor account expiry date must be extended. For example, if you select 30, the contractor account will expire 30 days from today. The following parameter is displayed if you select Custom.
    • Custom Extension Duration (Days): Enter the number of days by which the contractor account must be extended.
  • Select Ticket Field for the Extended Expiry Date: Select the ticket field that contains the approved account expiry date. When the field contains a valid date, the integration uses that value as the new contractor expiry date. If the field is empty or does not contain a valid date, the integration uses the configured extension period.
  • Enable Conditional Ticket Creation: Turn on this toggle button to create extension tickets only for contractor accounts that satisfy a custom condition. When turned on, the following parameter is displayed:
    • AI Expression Builder — Ticket Creation: Enter or generate an expression that defines when an extension ticket must be created. Only contractor records for which the expression returns true result in ticket creation.
  • Auto Close After End Date Extension: Turn on this toggle button to automatically transition the extension ticket after the directory account expiry date is successfully updated. When turned on, the following parameters are displayed:
    • Select Closure Status Field*: Select the ticket field from the dropdown menu whose value represents the current ticket status.
    • Ticket Closure Status: Select the status from the dropdown menu to which the extension ticket must be transitioned after the expiry date is successfully extended.

Enable Extension Period Automation: Turn on this toggle button to automatically process approved contractor extension tickets and update the corresponding account expiry dates. When turned on, the Extend the Extension Period section is displayed for further configuration:

Extend the Extension Period

Configure the following parameters:

  • Select Field For Approval*: Select the ticket field that indicates whether the extension request has been approved.
  • Approval Field Type: Select the type of the approval field. For example, select Dropdown when the approval field contains selectable values, or select a text-based option when approval is indicated through text.
  • Approval Field Value: Select or enter the value that represents an approved extension request. The integration processes only tickets whose approval field matches this value.
  • Action Decision Field*: Select the ticket field that determines which action must be performed after the extension request is approved.
  • Post-Approval Actions: Select one or more actions that the integration can perform after approval. For example, select Delete Account to delete the contractor account when the corresponding decision value is detected.
  • Delete – Decision Field Value: Enter the value that must appear in the Action Decision Field to trigger deletion of the user account.
  • Delete – Timing: Select when the account must be deleted. The following are the available options:
    • Immediately (delete now): Delete the account immediately after approval.
    • After extension ends (delete at the extended end date): Delete the account when the extended expiry date is reached.

  • Enable Conditional Ticket Read: Turn on this toggle button to read and process only extension tickets that satisfy a custom condition. When turned on, the following parameter is displayed:

    • AI Expression Builder – Filter Tickets to Read (Approval): Enter or generate an expression that defines which extension tickets must be read for approval processing. Tickets that do not satisfy the condition are ignored.

Access Fulfilment

The Access Fulfilment section allows you to process access requests from service desk tickets and grant or revoke the requested directory entitlements.

The feature reads the requested entitlement from a configured ticket field, matches the ticket requester with a directory user, and then grants or removes the corresponding group membership.

Enable Access Fulfilment: Turn on this toggle button to enable the processing of access requests from the configured service desk application. When enabled, the integration evaluates eligible tickets and grants or revokes the requested directory groups or other supported entitlements based on the configured access fulfilment settings.

Organizational Unit (OU) Assignment Rules

Click the expand icon () next to the Organizational Unit (OU) Assignment Rules to configure the following parameters:

Assignment Rules

This section allows you to define general directory group-assignment rules based on user attributes.

Click the expand icon () next to the Groups Assignment Rules to configure the following parameters:

  • Enable Assignment Rules: Turn on this toggle button to assign users to directory groups based on the conditions configured in the Assignment Rules rule builder. These rules are used for Microsoft Entra ID and other supported directory applications. They can also act as secondary group-assignment rules for Active Directory when the Active Directory-specific group rules are not enabled.

    Assignment Rules: Configure conditions that determine which directory groups must be assigned to users.     Click the Run Analysis button to evaluate the configured assignment rules against sample source data and verify the resulting group assignments.

Groups Active Directory (Group Rules)

This section allows you to configure group-assignment rules specifically for Active Directory.

Click the expand icon () next to the Groups Active Directory (Group Rules) to configure the following parameters:

    Group Assignment Rule: Configure conditions that determine which Active Directory groups must be assigned to users. You can upgrade an integration built from a template to the latest version to access new features and enhancements. 

Perform the following steps to upgrade an integration:

  1. Navigate to the Integrations module on the Aquera Admin portal.
  2. Click the vertical ellipsis icon next to an integration and click View Details. The Details panel is displayed with the following sections:
    • INTEGRATION DETAILS: Displays the integration name, description, creation date, last update date, and the user who created or last updated it.

  4. Provide the following details for the new integration to be created after the upgrade:
    • New Integration Name: Enter the name of the new integration.
    • Description: Provide a description for the new integration.
      The current version number and the upgraded version number are displayed.
  5. Click Upgrade. A new integration is created with the same configuration details as the existing one, but with features or enhancements from the upgraded version.
