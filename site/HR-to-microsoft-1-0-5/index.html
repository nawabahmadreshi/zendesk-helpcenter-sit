Ignore Case When Checking Uniqueness: This toggle determines whether the integration must ignore the character case of the generated value while checking uniqueness against the existing value.

  • When enabled, the integration ignores differences in character case between the generated value and the existing value while checking for uniqueness.
  • When disabled, the integration considers the generated value and the existing value as separate records. The generated value is treated as a new record, and the attempt logic is applied to it.

Update Case To Match Naming Pattern: This toggle determines whether the integration must update the existing user naming attribute values to match the character case of the values generated based on the user naming attributes configured in the integration.

  • When enabled, the integration compares the generated value with the existing value. If the values differ only by character case, the existing value is updated to match the character case configured in the Advanced User Naming Configuration section.
  • When disabled, the character case of the existing value is not updated.

Note: This toggle is displayed only when the Ignore Case When Checking Uniqueness toggle is enabled.

 

Ignore Case When Checking Uniqueness: This toggle determines whether the integration must ignore the character case when comparing the generated user naming attribute values with the existing attribute values in the directory for uniqueness.

  • When enabled, the integration ignores differences in character case between the generated value and the existing value while checking for uniqueness. For example, jsmith and JSmith are considered the same value.
  • When disabled, the integration considers character case when checking for uniqueness. Values that differ only by character case are considered different. The generated value is treated as a new record, and the attempt logic is applied to generate the unique attribute values.

Update Case To Match Naming Pattern: This toggle determines whether the integration must update the character case of existing user naming attribute values to match the values generated using the Advanced user naming configuration.

  • When enabled, the integration compares the generated value with the existing value. If the values differ only by character case, the existing value is updated to match the character case of the value generated using the Advanced user naming configuration.
  • When disabled, the character case of the existing value remains unchanged.

Note: This toggle is displayed only when the Ignore Case When Checking Uniqueness toggle is enabled.

 

You can generate a user naming attribute value by providing an expression that combines two values and appends the value retrieved from the configured table value.

You can append a value retrieved from a configured table while generating User Naming attributes.

Here is a sample prompt:

Generate an expression by combining FirstName and LastName with append the value from the Table.Department [“Customer Service”]. If the department value matches with the TABLE.Department[SOURCE.PrimaryWorkAssignmentDepartmentXRefCode] append the value in the expression. When appending the table values, do not add a period (.); add a space instead with parenthesis ( ).

If the given value does not match any of the values configured in the table, the user naming value is generated based on the user naming format configured in the prompt.
