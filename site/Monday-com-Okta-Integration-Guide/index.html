Monday.com / Okta Integration Guide

← Back to index

Overview

Aquera provides an innovative platform that allows your organization to scale complex data management by automating data synchronization from Monday.com users to Okta.

Aquera's integrations facilitate the automatic provisioning, ensuring consistency across systems. It allows organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately improving efficiency in managing intricate IT infrastructures and applications.

In this integration, every user you create, update, provision, or deactivate in Monday.com will be synced to Okta within their respective groups. You can use custom filters to filter out users based on your use case.

This guide covers details on how to set up the Monday.com / Okta integration to provision, update, or deprovision users from Monday.com to Okta.

Key Functions

This integration automates user sync operation with the following primary capabilities:

  • Synchronizes user data from Monday.com to Okta.
  • Creates, updates, and deactivates users from a group by configuring custom filters.
  • Sends notifications upon success and failure events. Sends per-transaction notifications via emails.
  • Generates detailed logs and reports.

Prerequisites

The following are the prerequisites:

  • Aquera Tenant Account: You must have a tenant account in the Aquera Admin portal. Visit https://admin.aquera.io and register to get a tenant account. Contact your Aquera account manager to get the Aquera tenant access.
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/.
  • Configure Applications in the Aquera Admin Portal:
    • Monday.com Connector: Ensure you add and configure the source application connector in the Aquera Admin portal. Refer to the Monday Configuration Guide for details.
    • Okta Connector: Ensure you add and configure the Okta connector in the Aquera Admin portal. Refer to the Okta Configuration Guide for details.

Integration Setup

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations on the left panel.
  3. Click Create Integration.
  4. Select Monday.com / Okta. The Create New Integration pop-up window is displayed.
  5. Enter a name and a description for the integration.
  6. Click Continue. The integration is created.

Once created, the following tabs are displayed:

  • Configuration
  • User provisioning
  • Okta
  • Attribute Map
  • Schedule

Configuration

This tab allows you to configure the settings involved in the integration. You can view all the integration settings to be enabled based on the use cases. The following sections are displayed in the configuration tab:

  • Parameters
  • Log Settings
  • Report Settings
  • Log Insights
  • Notifications

Parameters

The parameters section is for configuring and enabling the required settings for this integration. The following fields are displayed in this section:

  • Enable Report-Only Mode: Select this checkbox to generate a report detailing the data changes that would happen, but without applying them.
  • Enable Logging: Select this checkbox to generate logs outlining data changes. When selected, the Log Settings section is displayed for further configuration.
  • Enable Reporting: Select this checkbox to generate the integration report. When enabled, the Report Settings section is displayed for further configuration.
  • Enable Log Insights: Select this to visualize the integration-related metrics. When enabled, the Log Insights Settings section is displayed for further configuration.
  • Enable Email Notifications: Select this checkbox to enable email notifications for the integration.
  • Enable Unique Identity: Select this checkbox to enable the unique identity settings that are used to generate a username and email address for the user. When selected, the Unique Identity section is displayed in the Okta tab.
  • Enable Writeback: Select this checkbox to enable the integration to write back the Okta user attributes to Monday.com.

Log Settings

The Log Settings section allows you to configure the required settings to be logged. When enabled, the Log Settings section will appear for further configurations:

  • Select Log Type: Select the log type. This will decide the level of detail to be included in logs. If you do not find your log type in the dropdown list, click the refresh icon available adjacent to the field to refresh the list.
    The following are the available options:

    • Minimum: Select this option to include only operation details. No GUIDs or field-level information will be included.
    • Metadata: Select this option to include operation details and field names. GUIDs are excluded.
    • Non-PII Data: Select this option to include operation details, field names, and selected non-PII values. GUIDs are excluded.
    • GUID with Non-PII Data: Select this option to include GUIDs, operation details, field names, and selected non-PII values.
    • Employee Number with Non-PII Data: Select this option to include employee numbers, operation details, field names, and selected non-PII values.
    • Employee Number with All Data: Select this option to include employee numbers, operation details, field names, and all values, including both PII and non-PII data.
  • Select Log Level: Select the level of detail to include in the integration logs from the dropdown menu. If you do not find your Log Level in the dropdown list, click the refresh icon available adjacent to the field to refresh the list.
    The following are the available options:
    • Full: Select this option if you want to fetch all attribute details in the logs.
    • Include List: Select this option if you want to choose attributes to be included in logs. When selected, the following field is displayed:
      • Custom Inclusion List: Enter the attributes that should be included in logs. For example, email.
    • Exclude List: Select this option if you want to choose attributes to be excluded in logs. When selected, the following field is displayed:
      • Custom Exclusion List: Enter the attributes you want to exclude from logs. For example, entering salary and Location ensures these fields are not excluded.
  • Enter PII Fields: Enter the attributes that contain personally identifiable information that you want to be masked in logs. For example, enter email in this field if you do not want to show the email value in logs.
  • Enter GUID Fields: Enter the fields that contain unique identifiers. For example, fields like id or objectId can be marked to ensure proper handling and tracking.
  • Enter Employee Number Fields: Enter the attribute names that contain employee number values. For example, enter employeeId and employeeNumber if these attributes contain employee number values.

User Provisioning

The User Provisioning tab allows you to filter the users in group section in the Monday instance. Configure the following fields in the user provisioning settings:

Select Source Application

This section enables you to select the required source application for this integration.

  • Select Monday.com application instance*: Select the required application instance from the dropdown list.  If you do not find your application in the dropdown list, click the refresh icon available adjacent to the field to refresh the list.

Board and Source Filter

This section allows you to configure the board and group filter and to set conditions for the source application. The following fields are displayed for further configuration:

  • Boards and Groups*: Enter the board Id and group name from which the users data must be retrieved for provisioning. The value must be in boardId__groupName format.
  • Source Filter*: Select the required source filter that retrieves the required data from the board. If you do not find your required source filter in the dropdown list, click the refresh icon available adjacent to the field to refresh the list. The following are the available options:
    • All Group Items: Select this option to sync all the users items from a group.
    • Column Filter: Select this option to apply a column filter. When selected, the following fields will be displayed:
      • Column Name*: Enter the column name you want to filter.
      • Operator*: Select the required operator from the dropdown list. If you do not find your operator in the dropdown list, click the refresh icon available adjacent to the field to refresh the list.
      • Filter Value*: Enter the filter value you want to compare it against the column name.
    • Custom: Select this option to filter the data from Monday using a JavaScript expression. When selected, the following field will be displayed:
      • Custom Source Filter(JS expression)*: Provide the custom JS expression in this field to fetch users.
  • Upsert condition*: This field allows you to define which fetched items to be created or updated in Okta. If you do not find your required upset condition in the dropdown list, click the refresh icon available adjacent to the field to refresh the list. The following are the available options:
    • None: Select this option to not perform any condition.
    • All Group Items: Select this option to sync all the users items from a group.
    • Custom: Select this option to filter the data from Monday using a JavaScript expression. When selected, the following field appears.
      • Custom Upsert Condition(JS expression)*: Provide the custom JS expression in this field to fetch users.
  • Deactivate Condition*: This field is to fetch all the deactivated users from the board. If you do not find your required deactivate condition in the dropdown list, click the refresh icon available adjacent to the field to refresh the list. The following are the available options:
    • None: Select this option to not perform any filter condition.
    • Custom: Select this option to filter the data from Monday using a JavaScript expression. When selected, the following field appears.
      • Custom Deactivate Condition(JS expression)*: Provide the custom JS expression in this field to fetch all the deactivated users.
  • Suspend Condition*: This field suspends the selected users during each run. This prevents them from signing in while preserving their group and app assignments. If a user matches both deactivate and suspend, the integration deactivates the user. If you do not find your required suspend condition in the dropdown list, click the refresh icon available adjacent to the field to refresh the list. The following are the available options:
    • None: Select this option will not perform any filter condition.
    • Custom: Select this option to filter the data from Monday using a JavaScript expression. When selected, the following field appears.
      • Custom Suspend Condition (JS expression): Provide the custom JS expression in this field to fetch all the suspended users.
  • Enable Incremental Sync: Select this checkbox to fetch only datas that are changed from the last successful run.

This section allows you to configure the attributes used to identify and match users between monday.com and Okta.

  • Monday.com Correlation Attribute: Enter the monday board column name that the integration uses to fetch the matching Okta user.
  • Okta Correlation Attribute: Enter the Okta user attribute that the integration uses as the matching key.

Unique Identity

This section allows you to configure how unique usernames and email addresses are generated and managed in Okta. This section is available only if you select the Enable Unique Identity checkbox in the Parameters section.
The following are the available options in this section:

  • First Name Columns(ordered)*: Enter the monday board column title in which the integration will check for the user's first name. This integration fetches the first non-empty value and uses it to generate the username and email. 
  • Last Name Columns(ordered)*: Enter the monday board column title in which the integration will check for the user's last name. This integration fetches the first non-empty value and uses it to generate the username and email. 
  • Enable Unique userName: Select this checkbox to automatically generate a unique username if the configured username already exists in Okta. When enabled, the following field is dispalyed.
    • Unique userName Pattern Builder: Enter the unique username patterns in the order they should be tried to generate a unique username. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.
    • Enable Unique Email ID: Select this checkbox to automatically generate a unique email address if the configured email already exists in Okta. When enabled, the following field is displayed.
      • Email Generation Mode: Select how email addresses should be generated for users. The available options are displayed.
        • Same as username: Select this option to generated username as the user's email address.
        • Different Email: Select this option to generate different email address for the users. When selected, the Unique email Pattern Builder field will be displayed.
          • Unique email Pattern Builder: Enter the email patterns in the order they should be tried to generate a unique email address. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide..
    • Generate unique values only when source email is empty: Select this checkbox to generate a unique username and email only for users whose source email is empty. When disabled, the integration generates a unique identity for every new user, even if the user already has an email.

Attribute Map

The Attribute Map tab defines how data is mapped from the source to the target application. The default mapping of attributes is displayed on the page. The source attributes are listed on the left side, and the target attributes are listed on the right side of the page.

You can modify only the source attributes as needed to align with your specific use case.

You can write JavaScript expressions to modify the value of the source attribute and construct a value to be updated in the target attribute. Write the expression directly in the source attribute field or click the Expand icon in the source attribute field to write a long expression.

All attributes marked with a red asterisk (*) indicate required fields for successful provisioning.

After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the integration.
