HR / ITSM - NinjaOne Integration Guide

Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

This integration automates identity-driven IT service management workflows by connecting your HR system to NinjaOne. The integration retrieves workforce data from the selected HR application, detects employee lifecycle events based on the configured lifecycle rules, and automatically creates NinjaOne tickets for the configured lifecycle events.

The integration supports configurable ticket creation for employee lifecycle events, such as new hires, pre-hires, and terminations. It also allows you to control when tickets are created, map employee information to service desk ticket fields, and customize how employees are matched between the HR system and NinjaOne.

Key Functions

This integration provides the following capabilities:

  • Retrieves workforce data from the configured HR application.
  • Detects employee lifecycle events based on configured rules.
  • Creates NinjaOne tickets for selected employee lifecycle events.
  • Allows custom employee matching between the HR application and NinjaOne.
  • Maps HR attributes to NinjaOne request fields.
  • Supports configurable rules to determine when employee lifecycle events are processed for ticket creation.
  • Sends event notifications through email.
  • Generates detailed logs, operational reports, and execution summaries.

Integration Setup

This section explains how to configure the integration to synchronize employee lifecycle events from an HR application with NinjaOne and automatically create tickets for the configured lifecycle events.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for HR / ITSM - NinjaOne in the search box next to the Explore Templates section and click it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Source
  • Service Desk
  • Operations
  • Features
  • Tables
  • Schedule

Overview

The Overview tab displays general information about the integration, including its purpose and supported capabilities. It provides a high-level overview of how the integration automates ticket creation for employee lifecycle events.

Source

The Source tab allows you to select the HR application used by the integration and define which employees are considered for NinjaOne ticket creation.

The following sections are available on this tab:

Application Settings

The Application Settings section allows you to identify the HR application instance used by the integration. The following field is available in this section for configuration:

  • HR application instance: Select the HR application connector from which employee data and lifecycle events will be retrieved for this integration. If the required connector is not available in the list, click the refresh icon next to the field to reload the available connectors.
    Note:
    • Currently, this integration only supports the ADP Workforce Now connector.

Filter Employees

This section allows you to define which employees from the HR application are considered for NinjaOne ticket creation. The following field is available in this section for configuration:

  • Enable employee filter: Turn on this toggle button to filter employees considered for NinjaOne ticket creation. Only employees who match the configured filter criteria are processed. When enabled, the Employee Filter Configuration section is displayed for further configuration.

Employee Filter Configuration

This section allows you to configure the criteria used to filter employees from the HR application for NinjaOne ticket creation.

The following fields are displayed for configuration:

  • Use filter for new hires: Turn on this toggle button to filter new hires from the HR application. Only new hires who match the filter criteria are considered for NinjaOne ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Hire Date.
  • Use Filter for Change Employees: Turn on this toggle button to filter users from the HR application.  Only users who match the defined rules are considered for NinjaOne ticket creation. When enabled, the following fields are displayed for further configuration:
    • Look-back Window for Changes (Days): Enter the number of past days to consider for ticket creation. Leave this field blank to process all matching employees.
  • Use filter for terminated employees: Turn on this toggle button to filter terminated employees from the HR application. Only terminated employees who match the filter criteria are considered for NinjaOne ticket creation.
    When enabled, the following fields are available for configuration:
    • Employee filter criteria: Select the method used to filter terminated employees from the HR application. The following is the available option:
      • Based on date: Select this to filter terminated employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter terminated employees from the HR application. For example, Termination Date.
  • Use filter for rehires: Turn on this toggle button to filter rehires from the HR application. Only rehires who match the filter criteria are considered for NinjaOne ticket creation. When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Rehire Date.

Channel

  • Enable messaging: Enable this option to allow the integration to send messages and notifications through the configured messaging channel. When enabled, the Messaging Application section is displayed for further configuration.

Service Desk Application Configuration

The Service Desk Application Configuration section allows you to identify the service desk application instance used by the integration.

  • Service desk application instance: Select the NinjaOne application connector where the integration will create tickets. If the required connector is not available in the list, click the refresh icon next to the field to reload the configured application connectors.

Messaging Application

The Messaging Application Configuration section allows you to configure the messaging application instances used by the integration to send notifications.

  • Enable Slack notifications: Enable this option to send Slack notifications when the configured lifecycle event is detected. When enabled, additional Slack notification settings are displayed: 
    • Slack application instance: Select the Slack application instance configured in Aquera to send lifecycle event notifications. If the required connector is not available in the list, click the refresh icon next to the field to reload the configured application connectors.

JML Ticket Creation

This section enables you to configure how NinjaOne tickets are created for employee lifecycle events. The following field is displayed in this section:

  • Enable ticket creation: Turn on this toggle button to automatically create NinjaOne tickets for employee lifecycle events. When enabled, the Ticket Creation Configuration section is displayed for configuration.

Ticket Creation Configuration

This section allows you to configure how NinjaOne tickets are created for a selected employee lifecycle event.

  • Select event type: Select the employee lifecycle event for which NinjaOne tickets should be created. The following lifecycle events are available for selection:
    • Hire: Select this option if you want to create NinjaOne tickets when a new hire event is detected.
    • Change: Select this option if you want to create NinjaOne tickets when an employee change event is detected.
    • Terminate: Select this option if you want to create NinjaOne tickets when a termination event is detected.
    • Rehire: Select this option if you want to create NinjaOne tickets when a rehire event is detected.
    • Pre-hire: Select this option if you want to create NinjaOne tickets when a pre-hire event is detected.
  • Select change events: Select one or more employee attributes to monitor for changes in the HR application. After the integration is configured, the integration checks the selected attributes for subsequent changes. If a change is detected in any selected attribute, the integration considers the employee for mover ticket creation in NinjaOne.
    For example, if you select Department and Location, the integration tracks changes to these attribute values. If an employee's department or location changes, the employee is considered for mover ticket creation. 
    Refer to Supported Attributes for Change event for details on which attributes each HR application supports.
    Note: This option appears only when the event type is selected to Change.
  • Event timing: Define when the NinjaOne ticket should be created for the selected lifecycle event. The following are the available options:
    • When detected: Select this if you want to create tickets immediately after the lifecycle event is detected.
    • Before start date: Select this if you want to create tickets before the actual start date of the employee.
    • On start date: Select this if you want to create tickets on the employee's start date.
    • After start date: Select this if you want to create tickets after the actual start date of the employee.
      When you select Before start date or After start date, the following field is displayed to define the number of days:
      • Days Before / After Joining Date: Enter the number of days before or after the selected lifecycle event date when the ticket should be created. For example, entering 7 with Before start date selected creates the ticket seven days before the employee's effective start date.
  • Enable conditional event detection: Turn on this toggle button to create NinjaOne tickets only for employees who satisfy a defined condition. When enabled, the following field is displayed:
    • Ticket creation condition: Enter a condition to control which employees trigger NinjaOne ticket creation. Only employees who satisfy this condition are considered for ticket creation. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.
  • Enable ticket creation: Turn on this toggle button to create NinjaOne tickets for the selected lifecycle event. When enabled, the following fields are displayed for further configuration:
    • Organization: Select the organization (client) that the ticket belongs to. NinjaOne requires the clientId to create and update tickets.
    • Request Template: Select the NinjaOne request template used when creating tickets for the selected lifecycle event. If the required request template is not available, click the Refresh icon next to the field to reload the available request template.
    • Customize how users are matched across systems: Turn on this toggle button to configure custom employee matching. When enabled, the following fields are displayed.
      • Select How Employees Are Matched Between Source and Target: Select the method used to correlate employees between the HR application and NinjaOne.
      • Select Source Attribute for Matching the Employee: Select the HR application attribute used to uniquely identify employees.
      • Select Target Attribute for Matching the Employee: Select the NinjaOne field used to uniquely identify employees.
    • Auto update the ticket: Enable this option to automatically update the ticket when its status matches the configured update criteria. When enabled, the following field is displayed:
      • Ticket statuses to evaluate for auto-update: Select the ticket statuses that the integration evaluates before automatically updating a ticket. For example, select In Progress.
    • Auto close the ticket: Enable this option to automatically close the ticket when its status matches the configured close criteria. When enabled, the following fields are displayed:
      • Ticket statuses to evaluate for auto-close: Select the ticket statuses that the integration evaluates before automatically closing a ticket. For example, select Waiting for Customer.
      • Ticket close status: Select the status assigned to the ticket when it is automatically closed.
    • Ticket management mapper: This section allows you to map HR attributes to NinjaOne ticket fields. Source attributes are displayed on the left side, and service desk ticket fields are displayed on the right side of the page. You can modify only the source attributes as needed, to align with your specific use case. JavaScript expressions can be used to transform source attribute values and construct the values that are updated in the target attributes. You can enter the expression directly in the source attribute field or click the expand icon to write a longer expression. The Search Attributes field allows you to search for source attributes.
      Attributes marked with a red asterisk (*) are mandatory for successful execution.
      After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the configuration.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the Ticket field mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the ticket field mapper if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.
