HR / ITSM - Freshservice Integration Guide

← Back to index

This guide applies to the latest public version of the integration (version 1.4.0).

Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

This integration automates identity-driven IT service management workflows by connecting your HR system with Freshservice. The integration retrieves workforce data from the selected HR application, detects employee lifecycle events based on the configured lifecycle rules, and automatically creates Freshservice tickets for the configured lifecycle events.

The integration supports configurable ticket creation for employee lifecycle events, such as new hires and terminations. It also allows you to control when tickets are created, map employee information to Freshservice request fields, and customize how employees are matched between the HR system and Freshservice.

Key Functions

This integration automates Freshservice request creation for employee lifecycle events with the following primary capabilities:

  • Retrieves workforce data from the configured HR application.
  • Detects employee lifecycle events based on configured rules.
  • Creates Freshservice tickets for selected employee lifecycle events.
  • Allows custom employee matching between the HR application and Freshservice.
  • Maps HR attributes to Freshservice request fields.
  • Supports configurable rules to determine when employee lifecycle events are processed for ticket creation.
  • Sends event notifications through email.
  • Generates detailed logs, operational reports, and execution summaries.

Integration Setup

This section explains how to configure the integration to synchronize employee lifecycle events from an HR application with Freshservice and automatically create requests for the configured lifecycle events.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for HR / ITSM - Freshservice in the search box next to the Explore Templates section and click it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Features
  • Source
  • Service Desk
  • Operations
  • Tables
  • Schedule

Overview

The Overview tab displays general information about the integration, including its purpose and supported capabilities. It provides a high-level overview of how the integration automates employee lifecycle request creation between the HR application and Freshservice.

Features

The Features tab provides an overview of the functional capabilities supported by the integration. The following section is displayed on this tab:

Service Desk Bridge

The Service Desk Bridge section controls the functional capabilities supported by the integration.

The following features are available for this integration:

  • Enable HCM Bridge: This is enabled by default to process employee lifecycle events from the configured HR application.
  • Enable Service Desk Bridge: This is enabled by default to create and manage Freshservice requests based on employee lifecycle events.
  • Enable Employee Lifecycle: This is enabled by default to process employee lifecycle events, including onboarding, employee changes, and termination events.
  • JML Lifecycle Events: This is enabled by default to create Freshservice requests for Joiner and Leaver (JML) lifecycle events.

Note: This integration supports only onboarding and offboarding events.

Additional features displayed on this page represent capabilities supported by the integration. To learn more or enable these features, contact the Aquera Support team.

Filter Employees

The Filter Employees section allows you to configure how employee lifecycle events are processed by the integration. The following field is available in this section for configuration:

  • Enable employee filter: Turn on this toggle button to filter employees from the source system. Only employees who match the filter criteria are considered for Freshservice ticket creation. When enabled, the Employee Filter Configuration section is displayed for further configuration.

Employee Filter Configuration

This section allows you to configure the criteria used to filter employees from the source system for Freshservice ticket creation.

The following fields are displayed for configuration:

  • Use filter for new hires: Turn on this toggle button to filter new hires from the source system. Only new hires who match the filter criteria are considered for Freshservice ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the source system. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the source system. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the source system. For example, select Original Hire Date.
  • Use filter for account changes: Turn on this toggle button to filter users from the HR application.  Only users who match the defined rules are considered for Freshservice ticket creation. When enabled, the following fields are displayed for further configuration:
    • Select Attributes to Synchronize: Select the user profile attributes to synchronize from the source system to the target system. If you do not find your attribute in the list, click the refresh icon available next to the field to reload the available attributes.
      Note: This setting will be available only if you select ADP Workforce Now as you HR Application.
  • Use filter for terminated employees: Turn on this toggle button to filter terminated employees from the source system. Only terminated employees who match the filter criteria are considered for Freshservice ticket creation.
    When enabled, the following fields are available for configuration:
    • Employee filter criteria: Select the method used to filter terminated employees from the source system. The following is the available option:
      • Based on date: Select this to filter terminated employees using a date attribute from the source system. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter terminated employees from the source system. For example, select Termination Date.
  • Use filter for temporary account disable: Turn on this toggle button to filter users from the HR application.  Only users who match the defined rules are considered for Freshservice ticket creation. When enabled, the following fields are displayed for further configuration:
    • Leave types that trigger account deactivation: Select the leave types that trigger account deactivation. The integration deactivates accounts only for users whose leave type matches the selected values. If you do not find your leave type in the list, click the refresh icon available next to the field to reload the available leave types.
      Note: This setting will be available only if you select ADP Workforce Now as you HR Application.
  • Use filter for account rehire: Turn on this toggle button to filter rehires from the HR application. Only rehires who match the filter criteria are considered for Freshservice ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter to trigger rehire: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Hire Date. If you do not find your data attribute in the list, click the refresh icon available next to the field to reload the available attributes.

JML Ticket Creation

This section enables you to configure how the integration detects employee lifecycle events and creates Freshservice tickets. The following field is displayed in this section:

  • Enable ticket creation: Turn on this toggle button to automatically create Freshservice tickets for employee lifecycle events. When enabled, the Ticket Creation Configuration section is displayed for configuration.

Ticket Creation Configuration

This section allows you to define how the integration processes a specific employee lifecycle event and creates the corresponding Freshservice tickets.

  • Look-back window (Days): Enter the number of past days to consider for ticket creation. Leave this field blank to process all matching employees.
  • Select event type: Select the employee lifecycle event for which Freshservice tickets should be created. The following lifecycle events are available for selection:
    • Hire: Select this option if you want to create Freshservice tickets when a new hire event is detected.
    • Terminate: Select this option if you want to create Freshservice tickets when a termination event is detected.
    • Rehire: Select this option if you want to create Freshservice tickets when a rehire event is detected.
    • Change: Select this option if you want to create Freshservice tickets when an employee change event is detected.
    • Pre-hire: Select this option if you want to create Freshservice tickets when a pre-hire event is detected.
  • Event timing: Define when the Freshservice ticket should be created for the selected lifecycle event. The following are the available options:
    • When detected: Select this if you want to create tickets immediately after the lifecycle event is detected.
    • Before start date: Select this if you want to create tickets before the actual start date of the employee.
    • On start date: Select this if you want to create tickets on the employee's start date.
    • After start date: Select this if you want to create tickets after the actual start date of the employee.
      When you select Before start date or After start date, the following field is displayed to define the number of days:
      • Days before / After joining date: Enter the number of days before or after the selected lifecycle event date when the ticket should be created. For example, entering 7 with Before start date selected creates the ticket seven days before the employee's effective start date.
  • Select change events: Select the employee changes that should create a Freshservice ticket, for example change in Department or Location. By default, it uses the attributes selected in Select attributes to synchronize in the filter employees section. If multiple selected changes have the same effective date, they are grouped into a single Freshservice ticket.
    Note: This option appears only when the event type is selected to Change.
  • Enable conditional event detection: Turn on this toggle button to create Freshservice tickets only for employees who satisfy a defined condition. When enabled, the following field is displayed:
    • Ticket creation condition: Enter a condition to control which employees trigger Freshservice ticket creation. Only employees who satisfy this condition are considered for ticket creation. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.
  • Enable ticket creation: Enable this option to create Freshservice tickets for the selected lifecycle event. When enabled, the following fields are displayed for further configuration:
    Note: When you enable this, the Aquera integration will automatically create tickets in the service desk. 
    • Ticket type: Select the ticket type that should be used when creating tickets. If the required ticket type is not available, click the Refresh icon next to the field to reload the available ticket types.
      The following are the available options:
      • Request: Select this if you want to create requests for the selected lifecycle event. When selected, the following fields are displayed:
        • Ticket category: Select the Freshservice ticket category used during request creation. If the required ticket category is not available, click the Refresh icon next to the field to reload the available ticket category.
        • Ticket type name: Select the required ticket type name from the dropdown list. If the required ticket type name is not available, click the Refresh icon next to the field to reload the available ticket type name.
      • Journey request:Select this to create Freshservice tickets of journey request type. The Journey request type is used to create all the tickets required throughout an employee's onboarding process. When selected, the following field is displayed:
        • Ticket type name: Select the required ticket type name from the dropdown list.  If the required ticket type name is not available, click the Refresh icon next to the field to reload the available ticket type name.
      • Employee offboarding: Select this to create Freshservice tickets of employee offboarding type.
    • Customize how users are matched across system: Turn on this toggle button to configure custom employee matching. When enabled, the following fields are displayed.
      • Select how employees are matched between the HR application and Freshservice: Select the method used to correlate HR application employees with existing Freshservice tickets.
      • Select source attribute for matching the employee: Select the HR application attribute used to uniquely identify employees.
      • Select target attribute for matching the employee: Select the Freshservice Management field used to uniquely identify employees.
    • Ticket management mapper: This section allows you to map HR attributes to Freshservice ticket fields. Source attributes are displayed on the left side, and Freshservice ticket fields are displayed on the right side of the page. You can modify only the source attributes as needed, to align with your specific use case. JavaScript expressions can be used to transform source attribute values and construct the values that are updated in the target attributes. You can enter the expression directly in the source attribute field or click the expand icon to write a longer expression. The Search Attributes field allows you to search for source attributes.
      Attributes marked with a red asterisk (*) are mandatory for successful execution.
      After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the configuration.
  • Allow auto update the ticket: Turn on the toggle button to automatically update Freshservice JML tickets only when their current status matches one of the selected ticket statuses. When enabled, the following field is displayed:
    • Ticket statuses to evaluate for auto update: Select the Freshservice ticket statuses that should be evaluated to determine whether a ticket is eligible for automatic updates. If you do not find your ticket status in the list, click the refresh icon available next to the field to reload the available ticket statuses.
  • Auto close the ticket: Enable this option to automatically close the Freshservice JML ticket after all actions associated with the user lifecycle event have been completed successfully. When enabled, additional configuration options are displayed:
    • Ticket status to evaluate for auto close: Select the Freshservice ticket statuses that should be evaluated to determine whether a ticket is eligible for automatic closure. If you do not find your ticket status in the list, click the refresh icon available next to the field to reload the available ticket statuses.
    • Ticket close status: Select the Freshservice ticket status to apply when the integration automatically closes the ticket.
  • Enable email notification: Turn on this toggle button to sent email notification when a hire event occurs. When enabled, the following fields are displayed:
    • Subject: Enter the content that must be used as the email subject.
    • Notification recipients: Select the recipients to send email notifications. For example, select Supervisor if you want to send email notifications to the user's supervisor. The following field is displayed when you select Custom in this field:
      • Custom email address: Enter the email IDs of the users to whom you want to send email notifications.
    • Email notification template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the email body.
      Note: Make sure to give all the required details in the template body, as this notifications will be triggering the ticket creation so provide complete and accurate information to ensure successful ticket creation.
  • Enable teams notification: Turn on this toggle button to sent teams notification when a hire event occurs. When enabled, the following fields are displayed:
    • Select team: Select the required teams where the hire notification should be posted. If you do not find the required teams in the list, click the refresh icon available next to the field to reload the available teams.
    • Select Channel: Select the required channel where the hire notification should be posted. If you do not find the required channel in the list, click the refresh icon available next to the field to reload the available channel.
    • Teams notification template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the notification body.
      Note: Make sure to give all the required details in the template body, as this notifications will be triggering the ticket creation so provide complete and accurate information to ensure successful ticket creation.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the Ticket field mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the ticket field mapper, if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.
