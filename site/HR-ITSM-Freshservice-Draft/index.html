Features

The Features tab provides an overview of the functional capabilities supported by the integration. The following section is displayed on this tab:

Service Desk Bridge

The Service Desk Bridge section controls the functional capabilities supported by the integration.

The following features are available for this integration:

  • Enable HCM Bridge: This is enabled by default to process employee lifecycle events from the configured HR application.
  • Enable Service Desk Bridge: This is enabled by default to create and manage Jira Service Management requests based on employee lifecycle events.
  • Enable Employee Lifecycle: This is enabled by default to process employee lifecycle events, including onboarding, employee changes, and termination events.
  • JML Lifecycle Events: This is enabled by default to create Jira Service Management for Joiner, Mover, and Leaver (JML) lifecycle events.

Additional features displayed on this page represent capabilities supported by the integration. To learn more or enable these features, contact the Aquera Support team.

Source

The Source tab allows you to identify the HR application used by the integration and define how employee lifecycle events are processed.

The following sections are available on this tab:

  • Application Settings
  • Filter Employees

Application Settings

The Application Settings section allows you to identify the HR application instance used by the integration. The following field is available in this section for configuration:

  • HR application instance: Select the HR application connector from which employee data and lifecycle events will be retrieved for this integration. If the required connector is not available in the list, click the refresh icon next to the field to reload the available connectors.

Filter Employees

The Filter Employees section allows you to configure how employee lifecycle events are processed by the integration. The following field is available in this section for configuration:

  • Enable employee filter: Turn on this toggle button to filter employees from the source system. Only employees who match the filter criteria are considered for Freshservice ticket creation. When enabled, the Employee Filter Configuration section is displayed for further configuration.

Employee Filter Configuration

This section allows you to configure the criteria used to filter employees from the source system for Freshservice ticket creation.

The following fields are displayed for configuration:

  • Use filter for new hires: Turn on this toggle button to filter new hires from the source system. Only new hires who match the filter criteria are considered for Freshservice ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter Criteria: Select the method used to filter employees from the source system. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the source system. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the source system. For example, select Original Hire Date.
  • Use filter for terminated employees: Turn on this toggle button to filter terminated employees from the source system. Only terminated employees who match the filter criteria are considered for Freshservice ticket creation.
    When enabled, the following fields are available for configuration:
    • Employee filter criteria: Select the method used to filter terminated employees from the source system. The following is the available option:
      • Based on date: Select this to filter terminated employees using a date attribute from the source system. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter terminated employees from the source system. For example, select Termination Date.

Operations

The Operations tab enables you to configure various settings required for the integration execution. The following sections are displayed in this tab:

  • Monitor
  • Execution

Monitor

The Monitor section enables you to customize the operational and notification settings for the integration. It has the following sub-sections for configuration:

Define Notification Channel

The Define Notification Channel section enables you to configure the notification settings used by the integration. It has the following settings:

  • Enable email notifications: Select this checkbox to send email notifications for integration events. When enabled, the Notification Configuration section is displayed for further configuration.
Notification Configuration

The Notification Configuration section allows you to define notification settings for integration execution events.

If the List View toggle button is disabled, the following parameters are displayed:

  • Select event for notification: Select one or more integration events that should trigger an email notification. The following are the available options:
    • Success: Select this option to send an email notification when the integration completes successfully.
    • Failure: Select this option to send an email notification when the integration fails.
    • Hire Ticket Creation: Select this option to send an email notification for hire ticket creation events.
    • Terminate Ticket Creation: Select this option to send an email notification for terminate ticket creation events.
  • Notification Delivery Channel: Select the channel to send notifications. Currently, only Email is supported as a channel.
  • Send To: Select the recipients to send email notifications. For example, select Supervisor if you want to send email notifications to the user's supervisor. The following field is displayed when you select Custom in this field:
    • Custom Email Address: Enter the email IDs of the users to whom you want to send email notifications.
  • Subject: Enter the content that must be used as the email subject.
  • Template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the email body.
  • Attach Report: Select this checkbox if you want to attach a report to the email sent to the recipient.

To add another configuration, click the + icon adjacent to the List View toggle button.

To navigate to multiple configurations, use the arrow icons (< or >).

To delete a configuration, click the delete icon.

To view the notification configuration in list view, enable the List View toggle button.

In List View, only configured values are displayed. If you want to modify the configuration, click any value in the row and you will be redirected to the edit mode, where you can make changes.

Logging Settings

This section enables you to configure the level of detail recorded in execution logs. It has the following settings:

  • Log type: Select the log type. This will decide the level of detail to be included in logs.
    The following are the available options:

    • Minimum: Select this option to include only operation details. No GUIDs or field-level information will be included.
    • Metadata: Select this option to include operation details and field names. GUIDs are excluded.
    • Non-PII Data: Select this option to include operation details, field names, and selected non-PII values. GUIDs are excluded.
    • Correlated Attribute with Non-PII Data: Select this option to include correlated attribute, operation details, field names, and selected non-PII values.
    • Correlated Attribute with All Data: Select this option to include correlated attribute, operation details, field names, and all values, including both PII and non-PII data.
  • Log level: Select the log detail level. The following are the available options:
    • All: Select this to include all attribute details in logs.
    • Include List: Select this if you want to choose attributes to be included in logs. When selected, the following field is displayed:
      • Log — Custom Inclusion List: Enter the attributes to be included. For example, Email.
    • Exclude List: Select this if you want to choose attributes to be excluded from the logs. When selected, the following field is displayed:
      • Log — Custom Exclusion List: Enter the attributes to be excluded. For example, FirstName.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the Ticket field mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the ticket field mapper, if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.
