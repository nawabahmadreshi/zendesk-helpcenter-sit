Overview

The Aquera platform allows your organization to scale complex data management by automating data integration across resource types. Aquera's integrations facilitate the automatic provisioning, ensuring consistency across systems. It allows organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately improving efficiency in managing intricate IT infrastructures and applications.

This integration automates user lifecycle management between Workday and Papaya Global. It creates, updates, and deprovisions user accounts based on workforce events such as hires, transfers, leaves, and terminations. 

The integration also supports candidate processing, identity attribute writeback, username and email generation, group assignment, reconciliation, PII masking, and provisioning monitoring.

Prerequisites

The following are the prerequisites:

  • Admin Access to Workday: You must have admin access to your Workday instance. You can visit the Workday portal to get access to a Workday instance.
  • Tenant Account in the Aquera Admin Portal: You must have a tenant account with admin access in the Aquera Admin portal. Visit https://admin.aquera.io and register to get a tenant account. Contact your Aquera account manager to get the Aquera tenant access.
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/.
  • Configure Application Connectors in the Aquera Admin Portal: You need to configure the following application connectors in the Aquera Admin portal to integrate with Workday:
    • Workday: Ensure that you configure the Workday connector in the Aquera Admin portal. Refer to the Workday Configuration Guide for configuration details.
    • Papaya Global: Ensure that you configure the FTP Server connector in the Aquera Admin portal. Refer to the FTP Generic Configuration Guide for configuration details.

Integration Setup

This section details the configuration and mapping process for integrating Workday with Papaya Global. It outlines the steps to create the integration, set up integration preferences, and define how worker data is mapped from  Workday to Papaya Global.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Select Papaya Global / Workday.
  5. Enter a name and a description for the integration.
  6. Click Continue. The Configuration page is displayed to configure the integration.

Applications

The Applications tab enables you to configure various settings required for the integration execution. 
The following sections are displayed in this tab:

  • Application Configuration
  • SFTP Configuration

Application Configuration

The Application Configuration section allows you to identify the source application instance and the destination application instance used by the integration. The following field is available in this section for configuration:

  • Source application: Select the required source application you want to configure in this integration
  • Destination application: Select the destination application from which you want to fetch the data.

SFTP Configuration

The SFTP Configuration section allows you to configure and sync the workers data from the SFTP server. The following sections are available for configuration:

  • SFTP sync settings
  • Worker sync configuration

SFTP sync settings

This section allows you to select the required settings for the worker data sync. The following field is available in this section for configuration:

  • Enable sync worker data: Select this checkbox to configure and synchronize worker data from the CSV file. When enabled, the worker sync configuration section is displayed.

Worker sync configuration

This section allows you to configure the CSV file path, map CSV columns, and define worker data mappings required to synchronize worker data. The following fields are available for configuration:

  • File Path: Provide the relative path or the absolute path of the CSV file on the FTP server. The file extension must also be mentioned along with the filename. If the CSV file is encrypted, the extension must be accordingly modified here.
    For example: If the file is placed in the Aquera folder in the home directory and the file name is Users.csv, then the File Path can be configured in one of the following ways:
    ./Aquera/Users.csv which is the relative path
    /FileUploads/Aquera/Users.csv which is the absolute path (from the root)
    If Users.csv file has to be placed or is available directly under the home directory, then the File Path can be configured in one of the following ways:
    ./Users.csv which is the relative path
    /FileUploads/Users.csv which is the absolute path (from the root).
    Refer to the How to obtain the file path section for more details.
  • CSV Column Mapping: Enter the CSV column names to map them to the corresponding SCIM attributes in the Worker Data Mapper.

How to obtain the file path

  1. Open FileZilla (or any SFTP client).
  2. Enter the following connection details. For example, enter these fields to establish the SFTP connection.
    • Hostname - sftp.aquera.io
    • Username - hanu
    • Password - Aquera@1234
    • Port - 22
  3. Click Quickconnect to establish the SFTP connection.
  4. After the connection is established, navigate to the destination folder in the Remote Site.
  5. Create a new CSV file (or select the required output file) in that folder.
  6. Copy the complete remote file path of the created file or the existing output file from the Remote Site.
  7. In the integration, navigate to the Applications tab > Worker sync configuration section and paste the path into the File Path field.

Worker data mapper

The Papaya Global to Workday integration maps the Papaya Global and Workday attributes. You can modify only the source attributes as needed to align with your specific use case.

You can select the required column name in the CSV column mapping field to modify the value of the source attribute and construct a value to be updated in the target attribute.

All attributes marked with a red asterisk (*) indicate required fields for successful provisioning.

After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the integration.

Operations

The Operations tab enables you to configure various settings required for the integration execution. The following sections are displayed in this tab:

  • Monitor
  • Execution

Monitor

The Monitor section enables you to customize the operational and notification settings for the integration. It has the following sub-sections for configuration:

Define notification channel

This section enables you to define the notification channel used by the integration. It has the following settings:

  • Enable email notifications: Select this checkbox to send email notifications for integration events. When enabled, the Notification Configuration section is displayed for further configuration.

Notification Configuration

The Notification Configuration section allows you to define notification settings for integration execution events.

If the List View toggle button is disabled, the following parameters are displayed:

  • Template name: Enter a unique name to identify this notification template.
  • Select event for notification: Select the integration event that should trigger an email notification.
  • Notification delivery channel: Select the channel to send notifications. Currently, only two options are supported: Email and Chat.
  • Notification recipients: Select the recipients to send email notifications. For example, select Supervisor if you want to send email notifications to the user's supervisor. The following field is displayed when you select Custom in this field:
  • Custom email addresses: Enter the email IDs of the users to whom you want to send email notifications.
  • Email subject: Enter the content that must be used as the email subject.
  • Notification body template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the email body.
  • Attach Report: Select this checkbox if you want to attach a report to the email sent to the recipient.

To add another configuration, click the + icon adjacent to the List View toggle button.

To navigate to multiple configurations, use the arrow icons (< or >).

To delete a configuration, click the delete icon.

To view the notification configuration in list view, enable the List View toggle button.

In List View, only configured values are displayed. If you want to modify the configuration, click any value in the row, and you will be redirected to the edit mode, where you can make changes.

Global Operational Settings

This section enables you to configure integration-wide operational controls, reporting preferences, and monitoring settings. These settings apply to all integration runs and help control how execution details are logged, reported, and analyzed.

Logging settings

This section enables you to configure the level of detail recorded in execution logs. It has the following settings:

  • Log type: Select the log type. This will decide the level of detail to be included in logs.
    The following are the available options:

    • Minimum: Select this option to include only operation details. No GUIDs or field-level information will be included.
    • Metadata: Select this option to include operation details and field names. GUIDs are excluded.
    • Non-PII Data: Select this option to include operation details, field names, and selected non-PII values. GUIDs are excluded.
    • GUID with Non-PII Data: Select this option to include GUIDs, operation details, field names, and selected non-PII values.
    • Employee Number with Non-PII Data: Select this option to include employee numbers, operation details, field names, and selected non-PII values.
    • Employee Number with All Data: Select this option to include employee numbers, operation details, field names, and all values, including both PII and non-PII data.
  • Log level: Select the log detail level. The following is the available option:
    • All: Select this to include all attribute details in logs.

Execution

The Execution section enables you to configure advanced execution options that can be used for testing, troubleshooting, and controlling the scope of integration processing. It has the following sub-section:

Advanced Settings

Configure the following advanced settings:

  • Enable report-only mode: Turn on this toggle button to generate a report detailing the data changes that would happen, but without applying them.
  • Enable source filter: Turn on this toggle button to filter the users included in the integration. When enabled, the following fields are displayed:
    • Select filter type: Select the required filter type to filter worker details. If you do not find your filter type value in the list, click the refresh icon available next to the field to reload the filter type value.
    • Filter value: Enter the value for the selected source filter.

Tables

This section allows you to define and manage reference data used during integration to enrich or override attribute values.

Click a table row to open the Update Table window. Each row represents a key–value pair, where Name is the lookup key and Value is the mapped result used at execution time.

Managing table data

You can manage table entries using the following options:

  • Add Row: Allows you to manually add a key–value pair. For example, add Manager → Exclude to define a rule.

  • Upload CSV File: Allows bulk upload of entries. The CSV must contain two columns: NAME and VALUE, where each row represents a key–value pair.

  • Search: Allows you to quickly find specific entries within the table.

After making changes, click Save to apply updates.
