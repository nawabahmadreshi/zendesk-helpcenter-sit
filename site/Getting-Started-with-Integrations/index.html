Getting Started with Integrations

← Back to index

Overview

Aquera's integrations automate the execution of tasks or processes in a coordinated, streamlined manner. Aquera's integrations facilitate the automatic provisioning, ensuring consistency across systems. It allows organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately improving efficiency in managing intricate IT infrastructures and applications. Aquera provides numerous connectors that facilitate integrations between identity management providers and popular applications. This guide provides an overview of Aquera's integrations.

Integration Terms

The following are the integration terms:

  • Source Application: The application from which the data must be retrieved as part of the integration.
  • Target Application: The application to which the data must be synchronized as part of the integration.
  • Scheduled Trigger: The integration runs automatically based on the configured schedule.
  • Event Trigger: The integration is triggered when specific events occur in an application. An event notification occurs whenever there is a data change in an application, such as a new user creation, an existing user modification, a user activation, a user addition to a group, a user removal from a group, and so on. For the events to be sent to Aquera, webhooks may need to be set up in the corresponding application.

Types of Integrations

Aquera provides the following types of integrations:

User Integration

In User Integration, every user record newly created or modified in the source application is updated to the target application per the defined integration schedule. For further information, refer to the User Integration Setup Guide.

Bulk Integration

In bulk integration, all modified or new user records are updated in the target application as a batch per the defined integration schedule. The user data is sent to the target system as an array of user records. The Bulk Integration can be configured if the target application supports bulk or batch data import. For further information, refer to the Bulk Integration Setup Guide.

Data Integration

In data integration, you can synchronize data of any resource type from a source application to any resource type of a target application. With data integration, you can set up integrations for all resource types supported by the connector. For example, you can synchronize the Candidates resource type from a source application to the Employees resource type in a target application. For further information, refer to the Data Integration Setup Guide.

Integration Templates

You can set up integrations using the templates available on the Aquera Admin portal. The templates are designed for specific use cases and can be configured to suit your requirements. You can set up the integration to run either on a specific schedule or based on the data events in an application. Refer to Integration Templates to see the various templates provided by Aquera.

Workflow

You can set up integrations using Workflows to perform a sequence of tasks on the data across applications without writing any script. The data can be users, groups, tickets, and so on, based on the resource types supported by the application. The actions that can be performed are import, create, update, delete, and so on. JavaScript is generated internally based on the Workflow you have set up, and when the Workflow runs, this script is executed. You can set up the Workflow to run either on a specific schedule or based on the data events in an application. Refer to the Integration using Workflows for further information.

Event-Based Integration

Event-based integration runs in response to data changes in an application, such as new user creation, existing user modification, user activation, user addition to a group, user removal from a group, and so on. Event-based integrations require configuration in the application and are initiated by the application outside of the Aquera platform. Whenever an event occurs in the application, the event-based integration is triggered. The integration then processes the events sent by the application.

Integrations Listing Page

When you navigate to the Integrations module on the Aquera Admin portal, you can view the integration listing page that displays the list of all integrations created by the users in the tenant. You can search for an integration record from the search bar. 

Note: By default, all integrations are sorted by their created date.

The following are the types of views supported for listing the integrations:

  1. List View: The integration records are listed in the form of a list of rows.
  2. Card View: The integration records are listed in the form of cards.

The List and Card views display the following details:

  • Execution Icon: Used to start or stop an integration execution. Click the Execute icon to start an integration. If the integration is currently running, click the Stop icon to stop the execution.
  • Status indicator: Indicates the status of the most recent run of the integration.
    • A green color indicates the last run completed successfully
    • A red color indicates the last run failed.
    • A gray color indicates the integration has never run.
  • Applications: Displays the logos of the applications involved in the integration. 
    If more than 3 applications are involved, a + indicator appears showing the number of additional applications. Click the indicator to expand the list and view the remaining application logos.
  • Name: The name of the integration. Click on the integration name to navigate to the corresponding integration.
  • Enable / Disable Toggle: Use this toggle to control whether the integration must run automatically.
    • When turned OFF, a scheduled or event-driven integration does not run automatically. However, you can manually execute a scheduled integration. 
    • When turned ON, integration runs automatically based on its schedule or triggering events.
  • State: The trigger state of the integration:
    • For scheduled triggers, it indicates the schedule of the integration execution. If no schedule is configured for the integration, then this field shows Schedule not set.
    • For event triggers, it indicates whether the event trigger is enabled.
  • History: The execution status of the most recent five integration runs in the form of color bars. The history color bar moves from right to left for every integration run and the right-most color bar represents the most recent integration run. The following are the supported color codes:
    • Green: Indicates the integration run is a success.
    • Red: Indicates the integration run has errors.
    • Grey: Indicates the integration has never run or the integration run is canceled.
    • Blue: Indicates a currently running integration.
    • Yellow: Indicates the integration run is a failure or incomplete.
  • Author: The name of the user who created the integration.
  • Date Created: The creation date of the integration.
  • Last Edited: The date when the integration configuration was last modified. This column may not be displayed by default. Refer to the Manage Columns section for details.
  • View details: To view high-level details of an integration on a panel. If a new version of the integration is available, it shows an Upgrade option that helps you to upgrade the integration to the latest version.
  • Copy: To create a new integration by copying the configuration details of the existing integration. Provide the name of the new integration when prompted.
  • Delete: To delete an integration. 

Manage Columns

The Manage Columns icon enables you to choose which columns are displayed on the Integrations listing page.

  1. Click the Manage Columns icon at the top-right corner of the Integrations page. The list of columns that can be enabled is displayed.
  2. Select the columns you want to display and clear the ones that you want to hide.
    Note 1: The Applications and Name columns are always displayed and cannot be hidden.
    Note 2: The Last Edited column is hidden by default. If you enable it, the column remains visible only while you stay on the Integrations page. If you navigate to another page and then return, the column is hidden again by default.

Sorting Integrations

You can sort integrations on the listing page by one of the following columns:

  • Name: Sorts integrations alphabetically by the ascending or descending order of their names
  • State: Sorts integrations based on their trigger configuration: event-triggered, scheduled, or unscheduled.
  • Date Created: Sorts integrations in ascending or descending order of the integration creation dates.
  • Last Edited: Sorted by the ascending or descending order of the integration last modification dates.

Note: Sorting preferences are retained only while you remain on the Integrations page. If you navigate to another page and then return to the Integrations page, the page resets to the default sorting, and any previously applied sorting is cleared.

Filtering Integrations

You can filter the integrations based on the values in the following columns:

  • Applications: Filter integrations by selecting one or more applications involved in the integration.
  • State: Filter integrations based on their state: 
    • Enabled: List all integrations for which the Enable/Disable Toggle is On.
    • Disabled: List all integrations for which the Enable/Disable Toggle is Off.
    • Has Scheduled: Displays integrations that have a schedule configured, regardless of whether the execution toggle is On or Off.
    • Schedule not set: Displays integrations that do not have a schedule configured.
      Note 1: If you have selected both Enabled and Disabled states, an OR condition is applied, and all the integrations will be displayed.
      Note 2: If you select Enabled or Disabled together with Has Scheduled or Schedule Not Set, an AND condition is applied. Only integrations that satisfy both filter criteria are displayed.
      Note 3: Currently, there is no way to filter only the event-based integrations.
  • Author: Filter integrations created by a specific user.
  • Date Created: Filter integrations based on when they were created.
  • Last Edited: Filter integrations based on when they were last modified.

Note 1: When filters are applied across multiple columns, only integrations that satisfy all selected filter criteria are displayed.

Note 2: Filter settings are retained only while you remain on the Integrations page. If you navigate to another page and then return to the Integrations page, the filters are reset and all integrations are displayed.

Execution History

You can click the History column of an integration record to view more details about the execution history.

An Execution Report panel is displayed with the following details:

  • Applications: The applications used in the integration.
  • Execution Timeline:
    • The date and time the integration execution started.
    • The time duration of the integration execution.
    • The status of the integration execution: success, failure
    • Indication of whether the execution was triggered manually or automatically based on the schedule. If the execution was manually triggered, the name of the user who executed the integration is also displayed.
    • Download Report (CSV): Download the integration execution report as a CSV file. For user integration, this option is displayed only if the integration version is 4 or higher and the Send CSV Report configuration is enabled.
      Note: The integration needs to be executed at least once to generate a report.
    • View Logs: View the integration execution logs.
