Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

The iCIMS / Payworks integration synchronizes employees between iCIMS and Payworks. For each integration run, employees are synchronized in only one direction, based on the Sync Direction setting in the Parameters section. The integration does not synchronize employees in both directions during the same integration execution.

The following synchronization directions are available:

  • iCIMS to Payworks: It synchronizes employee lifecycle events from iCIMS to Payworks.
    When a candidate reaches a hire status in iCIMS, the integration creates the employee in Payworks. If the candidate is already matched to an existing Payworks employee, the integration updates only the fields whose values differ from iCIMS. Fields that already contain the same values are skipped. When a candidate reaches a termination status in iCIMS, the integration updates the employee's payroll status and termination date in Payworks.
    Note: This direction is normally triggered by an iCIMS webhook and processes one candidate for each event. You can also execute it manually for a specific candidate.
  • Payworks to iCIMS: It synchronizes organization and employment data from Payworks to the matching iCIMS People profile.
    If the matching iCIMS profile does not contain existing values, the integration performs an initial synchronization and writes the Payworks data to iCIMS. If values already exist, the integration updates only the fields whose values differ from Payworks. For terminated employees, the integration updates the configured termination status field in iCIMS instead of performing the standard employee data synchronization.
    This direction can be executed manually for a specific employee or scheduled to retrieve the full Payworks employee data. During a scheduled execution, each Payworks employee is matched to the corresponding iCIMS profile using the configured matching field.

Each synchronization direction has its own lifecycle operations, conditions, limits, and correlation settings. To match records between the two applications, the integration compares the configured iCIMS correlation field with the employeeNumber field in Payworks.

Key Functions

This integration supports the following functions:

  • Synchronizes employee data between iCIMS and Payworks in the configured synchronization direction.
  • Creates, updates, and terminates employees in Payworks based on hire and termination events received from iCIMS.
  • Supports writing Payworks employee information back to iCIMS after an employee is processed, when writeback is enabled.
  • Synchronizes organization and employment data from Payworks to matching iCIMS People profiles and updates the configured termination status for terminated employees.
  • Matches employee records between iCIMS and Payworks using configurable correlation attributes.
  • Supports configurable lifecycle operations, conditions, and execution limits for each synchronization direction.
  • Supports manual execution for individual records and scheduled synchronization.
  • Provides report-only execution, logging, reporting, dashboards, email notifications, and configurable masking of sensitive employee data.

Prerequisites

The following are the required setup steps before configuring this integration:

  • Tenant Account in the Aquera Admin Portal: You must have a tenant account with admin access in the Aquera Admin portal. Visit https://admin.aquera.io and register to get a tenant account. Contact your Aquera account manager to get Aquera tenant access.
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/.
  • Configure Application Connectors in the Aquera Admin Portal: You need to configure the following application connectors in the Aquera Admin portal:
    • iCIMS: You must have an iCIMS connector configured in the Aquera Admin portal. Refer to the iCIMS Configuration Guide for configuration details.
    • Payworks: You must have a Payworks connector configured in the Aquera Admin portal. Refer to the Payworks Configuration Guide for configuration details.
  • Webhook setup: You must have the required webhook created in iCIMS for the iCIMS to Payworks use case. Refer to the iCIMS Message Listener Integration Setup Guide for further details.

Integration Setup

This section details the configuration and mapping process required for this integration. It outlines the steps to create the integration and set up integration preferences.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for iCIMS / Payworks in the search box next to the Explore Templates section, and then select it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Select your iCIMS and Payworks connector instances.
  7. Click Continue. The Overview tab is displayed for further configuration.

Overview

This tab allows you to select the connectors used by the integration and configure the settings that control synchronization behavior.

The following sections are available in this tab:

  • Connections
  • Parameters

Connections

This section allows you to select the connections used for the integration. The following fields are displayed:

  • iCIMS: Select the iCIMS connector configured in the Aquera Admin portal.
  • Payworks: Select the Payworks connector configured in the Aquera Admin portal.

Note: If you do not find your connector in the list, click the refresh icon available next to the field to reload the available connectors.

Parameters

This section allows you to configure the synchronization behavior, operational features, and settings for manually processing an iCIMS candidate.

The following settings are available in this section for configuration:

Synchronization settings

This section allows you to select the direction in which employee data is synchronized.

  • Sync direction: Select the direction in which employee data is synchronized. You can select only one direction at a time:
    • iCIMS to Payworks: Creates, updates, and terminates employees in Payworks based on hire and termination events in iCIMS. This direction is triggered by the iCIMS webhook.
    • Payworks to iCIMS: Updates the matching iCIMS People profile with organization and employment data from Payworks.

Operational settings

This section allows you to configure operational integration features for the integration. The following fields are displayed:

  • Enable report-only mode: Select this checkbox to execute the integration in the report-only mode. The report-only mode generates a report to show the data that would be changed without actually making those changes.
  • Enable notifications: Select this checkbox to enable integration-related notifications. When selected, the Notifications tab is displayed for further configuration.
  • Enable dashboard generation: Select this checkbox to visualize the integration-related metrics. When selected, the Log Insights section is displayed for further configuration.
  • Enable logging: Select this checkbox to generate logs outlining data changes. When selected, the Logging section is displayed for further configuration.
  • Enable debug mode: Select this checkbox to log complete payloads and detailed field-level information for troubleshooting. iCIMS profile data may contain personal information, enable this only when required for troubleshooting.
  • Enable reporting: Select this checkbox to generate the integration report. When selected, the Reporting section is displayed for further configuration.

Manual candidate execution

Use this section to manually execute the iCIMS to Payworks sync for a single candidate. The following fields are available for configuration:

  • Candidate ID: Enter the Person ID of the candidate to process manually. When a Person ID is specified, the integration ignores the webhook payload and retrieves only the specified candidate through the API. Leave this field blank for event-driven synchronization.
  • Job ID: Enter the job ID to use for the integration. If left blank, the integration uses the job reference from the People profile.
  • Applicant workflow ID: Enter the applicant workflow ID. If left blank, the integration searches for the ID automatically. Specify the ID if the integration cannot find it through the search.
  • Run operation: Select Hire or Terminate to specify which operation the integration must perform during a manual execution.
  • Person matching attribute: Enter the applicant workflow field used to match the workflow to a person when the integration searches for the Applicant Workflow ID.

iCIMS to Payworks

This tab allows you to configure how candidates are synchronized from iCIMS to Payworks when hire or termination events are received from the iCIMS webhook.

Note: This tab is displayed only when iCIMS to Payworks is selected as the synchronization direction.

iCIMS settings

This section allows you to configure how iCIMS candidates are matched to Payworks employees and how webhook events are identified as hire or termination events. The following fields are available for configuration:

  • iCIMS correlation attribute: Select the iCIMS People attribute to match a candidate with the corresponding Payworks employee.
    Note: This field should use the same value as the corresponding correlation field configured for the Payworks to iCIMS direction. If different fields are configured, the two synchronization directions might not match the same employee records.
  • Hire status categories: Enter the iCIMS workflow status categories that identify a candidate as ready to be created or updated in Payworks. The integration matches the configured values regardless of capitalization or extra spaces.
  • Termination status categories: Enter the iCIMS workflow status categories that identify a candidate as ready to be terminated in Payworks. The integration matches the configured values regardless of capitalization or extra spaces.
  • Hire status IDs: Enter the workflow status IDs that identify a hire event. When configured, these IDs are used instead of Hire status categories to determine whether an incoming webhook event is a hire event.
  • Termination status IDs: Enter the workflow status IDs that identify a termination event. When configured, these IDs are used instead of Termination status categories to determine whether an incoming webhook event is a termination event.
  • Webhook event names: Enter the iCIMS webhook event names that the integration should process as candidate lifecycle events. If the webhook payload does not contain one of the configured event names, or if no payload is received, the integration does not process a candidate and reports the execution as no action.

Payworks settings

This section allows you to configure the Payworks field used to match an employee with the corresponding iCIMS candidate.

  • Payworks correlation attribute: Select the Payworks employee attribute to match with the corresponding iCIMS candidate.
    Note: This field should use the same value as the corresponding correlation field configured for the Payworks to iCIMS direction.

Attribute Mapper

Use this tab to map attributes between iCIMS and Payworks. The available mappings depend on the synchronization direction selected in the Overview tab.

You can modify the source attributes as needed to align the mapping with your use case.

You can also use JavaScript expressions to modify a source attribute value or construct a value to be written to the target attribute. Enter the expression directly in the source attribute field, or click the Expand icon to enter a longer expression.

Attributes marked with a red asterisk (*) are required for successful provisioning.

When iCIMS to Payworks is selected, the following mappings are available:

  • iCIMS to Payworks employee map: Defines how iCIMS candidate attributes are mapped to Payworks employee attributes when employee data is synchronized from iCIMS to Payworks. The integration uses this mapping to create new employees and update existing employees in Payworks.
  • Payworks to iCIMS writeback map: Defines how Payworks employee attributes are mapped back to iCIMS People attributes after the integration processes an employee in Payworks.
    Note: This mapping is available only when writeback is enabled.

When Payworks to iCIMS is selected, the following mapping is available:

  • Payworks to iCIMS map: Defines how Payworks employee attributes are mapped to iCIMS People attributes when employee data is synchronized from Payworks to iCIMS. The integration uses this mapping to update the corresponding iCIMS People profile during create and update operations.

After completing the source-to-target attribute mappings, click Save Changes in the upper-right corner of the page to save the integration.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the attribute mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the attribute mapper, if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.
