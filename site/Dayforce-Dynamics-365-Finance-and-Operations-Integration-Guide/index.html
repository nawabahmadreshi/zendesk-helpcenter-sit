Overview

The Aquera platform enables organizations to manage complex data integration processes by automating data synchronization across systems. Aquera's integrations help organizations streamline data management, reduce manual effort, and maintain data consistency across applications.

The Dayforce to Microsoft Dynamics 365 Finance & Operations integration facilitates the synchronization of employees, departments, jobs, and positions from Dayforce to Microsoft Dynamics 365 Finance & Operations based on the configured integration setup. When records are created or updated in Dayforce, the corresponding records are synchronized with Microsoft Dynamics 365 Finance & Operations according to the defined schedule.

To identify corresponding employee records across both systems, the integration uses the configured correlation attributes to match employee records in Dayforce with the corresponding records in Microsoft Dynamics 365 Finance & Operations.

The integration also supports managing position assignments, allowing manager relationships to be maintained based on the configured position hierarchy. 

Key Functions

The Dayforce / Dynamics 365 Finance and Operations integration provides the following functions:

  • Creates, updates, and deprovisions user accounts in Dynamics 365 Finance and Operations based on employee lifecycle events in Dayforce.
  • Creates or updates departments, jobs, and positions in Dynamics 365 using Dayforce data.
  • Supports full and incremental user syncs and allows you to schedule incremental syncs.
  • Allows you to filter employee records based on Dayforce employee attributes.
  • Generates detailed logs and reports.
  • Sends email notifications when a user is created, with the report attached.
  • Assigns an active manager to the employee.

Prerequisites

The following are the prerequisites:

  • Aquera Tenant Account: You must have a tenant account in the Aquera Admin portal. Visit https://admin.aquera.io and register to get a tenant account. Contact your Aquera account manager to get Aquera tenant access.
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/ 
  • Configure Applications in the Aquera Admin Portal: 
    • Dayforce Connector: Ensure you add and configure the Dayforce connector in the Aquera Admin portal. For details, refer to the corresponding Dayforce Configuration Guide.
    • Dynamics 365 Finance and Operations connector: Ensure you add and configure the Dynamics 365 Finance and Operations connector in the Aquera Admin portal. For details, refer to the corresponding Microsoft Dynamics 365 Finance and Operations Configuration Guide.
  • Position Occupancy Report: You must generate a Position Occupancy report in your Dayforce instance. Make sure that the report includes the following columns in addition to the default columns:
    • Job Assignment ID
    • Job ID
    • Job xRefCode
    • Job Name

Integration Setup

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations on the left panel.
  3. Click Create Integration.
  4. Search for Dayforce / Dynamics 365 Finance and Operations in the search box next to the Explore Templates section, and click it. The Create New Integration pop-up window is displayed.
  5. Enter a name and a description for the integration.
  6. Select your Dayforce and Microsoft Dynamics 365 Finance and Operations connector instances.
  7. Click Continue. The Configuration page is displayed to configure the integration.

Connections

This section allows you to select the Dayforce connector and the Dynamics 365 Finance and Operations connector for the integration. This section consists of the following fields:

  • Dayforce: Select the Dayforce application from which the integration retrieves employee, department, job, and position data.
  • Dynamics 365 Finance and Operations: Select the Dynamics 365 Finance and Operations application to which the the integration syncs the data.

Parameters

This section enables you to customize the integration settings according to your specific use case. It has the following settings:

Integration Features

Enable the following feature based on your requirements:

  • Enable employee management [ workers ]: Enable this toggle to manage the employee life cycle during synchronization from Dayforce to Microsoft Dynamics 365. When enabled, the Manage Employees section is displayed.
  • Enable cross-company employee search: Enable this toggle to allow the integration to search for an employee across all configured legal entities in Dynamics 365 before determining whether the employee is new or being transferred. If the employee is not found, a new employee record is created.

General Settings

Enable the following features based on your requirements:

  • Enable report-only mode: Enable this toggle to generate a report that shows the data that would be changed, without actually making those changes.
  • Enable logging: Enable this toggle to configure log settings. When enabled, the Logging Settings section is displayed for further configuration.
  • Enable report generation: Enable this toggle to configure the report settings. When enabled, the Reporting Settings section is displayed for further configuration.
  • Enable notifications: Select to enable integration-related notifications. When enabled, the Notification Settings section is displayed for further configuration.
  • Enable log Insights: Enable this toggle to configure the log insights settings. When enabled, the Log Insights Settings section is displayed for further configuration.
  • Enable limits on sections: Enable this toggle to set limits for creation, update, and termination operations. When enabled, the Provisioning Threshold section is displayed in the Manage Employees section.
  • Run integration in incremental mode: Enable this toggle to run the integration in incremental mode. When disabled, the integration runs in full sync.

Correlation Settings

This section allows you to configure the correlation between employee records in the source and target applications. 

Note: All parameters marked with a red asterisk (*) are mandatory.

This section consists of the following fields:

  • Source correlation attribute*: Select the correlation attribute in the source application that uniquely identifies a user record in your target application.
  • Target correlation attribute*: Select an attribute in the target application that matches the selected source attribute value to identify users.

Source Filter

Configure the following settings to filter employee records in Dayforce. This section consists of the following fields:

  • Enable employee filter: Enable this toggle to filter a specific user record from Dayforce. When enabled, the following parameters are displayed:
    • Employee filter attribute: Select an attribute to filter Dayforce users for provisioning to the Microsoft Dynamics 365 application.
      • Source filter value: Enter the value by which Dayforce users must be filtered for the attribute selected in the Employee filter attribute parameter.
    • Bulk filter attribute: Select an attribute to filter Dayforce users for bulk import to the Microsoft Dynamics 365 application.
      • Bulk filter value: Enter the value by which Dayforce users must be filtered for the attribute selected in the Bulk filter attribute parameter.

Position Sync Settings

This section allows you to configure the settings for managing employee position assignments and assigning managers during employee lifecycle synchronization. This section consists of the following fields:

  • Enable employee position management [ Workers ]: Enable this toggle to manage employee position assignments during employee lifecycle synchronization. When enabled, the following toggle is displayed:
    • Enable manager position assignment: Enable this toggle to assign an active manager to the employee based on the configured position hierarchy. When enabled, the Manager Assignment Settings section is displayed.

Manager Assignment Settings

This section allows you to configure the manager hierarchy used to assign an active manager to the user. This section is displayed only when the Enable manager position assignment toggle is enabled in the Position Sync Settings section.

This section consists of the following fields:
Note: All parameters marked with a red asterisk (*) are mandatory.

  • Max Manager Hierarchy Depth*: Enter the maximum number of hierarchy levels that the integration must check to find an active manager to whom the user can be assigned.
    For example: If you enter 3, the integration checks up to three levels in the manager hierarchy to find an active manager. It first checks the employee's direct manager. If the direct manager is inactive, it checks the direct manager's manager. If that manager is also inactive, it checks the next manager in the hierarchy. If an active manager is found at any of these levels, the employee is assigned to that manager. Otherwise, the integration performs the action configured in the Fallback manager action field.
  • Position occupancy report ID: Enter the ID of the Dayforce Position Occupancy report that the integration uses to retrieve the position hierarchy.
  • Report column - Employee position number: Enter the column name in the report that contains the employee's position reference code.
  • Report column - Manager position number: Enter the column name in the report that contains the manager's position reference code.
  • Fallback manager action*: Select the action to perform when an active manager is not found within the specified hierarchy levels. The following options are available:
    • Leave unassigned: Select this option to leave the user without an assigned manager.
    • Use default manager: Select this option to assign the user to the default manager.
      • Fallback manager personnel number: Enter the personnel number of the default manager to whom the user must be assigned.
    • Assign to admin: Select this option to assign the user to the admin.
      • Fallback admin personnel number: Enter the personnel number of the admin to whom the user must be assigned.

Position Hierarchy Settings

This section allows you to configure the position hierarchy settings. This section consists of the following fields:

  • Create position hierarchy type: Enable this toggle to create relationships between employee positions and their corresponding manager positions in D365 using the Dayforce Position Occupancy report, based on the configured hierarchy type. When enabled, the Hierarchy type field is displayed.
    • Hierarchy type: Enter the hierarchy type used to define relationships between positions in D365 based on the Dayforce Position Occupancy report. The default value is Line. Currently, the integration supports only the Line hierarchy type.
  • Report parameters (optional): Enter additional parameters to filter the data retrieved from the report.

Provisioning Settings

This section allows you to configure the settings that control how employee records are provisioned and managed in the target application. 

This section consists of the following fields:
Note: All parameters marked with a red asterisk (*) are mandatory.

  • Exclude inactive employees: Enable this toggle to exclude inactive employees during account creation. When enabled, the following fields are displayed:
    • Exclude inactive employees since: Enter the date and time from which inactive employees must be excluded, based on the selected time zone.
  • Do not sync future hires: Enable this toggle to exclude future hires from synchronization until their specified hire date and time are reached.
  • Time zone: Select the time zone used to determine when inactive employees are excluded and when future hires are included in synchronization.
  • Onboard/Offboard employees based on: Select the option that determines how employees are onboarded or offboarded. The following options are available:
    • Based on the Status: Select this option to onboard or offboard employees based on their status. The following fields are displayed:
      • Statuses to be considered as active: Select the statuses for which employees must be considered active.
      • Statuses to be considered as Inactive: Select the statuses for which employees must be considered inactive.
    • Based on the Date: Select this option to onboard or offboard employees based on the configured dates. The following fields are displayed:
      • Hire date field: Select the Dayforce field that must be used by the integration to determine when an employee must be onboarded. The available options are HireDate, OriginalHireDate, and StartDate.
      • Termination date field: Select the Dayforce field that must be used by the integration to determine when an employee must be terminated. The available options are TerminationDate and LastWorkingDate.
  • Create employee condition*: Select the condition under which employees must be created in the target application. The following are the available options:
    • All: Create all employees.
    • Active only: Create only active employees.
    • Inactive only: Create only inactive employees.
    • None: Disable the employee creation.
    • Custom: Creates employees based on a custom condition. When selected, the following field is displayed:
      • Custom create condition: Enter the JavaScript expression that defines the condition based on which an employee must be created in the target application.
  • Update employee condition*: Select the condition under which employees must be updated in the target application. The following are the available options:
    • All: Update all employees.
    • Active only: Update only active employees.
    • Inactive only: Update only inactive employees.
    • None: Disable the employee update.
    • Custom: Updates employees based on a custom condition. When selected, the following field is displayed:
      • Custom update condition: Enter the JavaScript expression that defines the condition based on which an employee must be updated in the target application.
  • Terminate / Deactivate condition*: Select the condition under which employees must be terminated/deactivated in the target application. The following are the available options:
    • All: Terminate/Deactivate all employees.
    • Inactive only: Terminate/Deactivate only inactive employees.
    • None: Disable employee termination/deactivation.
    • Custom: Terminate/Deactivate employees based on a custom condition. When selected, the following field is displayed:
      • Custom deactivate condition: Enter the JavaScript expression that defines the condition based on which an employee must be terminated/deactivated in the target application.

Provisioning Threshold

This section allows you to configure the limits for creation, update, and termination operations. This section is displayed only when the Enable limits on sections toggle is enabled in the Parameters section. 

This section consists of the following fields:

  • Create limit: Enter the maximum number of employee records allowed to be created per integration run. 
  • Update limit: Enter the maximum number of employee records allowed to be updated per integration run. 
  • Terminate limit: Enter the maximum number of employee records allowed to be terminated per integration run.

Note: The following values can be specified for the Create limit, Update limit, and Terminate limit fields:

  • Zero: Enter 0 to disable the corresponding operation.
  • Positive number: Enter a positive number to limit the corresponding operation to the specified number.
  • Negative number: Enter a negative number to perform the corresponding operation without a limit.

Attribute Map

The attribute mapper is displayed only when the Enable employee lifeCycle management [ Workers ] toggle is enabled in the Parameters section.

The Attribute Map tab defines how data is mapped from the source to the target application. The default mapping of attributes is displayed on the page. The source attributes are listed on the left side and the target attributes are listed on the right side of the page.

You can modify only the source attributes as needed, to align with your specific use case.

You can write JavaScript expressions to modify the value of the source attribute and construct a value to be updated in the target attribute. Write the expression directly in the source attribute field or click the Expand icon in the source attribute field to write a long-expression.

Tables

Tables allow you to define custom values for target attributes when the required values cannot be mapped directly from the source application. You can create a table containing the required mappings and reference it using an expression in the Attribute Mapper to populate the corresponding target attribute. You can add multiple tables based on your integration requirements.

For example: Suppose Dayforce provides a country reference code, but Microsoft Dynamics 365 Finance & Operations requires a Legal Entity ID. You can create a table and map the country reference codes to their corresponding Legal Entity IDs and use the following expression in the Attribute Mapper to populate the required value in the target application.
 

TABLE.legalentityid?.[dayforce.Employee["WorkAssignments.Location.LegalEntity.Country.XRefCode"]]

The table setup and functionality are the same as that in the User Integration. Refer to the Adding Tables in Integration section in the Using Tables in Integration guide for details.
