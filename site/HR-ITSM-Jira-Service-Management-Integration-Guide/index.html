HR / ITSM – Jira Service Management Integration Guide

← Back to index

This guide applies to the latest public version of the integration (version 1.1.0).

Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

This integration automates identity-driven IT service management workflows by connecting your HR system with Jira Service Management (JSM). The integration retrieves workforce data from the selected HR application, detects employee lifecycle events based on the configured lifecycle rules, and automatically creates Jira Service Management tickets for the configured lifecycle events.

The integration supports configurable ticket creation for employee lifecycle events, such as new hires and terminations. It also allows you to control when tickets are created, map employee information to Jira ticket fields, and customize how employees are matched between the HR system and Jira Service Management.

Note: Currently, only Dayforce and Oracle Cloud HCM applications are supported as source HR applications.

Key Functions

This integration automates Jira Service Management ticket creation for employee lifecycle events with the following primary capabilities:

  • Retrieves workforce data from the configured HR application.
  • Detects employee lifecycle events based on configured rules.
  • Creates Jira Service Management tickets for selected employee lifecycle events.
  • Allows custom employee matching between the HR application and Jira Service Management.
  • Maps HR attributes to Jira Service Management ticket fields.
  • Supports configurable rules to determine when Jira Service Management tickets are created for employee lifecycle events.
  • Sends event notifications through email.
  • Generates detailed logs, operational reports, and execution summaries.

Integration Setup

This section explains how to configure the integration to synchronize employee lifecycle events from an HR application with Jira Service Management and automatically create tickets for the configured lifecycle events.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for HR / ITSM - JSM in the search box next to the Explore Templates section and click it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Source
  • Service Desk
  • Operations
  • Features
  • Tables
  • Schedule

Overview

The Overview tab displays general information about the integration, including its purpose and supported capabilities. It provides a high-level overview of how the integration automates ticket creation for employee lifecycle events.

Source

The Source tab allows you to select the HR application used by the integration and define which employees are considered for Jira Service Management ticket creation.

The following sections are available on this tab:

  • Application Settings
  • Filter Employees
  • Filter Candidates

Application Settings

The Application Settings section allows you to identify the HR application instance used by the integration. The following field is available in this section for configuration:

  • HR application instance: Select the HR application connector from which employee data and lifecycle events will be retrieved for this integration. If the required connector is not available in the list, click the refresh icon next to the field to reload the available connectors.
  • Include additional properties from Dayforce: Select the additional properties that you want to include in this integration. If you do not select any option in this dropdown menu, the integration will use default properties. The integration considers EmployeeManagers, EmploymentStatuses, Addresses, WorkAssignments, Contacts, Roles, OrgUnitInfos, SSOAccounts, and EmployeeProperties as default properties.

Filter Employees

This section allows you to define which employees from the HR application are considered for Jira Service Management ticket creation. The following field is available in this section for configuration:

  • Enable employee filter: Turn on this toggle button to filter employees considered for Jira Service Management ticket creation. Only employees who match the configured filter criteria are processed. When enabled, the Employee Filter Configuration section is displayed for further configuration.

Employee Filter Configuration

This section allows you to configure the criteria used to filter employees from the HR application for Jira Service Management ticket creation.

The following fields are displayed for configuration:

  • Use filter for new hires: Turn on this toggle button to filter new hires from the HR application. Only new hires who match the filter criteria are considered for Jira Service Management ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Hire Date.
    • Employee filter lookback period (days): Enter the number of past days to consider when filtering new hires.
  • Use filter for terminated employees: Turn on this toggle button to filter terminated employees from the HR application. Only terminated employees who match the filter criteria are considered for Jira Service Management ticket creation.
    When enabled, the following fields are available for configuration:
    • Employee filter criteria: Select the method used to filter terminated employees from the HR application. The following is the available option:
      • Based on date: Select this to filter terminated employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter terminated employees from the HR application. For example, Termination Date.
    • Employee filter lookback period (days): Enter the number of past days to consider when filtering terminated employees from the HR application.
  • Temporarily disable account on leave: Enable this option to create or update a ticket when an employee is on the selected leave types. When enabled, the following field is displayed for further configuration:
    • Leave types for ticket creation: Select the leave types that trigger ticket creation or updates. If you do not find your leave type in the list, click the refresh icon available next to the field to reload the leave types.
  • Use filter for rehires: Turn on this toggle button to filter rehires from the HR application. Only rehires who match the filter criteria are considered for Jira Service Management ticket creation. When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
        • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Rehire Date.

Filter Candidates

The Filter Candidates section allows you to configure how candidate lifecycle events are processed by the integration. The following field is available in this section for configuration:

  • Enable candidate filter: Turn on this toggle button to filter candidates from the source system. Only candidates who match the filter criteria are considered for Jira Service Management ticket creation. When enabled, the Candidate Filter Configuration section is displayed for further configuration.

Candidate Filter Configuration

This section allows you to configure the criteria used to filter candidates from the source system for Jira Service Management ticket creation.

The following fields are displayed for configuration:

  • Use filters and controls for candidates: Turn on this toggle button to apply custom filter rules and controls for candidates that trigger account creation in the Jira Service Management ticket creation. When enabled, the following fields are displayed for further configuration.
    • Candidate filter criteria: Select the method used to filter employees from the source system. The following is the available option:
      • Based on status: Select this to filter candidates using a status from the source system. Only matching employees are considered for ticket creation.
    • Status to filter candidates: Select the candidate statuses that trigger account creation in the Jira Service Management ticket creation.

It allows you to select the Jira Service Management instance, define which lifecycle events create tickets, configure ticket settings, and map HR attributes to Jira ticket fields.

The following sections are displayed in this tab:

  • Channel
  • JML Ticket Creation

Channel

This section enables you to identify the Jira Service Management application used by the integration to create tickets. The following field is available in this section for configuration:

  • Service desk application instance: Select the Jira Service Management application connector where the integration will create tickets. If the required connector is not available in the list, click the refresh icon next to the field to reload the configured application connectors.
  • Enable messaging: Enable this option to allow the integration to send messages and notifications through the configured messaging channel. When enabled, the Messaging Application Settings section is displayed for further configuration.

Messaging Application Settings

  • Enable Slack notifications: Enable this option to send Slack notifications when the configured lifecycle event is detected. When enabled, additional Slack notification settings are displayed: 
    • Slack application instance: Select the Slack application instance configured in Aquera to send lifecycle event notifications.
  • Enable Microsoft Teams notifications: Enable this option to send Microsoft Teams notifications when the configured lifecycle event is detected. When enabled, additional Teams notification settings are displayed: 
    • Microsoft Teams application instance: Select the Microsoft Teams application instance configured in Aquera to send lifecycle event notifications.

JML Ticket Creation

This section enables you to configure how Jira Service Management tickets are created for employee lifecycle events. The following field is displayed in this section:

  • Enable ticket creation: Turn on this toggle button to automatically create Jira Service Management tickets for employee lifecycle events. When enabled, the Ticket Creation Configuration section is displayed for configuration.

Ticket Creation Configuration

This section allows you to configure how Jira Service Management tickets are created for a selected employee lifecycle event.

If the List View toggle button is disabled, the following parameters are displayed:

  • Select event type: Select the employee lifecycle event for which Jira Service Management tickets should be created. The following lifecycle events are available for selection:
    • Hire: Select this option if you want to create Jira Service Management tickets when a new hire event is detected.
    • Terminate: Select this option if you want to create Jira Service Management tickets when a termination event is detected.
  • Event timing: Define when the Jira Service Management ticket should be created for the selected lifecycle event. The following are the available options:
    • When detected: Select this if you want to create tickets immediately after the lifecycle event is detected.
    • Before start date: Select this if you want to create tickets before the actual start date of the employee.
    • On start date: Select this if you want to create tickets on the employee's start date.
    • After start date: Select this if you want to create tickets after the actual start date of the employee.
      When you select Before start date or After start date, the following field is displayed to define the number of days:
      • Days Before / After Joining Date: Enter the number of days before or after the selected lifecycle event date when the ticket should be created. For example, entering 7 with Before start date selected creates the ticket seven days before the employee's effective start date.
  • Enable conditional event detection: Turn on this toggle button to create Jira Service Management tickets only for employees who satisfy a defined condition. When enabled, the following field is displayed:
    • Ticket creation condition: Enter a condition to control which employees trigger Jira Service Management ticket creation. Only employees who satisfy this condition are considered for ticket creation. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.
  • Enable ticket creation: Turn on this toggle button to create Jira Service Management tickets for the selected lifecycle event. When enabled, the following fields are displayed for further configuration:
    • Space: Select the Jira Service Management space where tickets will be created. For example, select My Team if you want the tickets to be created in the My Team space.
      If the required space is not available, click the Refresh icon next to the field to reload the available spaces.
    • Work type: Select the work type that should be used when creating tickets. For example, Task. If the required work type is not available, click the Refresh icon next to the field to reload the available work types.
    • Enable to extend schema with Jira request type: Turn on this toggle button to retrieve additional request fields associated with the selected Jira Request Type. When enabled, the additional available ticket fields are retrieved and available for mapping in the Onboarding Ticket Field Mapper.
    • Request Type: Select the Jira Service Management request type used when creating tickets for the selected lifecycle event. If the required request type is not available, click the Refresh icon next to the field to reload the available request types.
    • Resolved Status Category: Select the Jira status category that represents completed requests. The selected status category is used by the integration when evaluating existing tickets. If the required status category is not available, click the Refresh icon next to the field to reload the available status categories.
    • Customize how users are matched across systems: Turn on this toggle button to configure custom employee matching. When enabled, the following fields are displayed.
      • Select How Employees Are Matched Between Source and Target: Select the method used to correlate employees between the HR application and Jira Service Management.
      • Select Source Attribute for Matching the Employee: Select the HR application attribute used to uniquely identify employees.
      • Select Target Attribute for Matching the Employee: Select the Jira Service Management field used to uniquely identify employees.
    • Onboarding Ticket Field Mapper: This section allows you to map HR attributes to Jira Service Management ticket fields. Source attributes are displayed on the left side, and Jira ticket fields are displayed on the right side of the page. You can modify only the source attributes as needed, to align with your specific use case. JavaScript expressions can be used to transform source attribute values and construct the values that are updated in the target attributes. You can enter the expression directly in the source attribute field or click the expand icon to write a longer expression. The Search Attributes field allows you to search for source attributes.
      Attributes marked with a red asterisk (*) are mandatory for successful execution.
      After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the configuration.
  • Enable ticket auto-update: Enable this option to automatically update the ticket when its status matches the configured update criteria. When enabled, the following field is displayed:
    • Ticket statuses to evaluate for auto-update: Select the ticket statuses that the integration evaluates before automatically updating a ticket. For example, select In Progress.
  • Enable ticket auto-close: Enable this option to automatically close the ticket when its status matches the configured close criteria. When enabled, the following fields are displayed:
    • Ticket statuses to evaluate for auto-close: Select the ticket statuses that the integration evaluates before automatically closing a ticket. For example, select Waiting for Customer.
    • Ticket close status: Select the status assigned to the ticket when it is automatically closed. The following are the available options:
      • To Do: Select this option to assign the ticket the To Do status after auto-close.
      • In Progress: Select this option to assign the ticket the In Progress status after auto-close.
      • Done: Select this option to assign the ticket the Done status after auto-close.
  • Send ticket creation request by email: Enable this option to send an email request with employee lifecycle event details to the configured recipients. Recipients can use the email to create the required ticket in the service desk application. When enabled, additional configuration options are displayed:
    • Ticket creation email subject: Enter the content that must be used as the email subject in the notifications sent for ticket creation.
    • Ticket creation email recipients: Select one or more recipient groups to whom the email notifications will be sent for ticket creation.
    • Ticket creation email template: Enter the content that must be used as the email body in the notifications sent for ticket creation.
  • Send ticket creation request by Slack: Enable this option to send a Slack message with employee lifecycle event details to the configured channel. When enabled, additional Slack settings are displayed: 
    • Select channel: Select the Slack channel within the selected team where ticket creation notifications will be posted. If you do not find your channel in the list, click the refresh icon available next to the field to reload the available channels.
    • Slack notification template: Enter the content that must be used as the notification message sent for ticket creation.
  • Send ticket creation request by Microsoft Teams: Enable this option to send a Microsoft Teams message with employee lifecycle event details to the configured team. When enabled, additional Teams notification settings are displayed: 
    • Select team: Select the Microsoft Teams team where ticket creation notifications will be posted. If you do not find your team in the list, click the refresh icon available next to the field to reload the available teams.
    • Select channel: Select the Microsoft Teams channel within the selected team where ticket creation notifications will be posted. If you do not find your channel in the list, click the refresh icon available next to the field to reload the available channels.
    • Teams notification template: Enter the content that must be used as the notification message sent for ticket creation.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the Ticket field mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the ticket field mapper if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.
