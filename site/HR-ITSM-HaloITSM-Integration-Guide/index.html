Overview

The Aquera platform enables your organization to scale complex data management by automating data integration across various resource types. Aquera's integrations facilitate automatic provisioning, ensuring consistency across systems. It enables organizations to streamline processes, dynamically scale resources, and automate repetitive tasks, ultimately enhancing efficiency in managing complex IT infrastructures and applications.

This integration automates identity-driven IT service management workflows by connecting your HR system with HaloITSM. The integration retrieves workforce data from the selected HR application, detects employee lifecycle events based on the configured lifecycle rules, and automatically creates HaloITSM tickets for the configured lifecycle events.

The integration supports configurable ticket creation for employee lifecycle events, such as new hires and terminations. It also allows you to control when tickets are created, map employee information to HaloITSM ticket fields, and customize how employees are matched between the HR system and HaloITSM.

Key Functions

This integration automates HaloITSM request creation for employee lifecycle events with the following primary capabilities:

  • Retrieves workforce data from the configured HR application.
  • Detects employee lifecycle events and Candidate lifecycle events based on configured rules.
  • Creates HaloITSM tickets for selected employee lifecycle events.
  • Allows custom employee matching between the HR application and HaloITSM.
  • Maps HR attributes to HaloITSM request fields.
  • Supports configurable rules to determine when employee lifecycle events are processed for ticket creation.
  • Sends event notifications through email.
  • Generates detailed logs, operational reports, and execution summaries.

Integration Setup

This section explains how to configure the integration to synchronize employee lifecycle events from an HR application with HaloITSM and automatically create requests for the configured lifecycle events.

Create Integration

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations from the left side panel.
  3. Click Create Integration.
  4. Search for HR / ITSM - HaloITSM in the search box next to the Explore Templates section and click it to create a new integration.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Once created, the following tabs are displayed:

  • Overview
  • Features
  • Source
  • Service Desk
  • Operations
  • Tables
  • Schedule

Features

The Features tab provides an overview of the functional capabilities supported by the integration. The following section is displayed on this tab:

Service Desk Bridge

The Service Desk Bridge section controls the functional capabilities supported by the integration.

The following features are available for this integration:

  • Enable HCM Bridge: This is enabled by default to process employee lifecycle events from the configured HaloITSM connector.
  • Enable Service Desk Bridge: This is enabled by default to create and manage HaloITSM requests based on employee lifecycle events.
  • Enable Employee Lifecycle: This is enabled by default to process employee lifecycle events, including onboarding, employee changes, and termination events.

Additional features displayed on this page represent capabilities supported by the integration. To learn more or enable these features, contact the Aquera Support team.

Employee Filter Configuration

This section allows you to configure the criteria used to filter employees from the HR application for HaloITSM ticket creation.

The following fields are displayed for configuration:

  • Use filter for account creation: Turn on this toggle button to filter users from the HR application. Only new hires who match the filter criteria are considered for HaloITSM ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter criteria: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Hire Date.  If you do not find your data attribute in the list, click the refresh icon available next to the field to reload the available attributes.
  • Use filter for account changes: Turn on this toggle button to filter users from the HR application.  Only users who match the defined rules are considered for HaloITSM ticket creation. When enabled, the following fields are displayed for further configuration:
    • Select Attributes to Synchronize: Select the user profile attributes to synchronize from the source system to the target system. If you do not find your attribute in the list, click the refresh icon available next to the field to reload the available attributes.
  • Use filter for account termination: Turn on this toggle button to filter terminated employees from the HR application. Only terminated employees who match the filter criteria are considered for HaloITSM ticket creation.
    When enabled, the following fields are available for configuration:
    • Employee filter criteria: Select the method used to filter terminated employees from the HR application. The following is the available option:
      • Based on date: Select this to filter terminated employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter terminated employees from the HR application. For example, Termination Date. If you do not find your data attribute in the list, click the refresh icon available next to the field to reload the available attributes.
  • Use filter for temporary account disable: Turn on this toggle button to filter users from the HR application.  Only users who match the defined rules are considered for HaloITSM ticket creation. When enabled, the following fields are displayed for further configuration:
    • Leave types that trigger account deactivation: Select the leave types that trigger account deactivation. The integration deactivates accounts only for users whose leave type matches the selected values.
  • Use filter for account rehire: Turn on this toggle button to filter rehires from the HR application. Only rehires who match the filter criteria are considered for HaloITSM ticket creation.
    When enabled, the following fields are displayed for configuration:
    • Employee filter to trigger rehire: Select the method used to filter employees from the HR application. The following is the available option:
      • Based on date: Select this to filter employees using a date attribute from the HR application. Only matching employees are considered for ticket creation.
    • Date attribute to filter employees: Select the date attribute used to filter employees from the HR application. For example, Hire Date. If you do not find your data attribute in the list, click the refresh icon available next to the field to reload the available attributes.

Ticket Creation Configuration

This section allows you to configure how HaloITSM tickets are created for a selected employee lifecycle event.

If the List View toggle button is disabled, the following parameters are displayed:

  • Look-back window (Days): Enter the number of past days to consider for ticket creation. Leave this field blank to process all matching employees.
  • Select event type: Select the employee lifecycle event for which HaloITSM tickets should be created. The following lifecycle events are available for selection:
    • Hire: Select this option if you want to create HaloITSM tickets when a new hire event is detected.
    • Terminate: Select this option if you want to create HaloITSM tickets when a termination event is detected.
  • Event timing: Define when the HaloITSM ticket should be created for the selected lifecycle event. The following are the available options:
    • When detected: Select this if you want to create tickets immediately after the lifecycle event is detected.
    • Before start date: Select this if you want to create tickets before the actual start date of the employee.
    • On start date: Select this if you want to create tickets on the employee's start date.

    • After start date: Select this if you want to create tickets after the actual start date of the employee.

      When you select Before start date or After start date, the following field is displayed to define the number of days:
       

      • Days Before / After Joining Date: Enter the number of days before or after the selected lifecycle event date when the ticket should be created. For example, entering 7 with Before start date selected creates the ticket seven days before the employee's effective start date.
  • Enable conditional event detection: Turn on this toggle button to create HaloITSM tickets only for employees who satisfy a defined condition. When enabled, the following field is displayed:
    • Ticket creation condition: Enter a condition to control which employees trigger HaloITSM ticket creation. Only employees who satisfy this condition are considered for ticket creation. You can describe the condition in plain language and use AI Assist to convert it into a filter expression. For details on how to set up an AI prompt, review and analyze the output generated by the AI Assistant, refer to the Using Aquera AI Assistant for Generating Unique Values in Integrations guide.
  • Enable ticket creation: Turn on this toggle button to create HaloITSM tickets for the selected lifecycle event. When enabled, the following fields are displayed for further configuration:
    • Ticket type: Select the ticket type that should be used when creating tickets. If the required ticket type is not available, click the Refresh icon next to the field to reload the available ticket types.
      The following are the available options:
      • Problem: Select this option to create HaloITSM tickets of the problem type to investigate the root cause of recurring issues.
      • Incident: Select this option to create HaloITSM tickets of the incident type to report and resolve service issues.
      • Question: Select this option to create HaloITSM tickets of the question type to manage user inquiries and information requests.
      • Task: Select this option to create HaloITSM tickets of the task type to track and complete assigned work.
    • Ticket type name: Select the ticket type name that should be used when creating tickets. If the required ticket type is not available, click the Refresh icon next to the field to reload the available ticket types.
    • Assign an agent: Turn on this toggle button to perform the onboarding process using an agent or service account. When enabled, the agents field is displayed.
      • Agent: Select the agent you want to assing for the generated ticket.
    • Assign an end user: Turn on this toggle button to identify the end user in the source system before starting the onboarding workflow. When enabled, the following fields are displayed for further configuration.
      • Mark current user as a end user: Turn on this toggle to identify the request submitted by a user must be considered as the end user during the onboarding process.
      • End user details: Select the end user from the dropdown list from the source system.
  • Customize how users are matched across systems: Turn on this toggle button to configure custom employee matching. When enabled, the following fields are displayed.
    • Select how employees are matched between Source and Target: Select the method used to correlate employees between the HR application and HaloITSM.
    • Select source attribute for matching the employee: Select the HR application attribute used to uniquely identify employees.
    • Select Target attribute for matching the employee: Select the HaloISM field used to uniquely identify employees.
  • Auto close the ticket: Turn on this  toggle button to automatically close the HaloITSM JML ticket after all actions for the employee lifecycle event are completed successfully. When selected, the following fields are displayed.
    • Ticket status to evaluate for auto close: Select the HalloITSM ticket statuses that should be evaluated to determine whether a ticket is eligible for automatic closure. If you do not find your ticket status in the list, click the refresh icon available next to the field to reload the available ticket statuses.
    • Ticket close status: Select the HaloITSM ticket status to apply when the integration automatically closes the ticket.
  • Onboarding Ticket Field Mapper: This section allows you to map HR attributes to HaloITSM ticket fields. Source attributes are displayed on the left side, and HaloITSM ticket fields are displayed on the right side of the page. You can modify only the source attributes as needed to align with your specific use case. JavaScript expressions can be used to transform source attribute values and construct the values that are updated in the target attributes. You can enter the expression directly in the source attribute field or click the expand icon to write a longer expression. The Search Attributes field allows you to search for source attributes.
    Attributes marked with a red asterisk (*) are mandatory for successful execution.
    After the source-to-target attribute mapping is completed, click Save Changes at the top-right corner of the page to save the configuration.
  • Enable email notification: Turn on this toggle button to sent email notification when a hire event occurs. When enabled, the following fields are displayed:
    • Subject: Enter the content that must be used as the email subject.
    • Notification recipients: Select the recipients to send email notifications. For example, select Supervisor if you want to send email notifications to the user's supervisor. The following field is displayed when you select Custom in this field:
      • Custom email address: Enter the email IDs of the users to whom you want to send email notifications.
    • Email notification template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the email body.
  • Enable slack notification: Turn on this toggle button to send slack notification when a hire event occurs. When enabled, the following fields are displayed:
    • Select Channel: Select the required channel where the hire notification should be posted. If you do not find the required channel in the list, click the refresh icon available next to the field to reload the available channel.
    • Slack notification template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the notification body.
  • Enable teams notification: Turn on this toggle button to sent teams notification when a hire event occurs. When enabled, the following fields are displayed:
    • Select team: Select the required teams where the hire notification should be posted. If you do not find the required teams in the list, click the refresh icon available next to the field to reload the available teams.
    • Select Channel: Select the required channel where the hire notification should be posted. If you do not find the required channel in the list, click the refresh icon available next to the field to reload the available channel.
    • Teams notification template: Enter the content to be used as the notification body. You can use available customization features, such as variables and Improve Description to configure the notification body.

Tables

In the Tables tab, you can add tables to the integration. Tables are used to define custom source attributes and synchronize them with the target application. If the required data is not available in the source application, you can define it in a table and use it to update the target application. Once defined, the table can be referenced in attribute mapping expressions to set or update values automatically.

For example, to set the timezone attribute of users in the target application to Europe/Paris, create a table during integration setup with timezone as the attribute name and Europe/Paris as the value. Once defined, reference the table in the source attribute of the Ticket field mapper using the following format:
TABLE.<table_name>.<key_name> or TABLE.<table_name>[<key_name>]

For example: TABLE.test.timezone

Note: You can configure expressions with nested tables in the ticket field mapper if required.
For example: TABLE.UserHireRecord[TABLE.UserRecord["empDate"]]

Refer to the Using Tables in Integrations guide for more details.
