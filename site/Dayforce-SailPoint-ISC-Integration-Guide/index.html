Dayforce / SailPoint ISC Integration Guide

Overview

Aquera's integrations facilitate automatic user provisioning, helping ensure consistency across systems. They enable organizations to streamline user lifecycle processes and automate repetitive tasks, improving efficiency in managing user identities and access.

With this integration, employee records created or updated in Dayforce are automatically synchronized with SailPoint based on the configured schedule.

This guide explains how to configure the Dayforce to SailPoint integration and synchronize employee data from Dayforce to SailPoint.

Key Functions

The Dayforce / SailPoint integration provides the following functions:

  • Creates, updates, and deprovisions user accounts in SailPoint based on employee lifecycle events in Dayforce.
  • Supports full and incremental syncs and allows you to schedule recurring full syncs.
  • Enables you to filter Dayforce records based on the values configured.
  • Generates detailed logs and reports.
  • Sends notifications about successful and failed integration run events via email.

Prerequisites

The following are the prerequisites:

  • Aquera Tenant Account: You must have a tenant account in the Aquera Admin portal. Visit https://admin.aquera.io and register to get a tenant account. Contact your Aquera account manager to get Aquera tenant access.
    Note: If your organization is in the EU region, use the following URL to register: https://admin.eu.aquera.io/ 
  • Configure Applications in the Aquera Admin Portal: 
    • Dayforce Connector: Ensure you add and configure the Dayforce connector in the Aquera Admin portal. For details, refer to the corresponding Dayforce Configuration Guide.
    • SailPoint Connector: Ensure you add and configure the SailPoint connector in the Aquera Admin portal. For details, refer to the corresponding SailPoint Identity Security Cloud Configuration Guide.
  • Source application in SailPoint: You must create a source application of type SCIM 2.0 in your SailPoint Identity Security Cloud instance. Make sure that provisioning is enabled as shown below.
  • Scopes: Make sure that the following scopes are enabled while generating a token: 
    • idn:accounts:read 
    • idn:accounts:manage
    • idn:accounts-state:manage
    • idn:sources:read
    • idn:sources:manage
    • idn:source-schema:read
    • idn:source-schema:manage

Integration Setup

Perform the following steps to create the integration:

  1. Log in to the Aquera Admin portal.
  2. Navigate to Integrations on the left panel.
  3. Click Create Integration.
  4. Search for Dayforce / Sailpoint ISC in the search box next to the Explore Templates section, and click it. The Create New Integration pop-up window is displayed.
  5. Enter a name and a description for the integration.
  6. Click Continue.

Dayforce

The Dayforce tab allows you to select the Dayforce connector used by the integration. The following section is displayed:

  • Application Settings

Application Settings

The Application Settings section specifies the Dayforce application instance that is used by the integration. The following field is available:

  • Dayforce Application Instance: Select the Dayforce application from which the integration retrieves the data.

Sailpoint

The SailPoint tab provides the configuration options for selecting the SailPoint connector, configuring the full sync schedule, upsert condition and mapping attributes between Dayforce and SailPoint.
The following sections are displayed:

  • Application Settings
  • Configuration
  • Mapping

Application Settings

The Application Settings section specifies the SailPoint application instance that is used by the integration. The following fields are available:

  • SailPoint Application Instance: Select the SailPoint application from which the integration retrieves the data.
  • SailPoint Source: Select the SailPoint source application that you have configured in the SailPoint instance.
  • Enable recurring full sync: Select this checkbox to run a full sync based on the configured schedule. The following. When enabled, the following fields are displayed.
    • Full sync schedule: Select the option to determine how frequently the full sync must run.
    • Start schedule from: Select the option that determines when the full sync must begin.
      • Start now: Select this option to begin the full sync immediately.
      • From specific date: Select this option to specify the date from which the full sync must begin. When selected, the following field is displayed:
        • Start date: Select the date from which the full sync must begin.
    • Start time: Select the time from which the full sync should begin.
    • Disable incremental sync: Enable this checkbox to run the integration only in full sync mode and not in incremental mode.
  • Reset last full sync timestamp: Enable this checkbox to reset and rerun a full sync from a specified date and time. When enabled, the following fields are displayed:
    • Reset effective date: Select the date from which the full sync must run again.
    • Reset time: Select the time to reset the last full sync timestamp.

Configuration

The Configuration section allows you to define the condition for creating or updating employee records in SailPoint.

Upsert Condition: Select the upsert condition that determines which employees are eligible to be created or updated in SailPoint. The following options are available.

  • All Employees: Select this option to create or update all employees in SailPoint.
  • All Active Employees: Select this option to create or update only the active employees in SailPoint.
  • All Inactive Employees: Select this option to create or update only inactive employees in SailPoint.
  • Custom: Select this option to define a condition that determines which employee records are created or updated in SailPoint.
    • Custom Upsert Condition: Enter the condition that determines which employee records are created or updated in SailPoint. This field is displayed only when Custom is selected in the Upsert Condition field.

Mapping

The Mapping section allows you to map attributes between Dayforce and SailPoint. 

Attribute Map

The Attribute Map page displays the default mapping from Dayforce to SailPoint. You can provide a JavaScript expression for a source attribute by clicking Enter Expression at the end of the source attributes list. The expression is evaluated at runtime, and the resulting value is assigned to the corresponding target attribute.

Preview Data

You can preview the attribute values that will be created or updated in sailPoint based on your mappings.

To preview the attribute values, perform the following steps:

  1. Click the Enter objects for preview field at the top of the Attribute Map page. A pop-up window is displayed.
  2. Select id and enter the ID of the employee.
  3. Click Preview. The data are displayed corresponding to each mapping provided in the Attribute Mapper.

Operations

This tab allows you to configure various settings required for the integration execution. The following section is displayed:

  • Execution

Execution

This section enables you to customize the execution settings for the integration. The following fields are available: 

  • Report Only Mode: Select this checkbox to generate a report that shows the data that would be changed, without actually making those changes.
  • Import Limit: The maximum number of employee records that must be retrieved from the source application during a single run of the integration.
  • Enable Source Filter: Enable this toggle to filter records retrieved from the source application. When enabled, the following fields are displayed:
    • Select Filter Type: Select the source attribute used to filter the records.
    • Filter Value: Enter the value used to filter the records based on the selected source attribute.
  • Source Non Native Filter: Enter the JavaScript expression used to filter Dayforce records after all users are retrieved from Dayforce.

Notification

This section allows you to configure notification settings for provisioning events.

Enable Email Notification: Select this checkbox to send an email notification when the integration runs. When enabled, the Email Notification Configuration section is displayed.

To navigate to multiple configurations, use the arrow icons (< or >) which is located at the bottom-right side of the table.

If you want to modify the configuration, click any value in the row and you will be redirected to the edit mode, where you can make changes.

If you want to display few rows in the table, select a value from the drop down list to specify the number of rows displayed per page.

To delete a configuration, place the cursor over the row and click the delete icon displayed on the right side of the table.

To add a new configuration, click the + Add Notification configuration button. The following parameters are displayed:

  • Select Event Type: Select the event for which the notification must be sent.
  • Admin Email Address: The comma-separated list of administrative email addresses to which notifications are sent.
  • Enter Subject Line: Enter the content that must be used as the email subject.
  • Email Template: Enter the notification email content in the template that is sent when a new user is created in the target application.

Tables

Tables can be added to create custom source attributes and POST (sync) them to the target application. Tables are used when an application attribute is empty or a specific data is not sent from the HR application, and you want to update a value for that attribute in Okta. Based on your requirements, you can add any number of tables in the integration.

The table setup and functionality are the same as that in the User Integration. Refer to the Adding Tables in Integration section in the Using Tables in Integration guide for details.

Schedule

Integrations can be scheduled to run automatically based on your choice of timeframe. Refer to the Integration Schedule Setup Guide for further details.
